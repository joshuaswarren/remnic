Enforce transactional review rounds so bot reviewers run once per settled head instead of once per push (umbrella #1988 decision D, mechanism from #1992). `Review Round Dispatch` has kept a per-PR round ledger in shadow mode since #1992: it recorded when the next round was due but never asked for it, so every intermediate commit still drew a full re-review from each bot. Measured over 46 PRs, that produced roughly 7.6 reviewer passes per PR, tracking commit count nearly 1:1 (one PR: 31 commits, 25 passes) - almost all of it spent re-reading work-in-progress. `REVIEW_ROUND_ENFORCE` now ships as `'true'`, so the gate posts the `@coderabbitai review` / `@codex review` trigger only when every thread in the round is addressed and the head has been stable for the debounce window (default 10 min), when the round exceeds its max age (default 24 h), or when a maintainer applies `review-round:force-dispatch`. Reviewer coverage of the merged head is unchanged: the settled head still gets a full review before merge, and `unresolved-review-threads` remains the untouched thread merge gate with its concurrency group still absent for `check-unsticker`. Set the variable back to `'false'` to return to ledger-only shadow mode.
