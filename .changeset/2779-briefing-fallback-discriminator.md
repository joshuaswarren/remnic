Diagnose, bound, and now cancel the briefing legacy full-read fallback (issue #2779). Every briefing memory read logs exactly one structured, content-free discriminator line — `mode=windowed|full-read-fallback durationMs=N count=M outcome=success|timeout|error err=<class>` — on success, deadline timeout, and rejection alike, so a slow windowed scan, an adapter without `readMemoriesWindow()` support, a timed-out full read, and a failing read are all distinguishable from the daemon log alone. Error lines carry the error class name only, never messages or memory content. The legacy full-read fallback no longer races-and-abandons a background scan: the deadline is delivered as an AbortSignal through the optional `readAllMemories({ abortSignal })` parameter (the #2307 corpus-read contract, already honored by StorageManager), so a signal-aware read stops scanning at its next boundary and nothing keeps consuming I/O after the briefing returns. A `readAllMemories` that declares no read options (pre-signal legacy doubles) cannot observe the deadline and is refused up front — the briefing fails open with an empty read and an upgrade hint instead of starting an unbounded, uncancellable scan. Real StorageManager paths already use windowed reads; no production adapter hits the fallback.
