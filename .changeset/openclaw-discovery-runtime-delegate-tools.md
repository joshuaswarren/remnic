Stability: stable

OpenClaw 2.0 delegate-mode fixes for hosts that register in the discovery modes.

- `registrationMode: "discovery"` and `"tool-discovery"` now run the runtime registration (tools, `before_prompt_build`, `agent_end`, memory capability). OpenClaw's loader accepts capability handlers in those modes, and the agent runtime that serves `openclaw agent` turns registers in them; skipping register() there left it with no memory loop. The one-time engram migration stays off in both discovery passes.
- Delegate `memory_search` refuses a `filters.namespace` instead of validating it: the daemon-backed search manager resolves the session's namespace itself, so a validated scope can be rebound before the search runs and answer from a different namespace.
- `openclawToolsEnabled: false` is honored as the ADAPTER toggle the manifest documents: delegate mode drops the dedicated `memory_get` adapter but keeps a `memory_search` surface, matching embedded mode (which falls back to its legacy search tool) instead of removing search entirely.
- Delegate `memory_get` answers an unresolvable `[m:xxxx]` handle with `{error:"not_found"}` (the daemon reports it as a 400), matching `getMemoryForActiveMemory`. Other 400s still surface as errors.
- When a PASSIVE delegate entry has already registered the model-facing tools and the memory slot's owner resolves to embedded, the owner adopts those registrations instead of registering the same names again: no host tool-name conflict, and the tools run the owner's embedded implementations rather than the passive entry's daemon and namespace.
- Discovery passes no longer claim the process-global session-command and CLI registration guards. Their registrations are transient, so a discovery pass that claimed a guard left the later full registration with no session commands and no CLI.
- `ModelRegistry` creates `<memoryDir>/.registry` on its first save instead of in its constructor, for the same reason as the profiling directory: constructing a runtime must not write.
- `bridgeMode: "auto"` treats a same-host loopback rewrite and its configured interface address as ONE probe candidate sharing one allocation of `bridgeHealthTimeoutMs`. Budgeting them separately halved the share, so a daemon slower than half the budget timed out on both aliases and auto selected embedded beside a healthy same-corpus daemon.
- `ProfilingCollector` creates its storage directory on the first persisted trace instead of in its constructor, so constructing a runtime (plugin registration, a read-only discovery pass, CLI metadata) no longer writes into the memory dir.
- Delegate mode registers daemon-backed `memory_search` (through the capability's search manager, so scoping and authorization match the host's own memory search) and `memory_get` (`GET /engram/v1/memories/{id}`) tools when the host exposes `registerTool`.
- Delegate mode does NOT register the OpenClaw 2.0 `registerMemoryPromptPreparation` step: it runs before `before_prompt_build` and is handed no session namespace, so it could only recall a previous scope. `before_prompt_build` injects this turn's recall in the session's bound scope.
- The recall query is the current turn (`event.prompt`, envelope-cleaned) capped at 1500 characters, keeping the tail, so a host that hands the hook an assembled prompt cannot 413 the daemon's body limit.
- `agent_end` no longer blocks on the observe POST: the turn capture is detached and chained per session, bounded by half the flush timeout so that a flush for the same session (which waits behind it for at most that long) can never overtake one observe and always keeps the other half for its own requests. When a whole QUEUE of observes outlasts that wait, the flush proceeds and a follow-up flush is chained behind the queue, so late turns are never left buffered past `session_end`. The follow-up drains a bounded number of rounds and releases its guard before flushing, so a session that keeps observing past the cutoff gets another follow-up behind the remainder rather than leaving it buffered. It drains the whole queue (including turns observed after the hook returned, which the daemon buffers per session) and resolves its scope from the session's bindings rather than the ended event's captured metadata.
- A `REMNIC_HOST` that names one of this machine's own interface addresses (a NIC or VIP) is dialed through loopback, like a wildcard bind; a gateway fetch to such an address has been observed to hang.
