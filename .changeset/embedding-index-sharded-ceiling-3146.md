Stability: stable

Fix the embedding fallback index failing forever with `RangeError: Invalid string length` once `state/embeddings.json` approaches V8's maximum string length (issue #3146). The index now has two single-generation layouts: the legacy single file while its whole serialization fits a per-file budget (V8 ceiling minus a 16MiB margin, overridable per environment via `REMNIC_EMBEDDING_INDEX_FILE_CHAR_LIMIT`), and 64 hash-assigned shard files under `state/embeddings/` once it does not. Migration is one-way and atomic: the complete shard set is staged, published with a single directory rename (the published directory is the layout marker), and the legacy file is renamed aside as a non-authoritative recovery artifact — partial generations are never merged, so a crash cannot resurrect deleted entries. After migration only the shard holding the mutated entry is rewritten; an entry whose removal empties its shard removes the shard file. Unreadable or over-budget index files fail mutation paths closed (`EmbeddingIndexStorageError`) with the file preserved in place for recovery, instead of continuing from a fresh empty index; read-only recall paths fail open and record the reason. A failed persistence invalidates the in-memory index cache so a retry cannot mistake unsaved entries for durable state. Index write failures and corrupt-file recoveries are recorded durably in `state/embedding-fallback-status.json` and surfaced through the new optional `embeddingIndex` block in `console_state`; residual per-shard overflows throw tagged `EmbeddingIndexCapacityError` naming the offending entry. Offline sync treats shard files as remote-authoritative runtime state, matching the legacy single-file index. References #3146.
