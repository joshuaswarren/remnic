Add corpus watermarks (issue #2149, detection half) — a cheap, comparable fingerprint of each daemon's active-memory corpus so an HA pair behind an active/backup VIP can detect silent corpus divergence (a primary at ~190k files and a backup at ~340k, discovered only by manual audit, becomes a same-day signal). The new `corpus-watermark.ts` exports the `CorpusWatermark` shape plus a pure, filesystem-free `digestPartitionCensus()` — sha256 over the DETERMINISTICALLY sorted per-`<category>/<YYYY-MM-DD>` file-count census (a census fingerprint, not a content hash; AGENTS.md pattern 26) — and `computeCorpusWatermark()`, which sources paths from the existing cheap `StorageManager.collectActiveMemoryPaths()` scan (now public, no frontmatter parse) and `stat`s only the newest partition's files for `newestWriteAt`, so it survives a 100k+ file corpus without the cost of `readAllMemories()`. The watermark is exposed to AUTHENTICATED callers on `GET /engram/v1/health` as `corpus: CorpusWatermark[]` (one entry per namespace via the namespace catalog; a single default-namespace entry when namespaces are disabled) and in `remnic doctor` as the `corpus_watermark` check. Peer polling and divergence alerting are a follow-up PR, so this check never warns and invents no threshold. The doctor summarizer lives in a new `operator-doctor-corpus.ts` sibling module because `operator-toolkit.ts` is at its structural-ratchet ceiling.
