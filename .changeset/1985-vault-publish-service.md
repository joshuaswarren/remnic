Add the markdown-vault publisher for timeline artifacts (issue #1985): `remnic timeline publish [--date YYYY-MM-DD] [--dry-run] [--what timeline]` writes the day's persisted timeline recap into the user's markdown vault daily note through strictly-bounded managed regions. Everything outside the region — frontmatter, human sections, other agents' sections, CRLF/LF — is byte-identical after publish; unchanged content produces no write; all writes are temp-file + rename in the note's directory; `--dry-run` performs zero writes. Config lives under `activity.timeline.vault.*` (default off; invalid values are rejected at config load naming the missing prerequisite). Path templates accept `{yyyy} {yy} {M} {MM} {d} {dd} {ww} {MMM} {MMMM} {ddd} {dddd}` with unknown tokens rejected naming the full valid set. `properties.mode: "frontmatter"` edits only prefix-owned frontmatter keys via targeted line edits; `"dataview-inline"` appends inline fields inside the region. Malformed managed-region markers on unfenced lines — a crossed begin/end pair, a nested second start before the open region closes, or an end with no open region — and symlinked paths resolving outside the vault, plus a symlinked destination note (renaming over the link would destroy it and leave its target stale), are refused without touching the file. Markers and headings inside fenced code blocks are ignored, so a fenced example is never published over or inserted into. The command is dispatched from one shared implementation, so it behaves identically in the host CLI and in the standalone `@remnic/cli` binary. The standup, weekly, and locations publish targets are rejected with a named reason until their phases land; the publisher mechanism is live for the timeline target.
