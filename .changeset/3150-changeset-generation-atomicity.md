Make offline-sync changeset pushes embedding-generation atomic (issue #3150). Changesets that touch an embedding generation now describe its complete post-change membership in an optional `embeddingGenerations` manifest; the receiver routes the whole generation through the shared locked atomic transaction — changed shards publish, unchanged shards carry over from hash-verified local bytes, removed shards sweep — instead of writing records one-by-one, so a crash or failure can never leave a mixed generation. Delete-only manifests shrink the generation through the same swap; full-evidence manifest-less tombstones remove the whole generation atomically; partial manifest-less deletion evidence defers as `embedding_generation_manifest_required` conflicts and leaves the generation intact. Legacy changesets without a manifest defer shard upserts as conflicts (`embedding_generation_manifest_required`) instead of risking a partial generation, and under-lock divergence (a concurrent daemon rewrite or a remote-only member) defers the whole generation as conflicts (`embedding_generation_diverged`) so the push side never checkpoints a deferred generation as applied. Changeset apply now requires the secure staging hook pair when custom storage IO meets generation members, matching the snapshot apply. Sender-side, apply batches keep one generation together across requests and an over-budget generation fails closed before any request with the staged-chunk-transport policy instead of the direct-push hint.
