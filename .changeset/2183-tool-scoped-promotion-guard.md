Tool-scoped shared-namespace promotion guard (#2183). A fact that references a specific tool or command, or whose structured procedure steps invoke a tool, and was produced by a known integration (`sourceConnector`) is no longer promoted to the shared namespace by ANY path — a different integration exposing a same-named but incompatible tool (Pi `search` = repo code search vs OpenClaw `search` = web search) would otherwise consume it.

Detection is the pure predicate `referencesAgentSpecificTool` (bounded, backtracking-safe regexes; keywords and generic names word-anchled so "tooling"/"commander" and the "search" inside "research" do not match; catches imperative invocations `Use \`search\``/`Run \`rg\`` and slash commands `Use /search`; slash detection is restricted to invocation context so bare absolute paths like `/etc/remnic/config.json` do not fire). The tool-scope decision has exactly ONE definition — `withholdToolScopedFromSharedNamespace({ content, sourceConnector, procedureSteps? })` (consults the text AND `procedureSteps[].toolCall.kind`, so a portable-titled procedure with tool-bearing steps is withheld) — consulted by every shared-namespace promotion path: `shouldPromoteGlobalFactToShared` (composed; gates the pre-judge namespace prediction AND the write-loop scope-routing block, with `procedureSteps` threaded through both) and the primitive itself (gates the post-write `promoteMemoryToShared`, covering both chunked and non-chunked call sites by construction). Every site is gated by the existing `extractionScopeClassificationEnabled` capability, so disabling scope classification makes the whole feature inert on every path (escape hatch). Unattributed or portable facts, and the disabled-capability case, are byte-identical to before.
