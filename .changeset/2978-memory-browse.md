Agent-facing browse verbs over the memory store (issue #2978): `memory_ls` lists the children of one store path (category dirs with counts, memory files with a one-line description), `memory_tree` returns a depth-limited tree (depth 1-4, entry-capped), and `memory_find` does deterministic name/path matching (`*` glob, one segment per pattern segment, or substring). Every call resolves through the caller's readable namespace — browse never crosses namespaces — and only the recall corpus is visible: `artifacts/`, meeting records, wearables day stores, `state/`, and the `questions/` queue are indistinguishable from missing paths (`not_found`), and support-passport private memories are filtered like the paginated list. Output is code-point sorted and stable across duplicate calls. Surfaces: MCP `engram.memory_ls`/`engram.memory_tree`/`engram.memory_find` (canonical `remnic_*` aliases, read-only annotated, real outputSchemas), `POST /engram|remnic/v1/memory/{ls,tree,find}`, and `remnic browse ls|tree|find`. Route bodies live in memory-browse-http-glue.ts with literal `enforceTokenOp` boundary-dispatch markers; the shared implementation is `EngramAccessService.memoryStoreBrowse`.
