Surface extraction-pipeline liveness (issue #2151). A daemon whose implicit extraction fails continuously can sit for months with a growing buffer while `/health` stays green and recall keeps serving — every individual failure is logged, but nothing aggregates them into a checkable status. A new `extractionLiveness` config block (`enabled` default true, `staleWindowMs` default 24h) drives a shared liveness verdict exposed three ways: the authenticated `/health` payload gains an `extraction` object (`lastExtractionAt`, buffered session/turn counts, oldest buffered turn age, `degraded`, `degradedReason`), `remnic doctor` gains an `extraction_liveness` check, and `remnic stats` prints the watermark, backlog, and verdict. `SmartBuffer.getBufferSnapshot()` enumerates buffered work across both the entries map and the legacy top-level turns array. Degradation follows the §22 error-vs-empty principle — it requires a non-empty buffer, so "nothing to extract" never reads as "extraction is broken" — and uses a half-open staleness window (§23). One aggregated WARN is logged per staleness window via an instance-scoped throttle rather than one line per failed attempt. The liveness logic lives in a new `extraction-liveness` module so the god-file line ratchets hold.

The `extraction` verdict is daemon-global: `/health` returns the same block for every namespace argument, pairing the global buffer with the root-store watermark. An unreadable buffer is itself reported degraded (a pipeline fault, not an empty queue), and `extractionLiveness.staleWindowMs` must be a positive integer of milliseconds — a fractional or non-positive value is rejected rather than floored.
