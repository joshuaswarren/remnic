# One shared deadline and one fixed result budget govern each delegate call end to end

Status: accepted

## Context
Hosts impose hard windows on hooks and tool calls, while a delegate operation is a pipeline of stages: scope resolution, posture probe, authorization probe, search pages, flush chunks. Giving each stage its own fresh timeout lets the stages multiply into an overrun the host abandons mid-flight — a 25-second search taking fifty, a queue of observes outrunning one cap, a single `search()` stretched across minutes by per-page timers. Separately, a daemon that filters artifacts or scores before capping would return empty pages for queries whose valid memories rank just behind the excluded hits, and an omitted search mode sends a flat corpus down a legacy ranking path — a different answer for the same request depending on bridge mode.

Search paging/budget, search-mode mapping, hook-field and recall-contract, and embedded-parity notes were merged into this record as the nearest neighbour (the delegate call contract) to respect the ten-file limit.

## Decision
- Open ONE deadline before ANY network work — including scope resolution — and pass what is LEFT of it to every sub-step. No sub-step starts its own fresh or fixed timeout.
- A spent or nearly-spent budget is not an error and not a reason to start a doomed request: answer from the last known snapshot, decline the flush, or fail closed — never overrun the host window. A caller that loses a race treats the snapshot it holds as unproven for its own call.
- The memory tool invocation gets one budget opened before the manager is acquired; the manager's own deadline is the host contract and cannot be shortened, so the check is that no request STARTS after the budget is spent.
- Cap after filtering: ask the daemon for more candidates than `maxResults` (bounded by an absolute daemon-safety ceiling, one extra hit to detect truncation), drop artifacts and sub-threshold hits on this side, then cap. The first page fixes the budget once — recomputing it per round lets the target grow with every doubled request. A short page means the daemon has nothing left; stop.
- A zero budget short-circuits to an empty result only AFTER scope and authorization resolution: shrinking the requested count must never be a way to get a successful answer for a namespace the session may not read.
- Always send an explicit search mode, mapped exactly as the embedded manager maps it (vector ranking, ordinary search plan, or backend default), so a host gets the same ranking semantics in either bridge mode.
- Caller input is adapted to the daemon schema at the boundary — trim oversized queries, floor schema-valid fractional limits like embedded mode, read per-call caps fresh — rather than converting a valid call into a 400.
- Recall injection follows the host contract: only a section-builder host injects while the hook pre-computes (peek only; the builder owns eviction); zero recall budget disables injection; the current turn outranks the transcript; the prompt-section cache is session-scoped and evicted before the short-query exit; spawned-subagent session keys get no unsolicited recall; heartbeat-triggered turns mirror the embedded gate; on builder hosts whose prompt construction aborted, the hook does not inject.
- The host SDK may be absent in host-free environments: probe it lazily through a mirrored grammar that must answer identically whichever helper is active.

## Consequences
- Worst case per call is bounded by the host's window, and a slow early stage can no longer multiply into a stalled or abandoned hook.
- Stages after a slow probe get less time; a near-spent budget degrades to cached or declined answers instead of partial requests.
- Over-fetching costs extra rows on the wire to keep pages non-empty under filtering.
- Ranking parity is now load-bearing: a mapping change in embedded mode must be mirrored in delegate mode.
