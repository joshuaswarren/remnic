# Every multi-file or multi-step storage mutation is crash-safe by ordering: destinations first, sources last, ids and receipts for idempotence, and out-of-band writes bump the sentinel

Status: accepted

## Context

Storage mutations span files and processes: transcript migration splits legacy logs, buffer drain hands sessions between owners, review promotion and space copies move records between corpora. A crash mid-sequence must never lose data, duplicate turns, or resurrect extracted/tombstoned content.

## Decision

Migration and copy protocols write destinations FIRST (write-then-rename, idempotent merge dedup by raw line), and only after all destinations are confirmed rewrite or remove the source; unparseable/no-sessionKey lines are tracked as unmovable and left in place. Only canonical session/<16-hex> dirs count as already homed — a legacy session/<name> dir is a real migration source. Entity pages in a copy batch copy byte-faithful behind a DEFERRED reconcile marker; the reconcile pass runs once, after every record landed, because a per-record marker could be consumed mid-batch and canonicalize a memory onto the wrong claimant. Re-resolve at the write and repair after it; a failed repair restores the snapshot prior target bytes. Review promotions canonicalize entityRefs against the target journal (repairing when it moved), roll back on partial promotion so a retry does not clobber-fail, fire the revocation hook only after the approval fully commits (never before the promote), clear tombstone-block markers AND restore active status (pending_review made promoted memories invisible to recall), and tombstone-blocked facts are ALWAYS review candidates regardless of confidence — visible, never silently dropped. Per-record tier moves and inherited-entityRef cases use whole-record rewrites with pre-write destination snapshots for repair.

The buffer drain claim protocol is an atomic handover: rename is the claim; the inbox is newline-prefixed JSONL (torn tails never fuse with the next record's parse), replay prevention uses exact consumed-record markers (not identity counts), a lease-less claim is adopted with its durable content intact, a superseded/fenced drainer never writes progress, a live owner hands its in-memory entry into the claim (never falls back to a session-file write behind the claim lock — that would resurrect claimed turns), and compaction order is body-first-then-inbox-consume. Per-session buffer files replace whole-state rewrites; a rejected load must not let later saves replace an encrypted file. Startup migration is deferred to read-readiness so a held migration lock cannot stall first reads (writes still queue behind it). CAS on frontmatter uses a standing business-time receipt token: caller-supplied `updated` is business time persisted verbatim; semantic mutations advance the token strictly, access telemetry does not, and delayed rollbacks key ownership on their receipt so a stale rollback is rejected. Out-of-band writers (review, spaces) bump the corpus sentinel per write on the canonical root. Storage contract tests pin atomicity, cache coherence, content-hash identity, failure semantics, namespace routing, and round-trips for every category dir (names, not singular keys — a divergence would silently drop a category from recall). The recall fallback scans all memory category dirs from the shared dir list, never questions/ or non-frontier dirs, with symlink containment isolating per-entry failures.

## Consequences

Write-destinations-first ordering temporarily doubles disk usage; the deferred reconcile marker means collision resolution is visible only after the whole batch lands; strict receipt matching rejects legitimate same-millisecond retries.
