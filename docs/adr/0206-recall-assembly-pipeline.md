# Recall assembly is fail-open, deadline-bounded, safety-filtered before scoring, and merges LCM evidence across every authorized key

Status: accepted

## Context
A recall is a race of parallel evidence branches (QMD hot/cold, embedding fallback, LCM sections, memory boxes) under one enrichment budget. A slow corpus scan (17s qmdPost outliers), a stalled transcript read, a corrupt fallback index, or a cross-namespace similarity hit must degrade one section — never the recall. Branch namespaces and (namespace,path) identities must stay aligned so traces and merges stay truthful.

## Decision
- Mandatory recall safety filters run BEFORE any deadline-bound scoring enrichment, so a scoring timeout falls back to the filtered list, never raw hits; forgotten/lifecycle-filtered/superseded/as_of-invalid memories are removed by the same boost path.
- The trust stage (TrustScore) subsumes the Memory Worth multiplier — exactly one runs — and is applied on EVERY recall path with identical lookup semantics; it is deadline-bound and fail-open (fallback returns inputs unchanged, as a distinct object so metrics can detect fallbacks). Pass already-loaded frontmatter in as the preloaded map so lookups do zero corpus scans.
- Every race step gets a child abort controller composed with the request signal; the losing task stops cooperatively at its next loop boundary and maps to its fail-open fallback, never rejecting the recall — request-level aborts reject at throwIfRecallAborted boundaries. A section that stops waiting on a shared store is recorded as cancelled, not empty.
- QMD results that settled before ordered assembly reached them must not become unchecked misses; they stay bounded by the shared assembly deadline. A hot-QMD phase abandoned by the budget is reported deterministically (a caller abort is not a backend degradation). Degradations are per-recall local arrays (overlapping recalls sharing a sink cannot mark each other failed) and are cached WITH their phase result, so cache hits replay stored degradations and every QMD-skipping path reports backend_unavailable.
- The confidence gate scores the pre-augmentation QMD top score (plus maxSpecializedScore only when QMD found something) BEFORE slicing, so reranking and contextual weights never shift the calibrated scale; when the gate rejects, all fallback pathways are skipped.
- MMR diversification runs on the pre-truncation pool on every branch; the configured core budget (not a derived one) is what unbounded sections report, and the bounded runner reports its own per-section effective budget. The whole recall body sits in try/finally so the profiling trace always closes; phase-2 timings are kept separate and folded in at record time.
- Query-scored LCM sections MERGE candidates across every authorized read key (primary overlay → coding fallbacks) under a single budget, queried independently with allSettled so one corrupt key's failure cannot discard other keys' evidence, deduped so the primary key wins collisions. Compressed-history keeps first-non-empty semantics (a per-session holistic narrative cannot be merged); legacy turn-order fallbacks never interleave sessions. A hosted scope profile without a session key yields an EMPTY key set, so LCM cannot bypass the profile read stack; never the literal "default" session id.
- Historical `asOf` is parsed once per recall; a malformed value means "no pin" (input boundaries are the source of truth). Namespace-bearing fields resolve through ONE ScopePlan. A same (namespace,path) memory merges once via derived agent-hit namespace; result identity keys are (namespace, path) so cross-namespace same-path hits don't collapse. Catalog read touches are recorded after the abort gate, immediately before retrieval, so lastReadAt reflects a real read. Memory-boxes reads start in parallel with phase-1. Per-session workspace selections are always cleaned up, even when the feature is off.
- Episodic context and cross-lingual planning are opt-in and fail-open; LLM reranking is default-off and fail-open; the knowledge-index section is fenced from untrusted entity content; user pushback triggers a suggestion to inspect/record feedback, never an automatic negative.

## Consequences
Recall latency is bounded and every degradation is visible and truthful, at the cost of per-step abort plumbing, allSettled fan-out on LCM keys, and duplicate safeguards against a silent double multiplier. Sections degrade individually; the recall never fails because one evidence source is slow or corrupt.
