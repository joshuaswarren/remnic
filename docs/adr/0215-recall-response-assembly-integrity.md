# Recall responses carry only admitted content with honest depth, cost, and audit accounting

Status: accepted

## Context
Response assembly had integrity traps on every axis: the prompt-injection `context` string was generated before tag filtering, so excluded memories leaked into it and the audit overstated what was injected; confidence-based disclosure escalation used the requested top-K as its denominator even when the orchestrator applied a much smaller cap, and forced escalation on sessionless callers by computing 0/N=0; token estimates undercounted raw-disclosure spend (missing excerpt cost, metadata fields, unreadable results attributing spend to a missing first result); debug snapshots exposed absolute internal paths; and disclosure validation ran after expensive, irreversible work had begun.

## Decision
- Tag filtering applies post-recall, after serialization, reading each result's loaded frontmatter tags; absent/empty tags are a no-op and an invalid match mode throws (rule 51). When the filter drops any result, `context` is rebuilt from the ADMITTED set, so excluded content is unreachable through any response field; the rebuilt context is a strict subset (full content at section/raw, preview otherwise). The audit record reflects what was actually injected — post-filter counts, pre-filter numbers overstate injection and leak excluded content into the audit summary. Audit recording is fire-and-forget: it never blocks or crashes recall. X-ray mirrors recall tag semantics (same normalization: trim, drop empty) and surfaces the considered-vs-admitted delta in snapshot filters.
- Disclosure depth defaults to chunk when omitted (pre-issue callers unchanged) and explicitly invalid values are rejected, never silently mapped. Validation happens UP FRONT — before recall executes, before the x-ray queue mutex, before namespace resolution — so a bad value fails fast instead of burning cycles on an irreversible recall; inside the queue the narrowed type is pinned, not re-checked.
- Confidence-based auto-escalation (operator opt-in, caller has not chosen a level, low fill ratio) escalates chunk to section; manual mode and explicit caller disclosure bypass it. The confidence denominator is the orchestrator-APPLIED top-K whenever present (a caller's explicit request is wrong when the planner or caps narrowed it), falling back to the explicit request top-K, then config; it is floored at observed results to stay within [0,1]; with no snapshot the helper takes its no-confidence branch instead of computing 0/N=0.
- Token estimates reflect real spend at the requested depth: raw excerpts are pre-fetched once so the first raw result's estimate includes archive-side excerpt spend; estimates include the metadata fields the summary actually emits; excerpt spend is attributed to the first READABLE result (credited to the first result when every file is unreadable) rather than always index 0; an unreadable result keeps its disclosure tag (so it is not counted as unspecified) but skips its estimate — best-effort, silent on read failure per the external-subsystem rule.
- Debug snapshots are display-safe copies with internal paths relativized; the live cached snapshot stays absolute for tracking/x-ray. X-ray snapshot capture goes through the orchestrator-owned critical section; the returned clone is owned by the call after release.

## Consequences
Response fields may be rebuilt rather than passed through (a different, strictly smaller wire format than the orchestrator's native context); escalation needs snapshot data and is disabled without it; token summaries are best-effort and omit unreadable content.
