# One-shot commands report what they actually did: no silent skips, no swallowed failures, no cross-scope leakage

Status: accepted

## Context
Short-lived CLI commands manage diagnostics, journals, briefings, exports, and connector state. Their failure modes — a denied namespace, a malformed config, a startup that finished too late, a parked write — are all easy to misreport silently as success or as emptiness, which is worse than failing.

## Decision
- Remote mode: when a remote origin is configured, status, query, xray, and daemon state target that origin — no local service-manager probe, PID file, or local spawn; "running" means the remote health endpoint answered, and a leftover local PID is reported as a leftover, not as live state. If startup finishes after the command deadline, the command stops instead of recalling.
- Doctor keeps running when the config it diagnoses is malformed. It surfaces dead-lettered (quarantined) writes and an unreadable quarantine store with generic detail, never raw errors that carry absolute paths or internal context; it computes the effective namespace with the operator's actual configured coding-mode values, falling back to ship defaults only when nothing is configured; it renders configured-plus-probed provider state so degradation is never silent; it captures the raw configured write namespace for linting before any parsing; and it reports which of "denied" versus "empty" a diagnosis hit.
- Journal: the master gate refuses every action before any read; the default date derives from the configured activity timezone, not the host clock; extracted text carries a provenance header naming the source note; a missing note or section is a legitimate no-journal day (exit 0, no state write); a per-date lock covers hash reread through extract, dedup, write, and state commit, while different dates may run concurrently on different lock files; the review-only pass lands candidates as pending review only, so the command still works without the judge dependency; completed runs advance the day's hash so identical content never re-runs; and `--help` short-circuits before config discovery so a broken config cannot hide the usage text.
- Drift scanning requires a real orchestrator backend with its embedding lookup and judge; a lookup error surfaces as backend-unavailable rather than an empty result, because an empty result would misreport a live preference as stale. The scan is deliberately not wrapped in a swallowing catch: a thrown lookup means backend-unavailable by contract.
- Briefing: the logger starts before config parsing so warnings reach stderr and JSON runs keep every level off stdout; a focus flag with no trailing value, or one that parses to nothing, is rejected so a templating miss cannot silently broaden the view to all memories; `--json` conflicting with `--format` fails fast; correction notifications are drained at most once, before any deadline risk can lose them; place-name sections and follow-up routing mirror the access service so CLI and server briefings behave identically; and the filename derives from the window's end time, not wall-clock, so it is stable regardless of when the command runs.
- X-ray validates flags before any IO so bad input surfaces the right error without touching disk, re-using the same pure validators rather than a second drift-prone shape; as a diagnostic it waits for deferred startup sync before recall.
- Buffer drain closes rather than exits, so the stdout pipe finishes reading and a late session report is not lost; a session captured for a namespace stays with that namespace — the drain never moves content across namespaces; and claim files are the durable record: one drain attempt per worker run, with claims left by crashed workers adopted by the next run.
- Tombstones: the CLI parses and applies the same tombstone configuration the daemon uses before revoking, or the revocation is silently refused and approved content blocks again on the next write. Config parsing runs in an isolated catch whose failure keeps tombstones at their safe default (disabled) while the approval still clears the block on disk; the revocation is awaited before CLI exit so a short-lived process cannot lose it; and the dedup index re-registers the now-active fact's content hash so the next extraction does not create a duplicate active fact.
- Training export: the privacy sweep defaults on because exported data is shareable; on an adapter that cannot run it, the command hard-fails with the opt-out path in the message instead of silently skipping redaction, and an explicit opt-out flag is the only bypass. Explicit user choices are distinguishable from defaults, so a mismatch is a hard error while a default mismatch can fall back with a warning. `--dry-run` is parsed first so statistics-only runs need no output path; `--out` aliases `--output`; dry-run populates a sentinel output so the parsed contract has no optional field; programmatic callers missing an output path fail loudly rather than writing to an empty path the shell might resolve elsewhere; and tilde is expanded on both the explicit flag and the config-derived default path.
- JSON mode redirects subprocess stdout to parent stderr so progress logs cannot corrupt the JSON payload emitted on stdout.
- Space resolution recreates a missing directory rather than silently falling back; a deleted active space is recoverable (fall through), while a corrupted manifest or permission error is fatal; the manifest's existence is checked before any bootstrap. Security screening in command context uses the same profile the live write path screens with.

## Consequences
Some commands refuse work a laxer version would guess through: a journal without its gate config, a drift scan without embeddings, an export without a sweep-capable adapter. The payoff is that operators see real state — quarantine counts, degraded providers, denied namespaces — instead of plausible-looking emptiness.
