# Hook requests resolve endpoint, credential, and namespace through one defined precedence, and ambiguous configuration disables rather than guesses

Status: accepted

## Context
Hooks and the MCP proxy must reach a daemon that may be local or remote (Tailscale/LAN/VPN, plain HTTP or TLS, behind a reverse-proxy subpath), may authenticate with one of several token names left by different install generations, and may be namespaced so buffered observations and flushes land on the same storage key. Getting any of the three wrong fails invisibly: writes land in the wrong store, probes 401 and hooks silently skip recall/observe, or observations queue under one namespace key while flushes drain another — so in-session memory never persists.

## Decision
Endpoint: a full `REMNIC_DAEMON_URL` (explicit scheme required) takes precedence over the legacy `REMNIC_HOST`/`REMNIC_PORT` pair, which remains a backward-compat fallback for existing installs and test harnesses. The URL may target remote daemons over http or https and may carry a base path for reverse-proxy subpath mounts; trailing slashes are stripped so `"/remnic/" + "/engram/v1/observe"` concatenates cleanly. An explicit but invalid URL (missing scheme, typo) must NOT silently fall back to HOST/PORT — that would route recall/observe/flush to the wrong store; instead the daemon is disabled entirely (all HTTP calls fail open) and the misconfiguration is surfaced once on stderr. Plain HTTP to a non-loopback host sends the bearer token cleartext; that deployment shape is supported on trusted LANs, so hooks warn once per invocation batch rather than refuse.

Credential: token resolution is primary-before-legacy — current names (`OPENCLAW_REMNIC_ACCESS_TOKEN`, `REMNIC_AUTH_TOKEN`) before legacy aliases (`OPENCLAW_ENGRAM_ACCESS_TOKEN`, `ENGRAM_AUTH_TOKEN`), connector-scoped lookups before the flat token store — so a stale pre-rename value cannot outrank the credential the daemon actually runs with. The liveness probe authenticates with the exact resolved token the gated operation will send: never a second resolution (a rotated token file could green-light a probe whose recall then 401s) and never `REMNIC_HOOK_TOKEN`, which is the detached worker's internal propagation channel only. This matters because an auth-gated daemon 401s every route including liveness, so an unauthenticated probe misreports "daemon not running" and silently skips recall/observe. The probe is one aggregate, readiness-gated budget: `/engram/v1/live` first, retrying the legacy diagnostic route only on 404; 401 and 503 are final answers.

Namespace: every observe/recall/flush body carries the configured namespace override (`REMNIC_NAMESPACE` / legacy `ENGRAM_NAMESPACE`) through a single chokepoint, so a namespaced install archives and flushes under one key; an explicit body namespace still wins. The same variables scope every MCP call. When a session moves out of a repo, `codingContext` is explicitly null so stale routing is cleared; outside a git repo it is likewise null rather than sticky.

## Consequences
Misconfiguration fails visibly instead of corrupting the wrong store, but the price is strict precedence rules that every new route, env var, or client must thread through the same chokepoints. The probe and operation must always share one credential snapshot, and namespace coverage must include every observe path — one omitted call site re-creates the dropped-tail bug.
