# Memory Worth scoring treats corrupt counters as a collapse to the prior, never as evidence

Status: accepted

## Context
Memory Worth multiplies a Beta posterior over per-fact mw_success/mw_fail counters into recall scoring. The counters live in hand-editable frontmatter, so the scorer receives values no writer would produce: fractions, negatives, NaN, 1e308 (which overflows the Laplace denominator to Infinity and drives the ratio to 0 - the opposite of the neutral prior), future lastAccessed stamps, and mis-constructed Dates. A partially corrupt record (mw_success: 10, mw_fail: NaN) would otherwise read as strong positive evidence.

## Decision
(1) Counter classification: an ABSENT counter is legitimate 'no data yet' (legacy half-instrumentation allowed); a fractional or negative value, or anything past the plausible upper bound, is corruption - refused outright (never floored) at write, and at score time it fails the record. (2) If EITHER counter is corrupt, the whole record collapses to the Beta(1,1) prior - partial evidence is never trusted. (3) Scoring uses Laplace smoothing ((s+1)/(s+f+2)), is defensively clamped to [0,1] against floating-point noise, and merely-very-large safe-integer counts pass through without collapsing. (4) Decay: an invalid now value (NaN/bad Date, or a future lastAccessed) skips decay and clamps age to zero rather than propagating NaN into recall ranking; negative decay is never applied. (5) Base scores are clamped at zero before the worth multiplier (a negative base would flip the multiplier's direction); candidates keep input order with an encoded stable tiebreak. (6) Outcome increments serialize per memory ID (promise-chained lock) so concurrent calls each persist +1; upstream errors are swallowed per memory and detached cleanup carries a catch handler; absent counters read as 0 matching the Beta(1,1) prior; corrupt stored values are rejected at write (refuse to layer increments on garbage) and surface as not_found. (7) Eligible categories are an allowlist kept in lockstep with the operator toolkit (declared locally to avoid a circular dep); corrections are never eligible (per-fact signal; legacy buckets must not inflate tallies). (8) mw_* fields are never set at creation (writeFactFile bypasses writeMemory deliberately); a negative counter on the update path must surface a validation failure, not clamp. (9) The in-package benchmark is the acceptance gate for enabling the filter by default: a deterministic (seeded) synthetic corpus where true positives only reach the top 5 with the filter applied - if it fails, do NOT ship the default flip; any new result field triggers a conscious re-evaluation of the default. Non-positive-integer bench case counts are rejected loudly (0 would produce a NaN precision). The CLI entrypoint normalizes its module URL via url.pathToFileURL with a naive fallback and a lazy node:url import.

## Consequences
Corruption collapses discard real (if partial) evidence; refusing fractional counters rejects hand-tuned frontmatter; the default-flip bench gate couples rollout to a synthetic corpus whose assumptions must be re-checked when scoring changes.
