# Replica divergence telemetry is validated at the trust boundary, certified only on complete censuses, and monitored with stale-while-rerefresh bounds

Status: accepted

## Context
The divergence monitor compares local corpus watermarks against peer-reported telemetry over the network. A peer can be unreachable, slow, scoped by a restricted token, mid-upgrade (fields absent), or simply lying (negative counts, duplicate keys, stale or future timestamps). A wrong read certifies convergence that does not exist or reports permanent false divergence against a scoped token.

Scope note: This file merges the divergence-comparison, peer-telemetry validation, fetch-bounding, capability-filtering, monitor caching, peer-config validation, and secret-resolution themes: one family about trusting peer telemetry.

## Decision
Peer telemetry is untrusted input validated against the namespace boundary: a noncanonical namespace key (path separator, control character) is corrupt telemetry, counts must be nonnegative integers, timestamps must be present and parseable, and any malformed entry routes the WHOLE peer response to `unknown` — never a silently smaller corpus that could read as converged; an empty array is a valid empty corpus and stays ok. Duplicate namespace keys are malformed (a later entry silently winning could certify convergence after a mismatch). Census completeness: a peer that advertises an incomplete census cannot certify convergence; prefer `corpusComplete` (describes THIS response's array) over the peer's independently-cached census flag; absent fields are compatibility (older peers), present-but-wrong types are corrupt and must not fall through to a weaker signal. The census freshness gate accepts computedAt only within a window in EITHER direction — too old predates changes, too far in the future is clock skew — and maxWatermarkAgeDeltaMs=0 means the strictest divergence mode, not a zero-length gate. Comparison semantics: local_only is advisory (a restricted token hides namespaces it cannot see) but still reported; peer_only is real divergence; equal counts with different digests is the split-brain signal; matching counts+digests with one dated and one null newestWrite is inconsistent telemetry, not agreement — a missing measurement cannot prove convergence. Per-peer errors never reject the whole poll. Fetching is bounded: one deadline for the whole peer (never one per prefix, which would double the documented bound), covering token resolution so a stalled SecretRef resolver cannot wedge the single-flight refresh; a dead resolver, resolution failure, or stall degrades to a per-peer failure, never a throw or hang; the deadline timer is NOT unref'd (it is the enforcing mechanism) and is always cleared on settle; the dual-prefix probe tries the path this server registers first, tries the legacy prefix only on 404 (any other non-2xx is real failure; a network error skips the second prefix — the host is unreachable regardless of path); a headers-then-stall mid-body abort is a timeout, not malformed JSON. Capability filtering: fetch-level states carry no namespace data and are preserved verbatim; a comparison peer's deltas are filtered so a restricted token never learns a hidden namespace; a census-level `unknown` survives verbatim (a partial local set is not made safe by filtering); re-certification runs the one shared ladder so a token that hid every namespace resolves to `unknown`, never a convergence claim derived from nothing; peer_only deltas are neutralized against a partial local set while real shared-namespace divergence stands. Monitoring is stale-while-revalidate: a failed poll backs off for one full interval (serving the last good report or the pending placeholder — both truthful, neither `converged`); expiry is measured from poll FINISH so a slow poll does not store an already-expired entry; the cache lives for the shorter of interval and freshness bound so a cached `converged` cannot outlive the gate; the census overlay gate is the SAME shared gate doctor applies so /health and doctor cannot disagree. Peer config: env placeholders expand with config.ts semantics; an UNTERMINATED `${NAME` is rejected at parse time rather than sent as a literal bearer token; only an OMITTED token selects unauthenticated polling (explicit null/empty/whitespace is present-but-invalid and rejected, since silently dropping it surfaces a healthy peer as http_401); re-validate after expansion; peer URLs must be clean bases (no query/fragment — the health path is appended by concatenation) and reject embedded credentials; store the canonical URL form. Secrets: SecretRef cache keys sort their tuple fields so equivalent refs share cache entries; resolver access prefers the injected host resolver and a throwing lazy loader means "no resolver available", not caller abort (doctor still runs unrelated checks); provider secret caches store only successful resolutions so transient failures retry; non-API-key and env-var-shaped markers are filtered out of candidate secrets.

## Consequences
A peer with corrupt or incomplete telemetry reads as `unknown` even when it is probably healthy. Scoped tokens cannot certify convergence they cannot observe. Config typos fail at parse time instead of surfacing as confusing 401s at poll time.
