# One unified TrustScore stage replaces separate filters, with parity-derived signals, cached per namespace, and quarantine that never alters scores

Status: accepted

## Context
Running memory-worth and trust scoring separately double-discounted candidates and let the two disagree; unification costs a single source of truth for weights, thresholds, and decay. Cache correctness requires pairing the corpus version with an age bound because trust values embed time.

## Decision
Trust scoring is a single recall stage producing one bounded [0,1] multiplier; when enabled it subsumes the standalone memory-worth filter (exactly one of the two runs — rule 39).

Rules:
- Signal computation reuses the exact computations of the components it subsumes (the Laplace memory-worth computation with the same recency half-life, converting days to ms) so the stage and any standalone computation never disagree on the same counters; decay must not be lost when subsuming the filter. The stage's multiplier equals `trustMultiplier(trust.score)` exactly — a memory-worth multiplier is never re-applied on top.
- Weight semantics: component weights are canonical in types.ts; active weights are sum-normalized so absent components redistribute their weight to present ones (a memory with only memory-worth data is scored purely on memory-worth). A disabled or absent signal is neutral, not negative; when every present signal's weight is 0, fall back to the neutral prior rather than scoring 0. `unchecked` faithfulness is absent (no signal), so a memory whose only signal is unchecked scores truly neutral and the epistemic hedge does not fire on unverifiable memories; `skipped_no_span` collapses to `unchecked`; provenance "none" is gentle negative evidence; a single corroboration mention is mild negative; "contradicted" contributes 0 and forces quarantine so a corroborated-but-contradicted fact is still excluded. Corrupt or out-of-domain signals are dropped. The blend is clamped to [0,1] against float noise; the base score is clamped at zero before multiplying (a negative base would invert the multiplier's direction); multiplier bounds defend against inverted min/max by taking the tighter bound.
- Bands resolve from one thresholds source; a hedge below high names the weakest component explicitly (never vacuous). Ordering is a stable sort by descending multiplied score with original input position as the deterministic tiebreaker.
- Quarantined candidates are excluded from injection but remain visible to X-ray with the reason (rule 34), and their score is kept unchanged — exclusion must never inflate or zero a hidden item; X-ray shows what the pipeline WOULD have injected.
- The per-namespace signal cache is valid only when the shared cross-process corpus version matches AND the entry is younger than the max age (signals bake `now` into values — ageDays, recency half-life — so an unchanged corpus still goes stale as wall-clock advances; a version-only cache would serve stale decay forever on a read-only corpus). Entries are recorded only when at least one signal is present.
- Preloaded candidate frontmatter seeds signals via the same buildTrustSignalMap computation (O(candidates) fast path, bounded-parallel direct fallback ≤16 matching the search-result batch size); a preloaded candidate absent from the signals map is EXAMINED-and-neutral (multiplier 1.0), never missing — otherwise every uninstrumented hot candidate re-triggers a namespace-wide corpus scan plus a direct re-read, defeating the fast path.
- Identity is a namespace-aware composite key with a bare-path fallback for legacy path-keyed maps (inert in production composite-keyed maps); a namespaced candidate belongs to exactly one namespace and never seeds from another namespace's corpus map. Cold-tier direct reads for namespace-fanout candidates pass the owning namespace so relative paths resolve against the right store, not the first fallback namespace. Namespace scans check the recall's shared assembly deadline cooperatively and stop between batches.
- The stage exposes narrow structural interfaces (frontmatter projections, host callbacks, compact X-ray projections) so it stays decoupled from full internal types.

## Consequences
See Decision: each rule pairs the constraint that forced it with its cost (extra reads and realpath work, explicit caller options, maintenance of shared helpers and gate regexes). Where topics were merged into this theme as nearest neighbours rather than standalone ADRs, that is noted here: the small single-site topics are absorbed into the theme whose files and failure modes they share.
