# Meeting records and memories are built idempotently behind a generator seam, gated by trust, and excluded from generic recall

Status: accepted

## Context
The meetings pipeline (issue #1900) reconstructs meetings from always-on capture signals (screen activity, audio, wearables, provider sources) that are individually unreliable: app-name labels are coarse ('Zoom' matches back-to-back different meetings), transcripts render clocks in a source-local timezone but write them as ending in Z, audio-only detection mistakes television for meetings, and an external durability judge can be down. Rebuilds must be idempotent (no duplicate memories, no wasted LLM calls) and records must never leak raw transcripts into the recall corpus through symlinks or generic recall.

## Decision
(1) Detection requires genuine overlap for app+audio pairing; span dwell ends at the NEXT foreground change (or end-of-array), spans are grouped per capture machine before sorting, and a lone trailing app tick gets a fallback dwell; transcript clocks written as UTC-suffixed are re-anchored to true UTC using each source's timezone. (2) An existing same-day record's id is adopted only on substantial overlap (majority of the shorter window) OR an identity signal corroborated by at least a quarter-window non-marginal overlap - a coarse identity match alone never licenses adoption across a thin sliver. (3) Meeting ids embed the day verbatim (mtg-DATE-HASH) and are validated for shape AND real calendar dates (no 2026-02-30 rollovers), surfaced as clean input errors rather than 500s. (4) The deterministic engine hands built records, removed ids, and unchanged/updated id sets to an injected generator seam: unchanged records skip (zero LLM calls) unless their deterministic episode memory is absent (sentinel for a prior failed generation, which must regenerate); records changed under a kept id have their prior memories retracted and refreshed. (5) Generator and reindex-hook rejections never fail the build after records are persisted - surface a generic warning, log the detail, let the next build catch up; generator-authored warning strings are folded into the surfaced memoryWarning. (6) An optional external durability judge that throws degrades the pass (no verdicts; trust bands still route) rather than aborting the day build. (7) Trust gating: audio-only episodes are classified on the provider-derived title alone and routed to review; meeting transcripts carry the same contamination risk as wearable audio and fixed 0.8 extractor confidence, so high-impact personal claims top out in review; the synthesized summary goes through the SAME trust decision and can be gated out. Facts blocked by the tombstone chokepoint count as blocked, never as written. (8) Facts are idempotent per meeting (no duplicate write of an identical claim). (9) The build fires the isolated reindex whenever anything discoverable changed, including a prior failed episode write. (10) Meeting records live inside the QMD collection root but are excluded from generic recall via the SAME retrieval-policy predicate as artifacts (no parallel filter), and filtering happens BEFORE the cap so dropped records do not consume result slots. (11) meetingsBuild requires a READ grant, not merely a write grant; a write-only principal is denied. (12) The meetings store rejects a symlinked root, day directory, OR leaf record file before any IO, so a pre-existing id.md symlink into facts/ cannot leak raw transcripts into the recall corpus. (13) One CLI runner implementation serves all hosts; --date is validated regardless of enabled state; user app-pattern extensions are additive over shipped defaults; trust bands check the auto-approve band first; mutating HTTP routes carry the mutating quota; the debounced post-sync tail-step does not keep the event loop alive and is flushed on manual wearable syncs.

## Consequences
The high adoption bar can split a genuinely resynced meeting when overlap is thin; review gating delays active memories for audio-only detections; seam isolation means a failing generator leaves memories missing until the next build; strict symlink refusal rejects aliased layouts.
