# Retired facts are protected by namespace-scoped, keyed tombstones that must never resurrect

Status: accepted

## Context
Memory retirement (forget, temporal supersession, pattern reinforcement) must survive re-extraction and import. Several incident threads (issue #1579 and related) showed a retired fact becoming active again: shared backing files let one namespace's tombstone evict another's; revocations referenced tombstone ids that rebuilds re-minted, silently un-revoking; lookups ran on the hot write path where a load failure could crash every write; and multiple processes appending to one JSONL file dropped each other's entries.

## Decision
The tombstone store is the non-resurrection chokepoint, under these rules: (1) every discriminator key includes the namespace, so namespace-scoped stores sharing a backing file cannot evict each other's entries; a namespace equality check is kept as defense-in-depth. (2) Lookup checks EVERY supplied supersession key (the union of the singular and array forms) across all tiers - emitters append one tombstone per matched key, so the active block can live on any later key. (3) Lookup never awaits a load (it is on the hot write path); if the store is not loaded or the backing file is unreadable (ENOENT, permission), it fails open and returns null rather than crashing writes. (4) The record mtime is captured before reading so a successful load does not immediately trigger a staleness reload. (5) All appends, revokes, and rebuilds run under an in-process mutation serializer that wraps a cross-process advisory lockfile; under that lock the in-memory index is re-synced against disk before any payload is computed, so a rebuild can never overwrite a peer's just-appended entry. (6) Rebuild preserves existing revocations and tombstones from OTHER namespaces, reuses existing tombstone ids keyed by (sourceMemoryId, supersessionKey) so revocations survive, and preserves a persisted content hash whenever the legacy normalizer is ambiguous (including the empty-skeleton case), keeping both the persisted identity and the current-body alias. (7) Forget, supersede, and pattern reinforcement emit a LIVE tombstone (best-effort, one per derived supersession key via the shared helper) at retirement time so the block exists before any manual rebuild. (8) A write blocked by a tombstone counts as blocked - never as the requested active/review write - and surfaces id+tier in safety reasons for recall x-ray. (9) The semantic tier ships dark, off by default.

## Consequences
Fail-open lookup means a not-yet-loaded store can miss a tombstone; callers must ensure the store is loaded (StorageManager does). The full read-merge-write under a cross-process lock serializes concurrent writers; rebuild rewrites the whole JSONL and depends on preservation rules to avoid cross-namespace data loss.
