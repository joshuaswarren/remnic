# Install-time gates and tests replicate the runtime's exact resolution rules so a green result never lies

Status: accepted

## Context
The plugin's MCP proxy refuses to start on fatal config (for example a plain-HTTP daemon URL to a non-loopback host without the cleartext opt-in), which historically let `agy plugin install` complete green while remember/recall tools never registered. The proxy cannot be imported by a checker — it starts a server at module load — so install-time and test-time checks must duplicate runtime logic, and duplication is only safe if tests pin every input the runtime consults. Developer and CI shells routinely carry real token and daemon-URL variables that would otherwise leak into no-token or default-refusal test paths through `...process.env` spreads.

## Decision
Install preflight: run before plugin install and mirror the MCP server's env-resolution order and cleartext-http gate deliberately — the proxy cannot be imported, and the two checks must agree or the preflight lies about the install outcome. Exit 0 means the proxy will start (silent for loopback/https, one warning line when the cleartext opt-in is engaged); exit 2 mirrors the proxy's startup refusal and names the daemon URL, the refusal, and the opt-in. Unexpanded `${...}` placeholder values count as unset, same as the proxy — an install-time template must not pass as a real URL.

MCP stdio proxy contracts: `http://` is gated to loopback targets so the bearer token never travels cleartext off-host, `https://` is unrestricted, and `REMNIC_MCP_ALLOW_CLEARTEXT_HTTP=1` is the explicit opt-in for trusted-LAN deployments — the refusal stays the default. Upstream Node errors are sanitized (paths and control characters stripped) so nothing leaks into the JSON-RPC error envelope. One newline-terminated line per JSON-RPC record, with any trailing partial line flushed. Only the first terminal path per forwarded request may write a reply (request and response error channels and late socket errors can all fire). A bare base URL targets the daemon's `/mcp` endpoint; an explicit path is preserved as configured. Notifications never reply — 2xx bodies are silently discarded — and empty 202/204 bodies on a request are contract violations surfaced as parse errors so clients see failure. Credentials resolve from the environment or the shared Remnic token store (hooks and MCP share one credential); placeholder values are unset.

Test isolation: hook and proxy integration tests spawn the real runner/proxy as child processes against an in-process mock HTTP server, with isolated `HOME`/`XDG_STATE_HOME`, and pin every environment variable the code consults — every token name, `REMNIC_HOOK_TOKEN`, daemon-URL variables, opt-ins — so an inherited value from a developer shell or CI runner cannot flip a no-token assertion or leak an opt-in. Tests that want specific values set them via an `env.extra` override that spreads last. Implementation-detail assertions read the shared core module; behavioral tests spawn the wrapper entry. Mock servers are consumed with async spawns so the test's event loop stays free to answer. Where a test stub must block on `Atomics.wait` (the sync probe), the stub runs on its own worker thread so its event loop keeps turning.

## Consequences
A green install and a green suite reflect what the runtime will actually do. The duplicated gate logic must be updated in lockstep with the proxy (flagged in code), the env-pinning lists must grow with every new variable the runtime consults, and spawning real processes makes the suites slower but honest.
