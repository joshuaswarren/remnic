# Flush-plan ingestion is claim-based and at-least-once, hardened against symlink swaps, and adapts chunk size to the daemon's body limit

Status: accepted

## Context
The host appends durable notes to a plan file while flushes run; a crash between a claim rename and its merge strands notes; several processes (and replacement lock holders) can work on the same snapshot; the daemon's `maxBodyBytes` is configurable to any positive integer and is not reported anywhere the client can read; an old failure contract collapsed every error to `null` and retried forever on auth refusals; and a writable workspace lets an attacker plant symlinks (issue #2380). The transcript flush that follows shares the same deadline.

## Decision
- Take ownership by an atomic rename claim under a bounded lock; fold any stranded rotate target into the snapshot BEFORE claiming (renaming the live plan onto it would destroy its notes), and abort the claim when that target exists so the new owner recovers instead.
- Ownership is re-checked immediately before every destructive write, not assumed from the acquire: long synchronous chunking, recovery reads, and observe awaits are exactly the windows where a stale-break can hand the snapshot to a replacement holder. After ownership is lost the run writes nothing; the accepted chunk is resent by the next owner — observe is at-least-once here, the safe direction.
- An accepted chunk is committed and dropped BEFORE anything else can return; a later chunk that throws must not resend what the daemon already took.
- Chunks start large and HALVE only on a body-limit rejection (413): 431 is an oversized header and a refused credential does not shrink — both stop the ladder instead of running it. No fixed ceiling is guessed, because the daemon's limit is unreported; adapting needs no daemon surface and converges in a few requests.
- At the minimum chunk size, a still-refused leading line is one the daemon will never take: it is set aside in an inspectable sidecar — nothing deleted — so the queue keeps draining. The trigger is the CHUNK's shape, not a byte floor, so a tiny daemon limit still splits instead of quarantining notes it would have accepted.
- Newly appended notes are re-claimed a bounded number of times so they still leave in this flush, without spending the whole shared deadline that the following transcript flush needs; a contended lock declines the flush.
- EVERY path this module reads or writes is checked, not just the plan: `lstat` on the root and every segment (never `realpath`, so a link cannot be resolved away before the check), re-validated inside the lock (the one-time check ran before the lock wait), opened with `O_NOFOLLOW`, and the snapshot directory pinned by descriptor with inode verification so a swapped parent cannot redirect a create, rename, or unlink; a host without procfs falls back to path-based I/O rather than trusting an unverified descriptor.
- Writes replace the target in one step — fresh temp file via `wx`, then rename — and use 0600 so a default-mode temp under a permissive umask cannot widen the durable notes.
- Deadline is shared with the caller: the lock wait never exceeds what is left, and the stale-interval re-check runs AFTER sidecar writes that can themselves outlast it.

## Consequences
- Notes are never silently lost: crash windows leave recoverable `.rotating`/`.inflight` state, and duplicate delivery (at-least-once) is the only failure direction.
- Planted-symlink attacks fail closed at every layer; the cost is per-segment `lstat`, descriptor verification, and temp-plus-rename writes.
- No fixed body-size assumption; small daemons get slower draining instead of deadlocked flushes.
- Quarantined lines require operator inspection; the flush declines rather than queues when another holder owns the plan.
