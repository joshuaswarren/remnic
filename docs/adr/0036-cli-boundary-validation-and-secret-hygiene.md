# The CLI validates all input at the boundary and never lets config-derived values reach output

Status: accepted

## Context
Config parse errors embed raw config values, including resolved API keys, and static analysis flags any such value reaching console output. Credential material can likewise leak through warnings, error messages, or process listings. Separately, lax flag parsing silently consumes values, falls through to defaults, or mistakes flag values for positional arguments.

## Decision
- Every command that catches a config or bootstrap parse failure prints a fixed constant message — never the error text — and logs nothing derived from the config: not the parsed object (a redactor cannot see through taint and a deny-list is only as complete as its last edit), not its shape (which still reads every value), not the raw file text. Registry paths that install no logger use quiet parsers and report the file path, never the caught error. Credential warnings fire once per invocation and never echo the value.
- Value flags must carry a real value: a bare flag, or one whose value is another flag, is rejected. A flag present without its value is malformed input, never "use the default". Value-bearing flags are extracted before boolean flags are consumed. Scoped-capability flags parse before positionals and each consumes exactly one following token, so a flag value is never mistaken for a command's positional argument; skipping each value flag and its token leaves only real positionals. `--source` is extracted before positional handling so later arguments can override it. Tilde expansion applies to every path input — explicit flags and config/env-derived defaults alike. Directory arguments reject file paths but permit not-yet-existing directories.
- A present, non-empty config file is authoritative and parsed strictly: any invalid value — unknown key, bad policy, malformed structure — surfaces as an error rather than silently defaulting, which could auto-resolve conflicts the operator configured against.
- Credential resolution is explicit. An argv token is accepted where offered (its process-listing visibility is the documented trade-off); an empty env credential is a hard error rather than a silent no-token run or a fall-through to a lower-precedence channel; and all offline subcommands validate credentials through the one shared channel. Connector tokens that authorize health exclude tokens the access server pins to narrower paths, so a health probe cannot produce a misleading 401. OAuth approve/deny requires a TTY: the no-TTY gate fires before any decision request, while the lookup GET may run so the operator can see what they would approve. Pending scopes and resource are displayed for vetting; the operator token resolves from env exactly as the daemon merges it (env accepted even with a file token present); and a server `error_description` reaches the operator verbatim.
- Command-surface tests exercise dispatch in-process: HOME points at a temp directory so the migration pass is a no-op and no developer state is touched; only fast, deterministic commands are routed, while heavy commands stay in their subsystem suites; the catch-all banner's absence proves routing; and every command advertised in the banner must appear in the dispatcher inventory. Pure argument helpers are extracted so tests can import them without triggering the CLI, and positional/flag separation logic is delegated to the exported parser for independent testability.

## Consequences
Boundary errors are less specific (fixed messages), previously-tolerated configs now fail parse, and the surface suite deliberately excludes slow commands. Argv-passed credentials remain visible in process listings; the env/file parity rule exists so the CLI never fails authorization against a daemon that merged env over file.
