# One scope plan decides read, write, and objective-state namespaces across every surface

Status: accepted

## Context
Namespace decisions were resolved ad hoc at many call sites: the write layer recorded decisions under a profile-plan-authorized namespace while the read layer used raw namespace ACLs (rejecting profile-granted layers the same session wrote through); memory_search had no sessionKey and probed the default store eagerly; deep recall loaded the DEFAULT namespace's harmonic graph and searched the base collection for non-default callers; objective-state risked silently collapsing to the default store; and session-delta gated marker writes on canWriteNamespace, which misses overlay/profile grants.

## Decision
- All surfaces must resolve namespaces through the shared scope-module resolvers: one resolved namespace, one storage instance, per read or write. Read authorization must use the SAME profile-plan authorization as the write path, not the raw namespace ACL.
- A sessionKey is REQUIRED to apply the coding overlay: sessionless reads and writes land in the base namespace, so a client supplying cwd/projectTag without a session never lands in a `default-project-*` namespace its own recall never searches.
- With no overlay, implicit writes collapse to config.defaultNamespace exactly like the legacy memory_store path (namespaces-disabled / no-session / projectScope-off).
- Objective-state keeps its stricter contract: an implicit snapshot is based on the PRINCIPAL SELF namespace and authorized against that base (least privilege); the rejection for an unwritable self base must stay, but only when objective-state writes are enabled. scopeDebug.baseNamespace reports the self base, not the general write namespace. Legacy overlay compatibility applies only to principal-owned user-project layers, never hosted profile layers.
- memory_search reaches the default collection lazily, only after authorization and only for profile-intended global-layer queries with no explicit namespace.
- Deep recall resolves through the same namespace layer as memoryGet: seeds search the namespace's own collection, harmonic overrides only apply to default-namespace reads, nodes/anchors project against the namespace's current active memories, private records read as absent, and the active set is enumerated (never an exclusion list).
- Session-delta marker writes gate on the WRITE-path resolver (memory_store's exact authorization), and read/write markers from the namespace-routed storage root, not the global memoryDir.

## Consequences
Authorization behavior is uniform across observe, recall, search, compaction, delta, and deep recall. Dynamic project namespaces must not be re-rejected by the persist layer after the resolver authorized them. Unauthenticated callers cannot read arbitrary namespaces when namespaces are enabled.
