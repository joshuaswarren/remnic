# A configured local faithfulness endpoint is an opt-in fast path fully decoupled from the fallback chain

Status: accepted

## Context
A local fine-tuned verifier endpoint is the cheapest deterministic path when configured, but a local outage or misconfiguration must not degrade the whole gate, and local-only configuration must not leak into the gateway fallback chain.

## Decision
When extractionFaithfulnessBaseUrl plus a model name are configured, the local endpoint is tried first; ANY failure (network, non-2xx, malformed body, timeout) returns null and falls through to the configured chain, preserving byte-identical routing when unset. The local probe gets a smaller budget than the batch timeout (half, minimum 500ms) so a hanging endpoint abandons before the batch timer fires, and the batch AbortSignal is forwarded so the probe aborts the instant the batch budget elapses. extractionFaithfulnessModel is the LOCAL model's name: it never reaches the fallback chain as an override — a local outage must yield graceful fallback, not backend_unavailable on an unavailable local-only model. Conversely, an explicit faithfulness model override (or gateway modelSource) skips the local backend entirely, because LocalLlmClient ignores options.model and would silently run the wrong model. LocalLlmClient ignores options.signal (it uses its own per-attempt controller keyed on timeoutMs), so the gate forwards timeoutMs per attempt and must not rely on the batch signal for the local client. A 200-with-garbage local response surfaces malformed_output by default (misconfiguration must be visible); with extractionFaithfulnessLocalParseFallback=true an unparseable OR partial response falls through to the chain — accepted only when the parsed verdict map covers every expected integer index 0..N-1 (non-integer indexes rejected). Object-wrapped verdict arrays ({"results": [...]}, {"verdicts": ...}, {"entries": ...}, {"facts": ...}) are accepted; rejecting them marked batches malformed_output and let unsupported facts write ACTIVE in enforce mode. CLI boolean overrides arrive as the string "true" and are coerced, never compared with === true.

## Consequences
The default parse-fallback-off setting makes a bad local endpoint loud instead of silent; the completeness gate can still reject a locally valid-looking but incomplete verdict, paying a chain call.
