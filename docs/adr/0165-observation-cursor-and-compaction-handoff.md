# Transcript observation is cursor-checkpointed per session, and compaction drains the unobserved tail before flushing

Status: accepted

## Context
Observation of a host transcript is asynchronous and concurrent: a detached worker can be mid-observe when the session ends or the host compacts, several hook events fire for the same session id (hosts reuse ids across resume), and the LCM compaction flush can only drain work already queued by earlier observe calls. Without explicit checkpoints and ordering, a crashed or contended run either replays the whole transcript, silently drops the last turns before the host summarizes them away, or corrupts cursor state through symlinks and stale locks.

## Decision
Checkpointing: each session has a cursor marking the last successfully observed offset; it is advanced only after a successful observe and retained on failure so the tail is retried, never lost. After the final flush succeeds (or there is nothing left to flush), a done tombstone is written containing the observed-message checkpoint. Queued workers check the tombstone under the lock and exit rather than treating a missing cursor as 0 and replaying the whole transcript. SessionStart restores the tombstone's checkpoint into the cursor and clears it, so a resumed session observes the new tail instead of never observing again. The final flush never operates through a symlinked cursor file, and symlink targets are left exactly as created. When the drain cannot run at all, neither marker nor cursor changes — state stays intact for retry.

Concurrency: session state is guarded by a mkdir-based per-session mutex with stale-lock reaping (10 minutes) and explicit wait budgets per caller: roughly 5 s for foreground hooks, ~15 s for the PreCompact tail drain, ~120 s for the detached session-end drain (an in-flight observe can run that long). `0` retries means "try once, don't wait" — a free lock is still taken; only a busy lock is skipped immediately.

Compaction handoff: PreCompact must drain the unobserved transcript tail to `/engram/v1/observe` BEFORE posting the LCM compaction flush, because the flush only drains already-queued work and a turn that landed after the last PostToolUse exists only in the transcript — it would be lost when the host summarizes the context. The drain waits a bounded budget for an in-flight observe worker: once it releases the lock, either it already advanced the cursor or we observe the remaining delta, and the flush then sees all queued work. If the worker outlasts the budget, PreCompact returns "busy" and skips the flush entirely — deferring to the next PreCompact/Stop rather than racing. On success the cursor is advanced, not removed, so the post-compact transcript does not re-observe the tail. PreCompact acknowledges first so the host never waits on the network, and always returns `continue:true`. Devin emits PostCompaction (after the fact) instead of a pre-compact event; the same drain+flush is equally correct there.

## Consequences
Observation survives crashes, resumes, and contention without duplication or loss, at the cost of persistent per-session state (cursor, lock, tombstone) that must be reaped and adopted across version migrations. Skipping a flush under lock contention deliberately postpones memory of that tail to the next cycle — correctness is chosen over liveness.
