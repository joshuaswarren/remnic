# Recall filters and caps run exclusion-before-cap, with temporal validity evaluated at the pinned instant

Status: accepted

## Context
Generic recall draws from a capped fetch window shared with meeting records, archived rows, locked secure-store entries and superseded facts. If exclusion or supersession filtering runs after the cap, non-recallable records starve valid memories out of the window with no refill; if supersession runs before an as_of check, historically valid facts are wrongly dropped.

## Decision
Exclude non-recallable records (dedicated surfaces, generic-recall exclusions, review-lifecycle statuses, unloadable secure-store candidates) BEFORE applying any fetch cap or truncation, and overfetch the full candidate set first. When the caller pins as_of, evaluate temporal validity at that instant first and bypass the supersession filter entirely; otherwise drop superseded facts unless configured otherwise, and admit a superseded row only through the state-view post-pass fixpoint when its successor survives every gate. Read temporal and tag snapshots together for consistency, distrust mtime for age when content dates exist, and render loaded flat memories rather than QMD previews.

## Consequences
Candidate fetches are larger than the caller's limit by design. Historical recall bypasses supersession, so as_of callers must rely on isValidAsOf as the sole historical authority. Cap slots are never spent on rows that later filters would drop.
