# Memory frontmatter is round-trip safe (emit only when present, preserve explicit zeros, validate on write) and all text parsing is ReDoS-safe and deterministic

Status: accepted

## Context

Frontmatter is read and written by many components and external tools; YAML quoting and tokenizer choices can inject or corrupt data, and naive regexes over memory text backtrack polynomially on hostile input. Consolidation and citation flows parse LLM/stored text and must stay deterministic and collision-free.

## Decision

Frontmatter fields are emitted ONLY when present so legacy files round-trip without new keys; Memory Worth counters are preserved verbatim including explicit zeros (a zero is data, not absence), and counters/provenance (consolidation derived_from/derived_via, bi-temporal observedAt, telemetry values like surprise in [0,1]) are validated on write and tolerated as quoted on read via a hand-rolled inline-YAML tokenizer that honors quoting. Values that could break YAML are emitted unquoted only when safe (injection guard), and block-sequence style is collapsed to inline flow style. OKF type metadata is inert presentation; `category` stays canonical. API symbols moved to other modules keep stable re-exports.

All regexes over memory-sized text are ReDoS-safe: bounded repetition instead of `+`, linear trailing trims instead of anchored `\s+$`, dropped whitespace groups, no nested quantifiers, and charCodeAt/token-jump scans instead of per-candidate slicing.

Citation templates build matchers per template with tightened per-placeholder tokens (intermediate tokens cannot cross separator boundaries; the last token is relaxed so values like ISO timestamps match), a compact-token form is only accepted at end-of-string or bracket-wrapped so prose like `long-term` never suppresses citation injection, and whitespace-separated separators require hard bracket delimiters. Canonicalization strips BOTH the default and custom marker forms in either order (a config change can re-tag a body), and a template with no literal anchors yields no matcher — strip passes text through rather than guessing. Substitution is single-pass with a replacer function so `$` sequences emit literally and substituted values are never re-parsed as templates.

Consolidation operator types live in a standalone module (no import cycle); pattern-reinforcement is maintenance-only and NEVER acceptable as LLM output (the LLM vocabulary is narrowly split/merge/update); derived_from parsing distinguishes page-version snapshots from memory ids by consuming only the final :digits, rejecting leading non-alphanumerics and never misclassifying namespace-prefixed ids; JSON extraction walks balanced braces and returns the LAST matching block so a prepended example cannot steal precedence; the heuristic default operator is deliberately conservative; post-consolidation handling is one shared helper for semantic and causal flows. Rule promotion writes sealed envelopes; the derived-rule cache is keyed on the CORPUS version and honors the opt-out.

Smallest topics merged here per the ten-file cap: session display labels are never storage routing keys; the skills registry is host-decoupled with module-relative builtin path resolution and a deliberately minimal six-key frontmatter parser; semantic chunking rounds smoothing windows up to odd (symmetry) and caps targetTokens at maxTokens in every recursive path; the standing memory block sorts by band rank then id codepoints (never localeCompare) so the prefix cache text is byte-identical across rebuilds; connector labels TRUNCATE in recall rendering but SUPPRESS in prompts (a truncated id could collide) — a deliberate asymmetry; scope-forcing is capability-gated with one shared qualifier parser (one boundary rule, one case policy).

## Consequences

Hand-rolled parsing concentrates correctness risk in a few tokenizer/regex sites; conservative operator defaults mean some consolidatable clusters are left unmerged by design; the truncate-vs-suppress asymmetry is intentional and should not be 'fixed'.
