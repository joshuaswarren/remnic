# Startup finalizes QMD state before the init gate opens, shares one backend bring-up per epoch, and keeps heavy work deferred

Status: accepted

## Context
The orchestrator instance is reused across stop/start cycles, recall() awaits the init gate, and on low-power hardware QMD warmup can take 30-60s and cause gateway restart loops if it blocks startup. Concurrent readiness callers, mid-flight lifecycle restarts, and a stale warm router cache (which can skip the catalog's onResolve hook) all race the probe → catalog discovery → collection-ensure → noop-swap sequence.

## Decision
- The QMD probe + collection check (including the NoopSearchBackend swap) must complete BEFORE the init gate opens, so recall() always observes the final backend; a readiness caller arriving mid-run awaits the SAME backend bring-up flight, never a half-finished state, and never starts a second probe/ensure.
- The shared flight is joined only while its epoch is current and not abandoned; it aborts only when its epoch retires or every participating caller's signal has aborted — never on one caller's per-attempt timeout. Each caller holds the run open until its own signal aborts; the last live caller's abort cancels it. An aborted caller settles its own wait as "retired" and releases its slot; the flight clears on settle in both directions without a derived rejecting promise.
- An "unknown" collection check result is unverified: neither readiness nor the full sync may claim success, and the warm-up gate counts it as degraded. Only a verified ensure ("present" or explicit "skipped") disarms the retry loop; the server retry loop owns the sync otherwise.
- Every initialize() recreates the deferred-ready gate, aborts the previous lifecycle controller before replacing it, captures the gate resolver by value, and resolves both initPromise and deferredReady on init failure so callers never hang or pay a timeout penalty. The init-gate timeout is configurable.
- Seed the namespace catalog with all configured namespaces explicitly at startup (best-effort, never fatal); ensure collections for the catalog-union namespace set, not just the configured set.
- Deferred init (QMD sync, warmup, conversation index, caches, cron) runs in the background after the gate; the corpus-wide index update is deliberately NOT awaited — recall serves the previous index until the update commits atomically. Cache/cron warmups that deferredReady callers rely on ARE awaited; errors are caught individually and non-fatal.
- The content-hash dedup index initializes from the corpus-authoritative rebuild; when the locked rebuild cannot run at init, pre-warm with the shared instance and gate misses on non-authority until a later rebuild acquires the lock. The first-save rebuild is backgrounded (joined via a single in-flight promise), tracked for destroy() but not gating deferredReady.
- Wearables auto-sync starts as an unref'd, idempotent, statically-gated periodic timer, re-checked after async import so a destroyed orchestrator never gains a live interval; activity/location schedulers are master-default-off and delegate their lifecycle to their owning registrars, running the same shared runner as CLI/MCP/HTTP.
- When swapping to a no-op backend, reset the real backend's available flag first, so a concurrently captured reference cannot observe isAvailable()===true against a missing collection.

## Consequences
Startup returns fast on weak hardware, and no caller ever observes a half-swapped backend or a stale gate — at the cost of epoch/flight bookkeeping and a first recall that may serve the previous index until the background update commits.
