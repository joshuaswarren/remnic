# Observe captures are durable before they are accepted and never silently evicted, and write quota is accounted exactly once per real mutation inside the idempotency lock

Status: accepted

## Context
Clients treat a 202 as "kept": before #3251 an accepted observe could lose its capture on a lifecycle deadline or disconnect, and a failed buffer save could still ack. Extraction can run for minutes, and capacity pressure tempts eviction of already-accepted pending captures. On the accounting side, retried writes (idempotency replay) must not double-bill quota, while genuinely committed writes must not escape accounting even when the client disconnects mid-flight; the MCP layer reports structured non-errors (`{ ok: false }`) with `isError:false`, which look like successes to naive accounting. Direct service callers bypass wire schemas, so accepted category aliases can arrive uncanonicalized; write fingerprints and quarantine parking must agree on a request's identity. `TranscriptManager.append` silently drops skip-listed channels; two identical observes can overlap before either records a fingerprint; and retaining full turn text for 8192 entries is a heap-exhaustion surface on a daemon that accepts arbitrary observe payloads.

Merged into this theme as nearest neighbours: catalog write-touch recording (writes that bypass the extraction path), the fact-dedup per-dir lock, keyed force-flush preemption, and observe stage timing.

## Decision
1. Durability before acceptance: an ACCEPTED observe leaves a durably pending capture — the capture settles (accepted + durable) even when the tracker cancels; only the background extraction rejects (abort, or queue-wait deadline). A durable-save failure rejects the observe and never acks 202 over non-durable turns (#1909). At cap, a new observe is REFUSED before acceptance — bounded backpressure, never silent eviction of previously accepted pending captures; seeded, pinned captures cannot be evicted.
2. Quota accounting: enforcement is solely authoritative inside the service's idempotency lock (`enforceWriteQuota`), atomic with the real miss and never on a replay; there is no HTTP pre-check, so a stale peek cannot 429 a safe replay (#1434). Admission RESERVES a limiter slot per request; a failed or exempt write (dry run, replay) releases its slot, and the hit records only after the write succeeds. Codegraph tools: only mutating tools count as writes (index, delete_project, ingest_traces, manage_adr record|supersede); read-only tools never hit the quota; rejected calls carrying `{ ok: false }` structuredContent (confirm_required, package_missing, runtime_unavailable) are not billed even though the MCP layer sets `isError:false`; a write tool that succeeded WITHOUT structuredContent still consumed a write and is counted; a mutation that committed just before client disconnect records its side effect, then honors cancellation before any response is emitted.
3. What counts as a write: observe, memory_store, suggestion_submit, decision record/supersede, briefing refresh, and correction planning — planning persists a pending plan file on every successful call, so it mirrors apply's precheck and accounting to bound files under state/corrections/pending. Pure reads (get/list, console state) and operator bookkeeping writes (last-seen head markers, calibration) stay uncounted.
4. Write identity: fingerprints hash the CANONICAL category, so `fact` and an alias spelling under one idempotency key are the same request (#2829); the shared builder is byte-parity-asserted against the historical inline literal. A replayed coercion note is rewritten from THIS request's raw category (#2780 fix B).
5. Category aliases: the schema transform canonicalizes accepted aliases and mints the retained spelling (`rawCategory`) from the request itself; a schema-minted rawCategory always wins; near-misses pass through untouched and reject at the write candidate with the attempted category echoed. Direct service callers (no wire schema) canonicalize at the same boundary the transform covers; the CLI store path performs only the schema parse; in-process consumers canonicalize at the split boundary.
6. Concurrency: the fact-dedup window takes a real per-dir lock on `storage.dir`. Keyed force-flush preemption aborts ONLY the armed slot matching the caller's session key, never a neighbouring session's. The observe scope plan resolves FULLY before any session mutation.
7. Reporting: a tombstone-blocked capture is pending_review (no active copy) and reports as queued_for_review, so HTTP/MCP callers never read it as a successfully stored active memory (#1645). Failed or slow observes record non-content stage timing (25s incident) so slow stages are diagnosable.
8. Transcript persistence (#2783) is best-effort — it must never fail the observe. The skip list is checked BEFORE appending so `transcriptPersisted` stays truthful, and channel identity derives from the RAW session key: the legacy parser requires the `agent:` prefix, so a namespace-prefixed identity would classify every namespaced cron session as "session" and the skip list would silently not apply. The fingerprint is a fixed-size digest, never raw content. Append serialization: check-then-register is atomic on the event loop (no await between its steps); a caller finding an in-flight append awaits it and re-runs BOTH checks; after a failure exactly one waiter proceeds to retry; the fingerprint is remembered only after a successful append, so a transient failure never permanently swallows the turn — the client's retry re-appends. TTL refresh deletes then re-inserts, so Map insertion order cannot make a refreshed fingerprint the FIFO-eviction victim.
9. Default-store transcript writes keep the raw key, mirroring the LCM archive key rules.

## Consequences
Replays return cached responses without consuming quota; dry runs never consume slots; eviction pressure surfaces as explicit refusal instead of data loss. Alias handling must mint `rawCategory` at every entry surface or fingerprints diverge. Transcript persistence adds digest bookkeeping and per-fingerprint serialization to the observe path. Quarantine parking keeps the full request so replay can re-report coercion.
