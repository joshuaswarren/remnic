# Namespace posture is an authorization fact: probed once, cached with health, and failed closed when unproven

Status: accepted

## Context
The daemon may be flat or partitioned and can restart into the other posture at any time — including inside any cache window and without any probe failure to announce it. Health may never have been probed, may be failing, or may answer while staying silent about its posture. The plugin's own config describes the PLUGIN's deployment, never the daemon's partitioning, so there is no local evidence that an absent namespace is safe. On the daemon, an absent namespace means a principal-wide fan-out, and a flat answer licenses exactly that. `status()` is synchronous by the host's interface, and daemon requests resolve credentials dynamically, so refusals cached against the wrong key outlive the token that caused them.

The health snapshot lifecycle, failure backoff, cache TTL, and probe-budgeting notes were merged into this record as the nearest neighbour (they describe the same posture pipeline) to respect the ten-file limit.

## Decision
- Only an explicit daemon-reported `false` makes an absent namespace safe. `true`, `undefined` (never reported, or a probe that failed), and a silent-but-answered health all leave the scope unprovable: refuse.
- An empty scope means "the daemon's default": send the concrete default health reports instead of an absent namespace, and treat that substituted default as an authorization fact that must be verified — a fresh session bound to an unverified substituted default is refused, not run.
- Cache authorization verdicts keyed by namespace AND token; "unknown" is a real verdict and is cached rather than re-probed in front of every request.
- An EXPLICIT scope is the caller's own and the daemon enforces it on the operation endpoint: it needs no posture fact, rides the cache, and costs no probe. An ABSENT scope is decided by the posture, which must be current; unscoped requests revalidate unconditionally rather than trusting any cache window. Each probe of a cached manager costs at most ONE probe, never one eager plus one revalidating.
- The session's namespace binding decides the scope; the model may only restate it. A model-supplied `filters.namespace` is refused outright, because a scope validated here can be rebound before the manager's own resolution runs — there is no atomic way to carry it.
- The FIRST capability handout waits for one real probe (the synchronous `status()` has nothing truthful to report before one); afterwards handouts never block — operations that need a current posture refresh on their own, and expired snapshots converge in the background.
- A failed probe backs off instead of retrying per hook; a persistently malformed 200 backs off exactly like a transport failure; the posture settles to known-unavailable and the backoff owns the retry. Memory must never break the turn, and a persistent failure must not log per hook.
- On probe failure the SAFETY facts stop being proven: flat posture, corpus-shared, and `defaultNamespace` all revert to unknown — a held stale default would slip past the unknown-posture guard and bind a fresh session to the previous tenant.
- One TTL for the whole snapshot: posture does not need a shorter one because unscoped requests revalidate regardless.
- The session's namespace binding is awaited, not fired-and-forgotten: the store is local and the binding must be durable before dependent calls run.

## Consequences
- A flat daemon restarting partitioned, a changed default namespace, and a swapped under-scoped token are all caught within one probe or one cache entry.
- Unscoped operations pay a probe (or fail closed while the daemon is down); explicitly scoped operations stay probe-free and unaffected by a slow or dead `/health`.
- Refusals are precise (naming the fix) rather than silent 403s on first search.
- An absent posture after a long outage means unscoped surfaces refuse until a probe succeeds again — availability is traded for authorization.
