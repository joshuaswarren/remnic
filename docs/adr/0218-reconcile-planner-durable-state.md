# Peer reconciliation plans deterministically with retraction precedence and untrusted-input validation, and durable state writes are lock-guarded and crash-safe

Status: accepted

## Context
Two peer daemons must converge a shared corpus without resurrecting retracted facts, losing deletions, or racing on case-insensitive or Unicode-normalizing filesystems. Peer censuses are untrusted input; identity hashes written by older normalizers are ambiguous; and session/recall state on disk is written by concurrent processes that crash mid-write.

Scope note: This file merges the reconcile planner (#2150), manifest identity-versioning (#2367), cursor/identity-cache, and the recall-state durability themes (rotation lock, offline-sync impressions, defensive copies), plus the small relay/replay/relevance records, into one durability family, as the chunk's ten-file limit requires.

## Decision
Reconciliation uses its own bootstrap planner (not a mode flag) over base-cursor semantics: only an ABSENT base means bootstrap; a base that matches one side turns a conflict into an ordinary one-sided change; base PRESENCE is what proves a deletion, so bootstrap merge must push. Retraction outranks every other decision for a path on EITHER side — planning a retracted path as `identical` lets the peer serve the retracted fact forever. Planning rejects ambiguity rather than guessing: duplicate paths are accepted only when they agree (same bytes with different mtime is still ambiguous under newest-wins); paths that resolve to ONE file (case-fold, NFC, Windows device names, trailing dots/spaces, U+FFFD surrogate collapse, superscript digits) must not draw separate push and pull, with Windows-only hazards constraining a plan only when the LOCAL participant would materialize paths on Windows; one (namespace, path) never draws both push and pull; namespaces compare after trim plus TextEncoder tokenization so lone surrogates and U+FFFD collapse like on disk. Inputs fail loudly: census identity fields validated with digest equal to path in importance; census paths pass the same boundary check as offline-sync; mtimeMs is decision-relevant and fractional values are valid; a bare string satisfies Iterable<string> so tombstone sets must be validated before iteration; a Date/Map/RegExp conflictPolicy silently takes the default, so validate the exact shape. Plans are deterministic: a total ordering for entries byte-identical across runs, `converged` derived from the entries rather than tracked alongside them, newest-wins reads the timestamp so arrival order never picks the winner, and two inputs for one namespace cannot sort equal and let batch order decide. Memory is bounded: index the peer census only, stream the local one, keep path→digest (decision-relevant fields only), never whole records; batch reads are bounded with aborts between batches, cache hits on a synchronous fast path, and every result stored at its own input index (a dense push would drop entries when a miss precedes a hit). Identity is versioned: identity-resolution logic versioned independently of the content normalizer; a non-empty legacy hash is ambiguous, so keep the persisted hash primary and expose the recovered current identity as an alias; an EMPTY legacy skeleton identifies nothing and recovery there is repair; a cache hit is valid only when built by the current parser; a thrown read is not a negative identity; the on-disk cache is node-local (never a peer file) and structurally guarded as untrusted JSON; the cursor trims trailing slashes linearly (no quadratic backtracking) and keys duplicate pairs with the same exported identity. Durable state: every active-file write goes under the shared cross-process rotation lock (concurrent record() serialized through rotate-then-append); a snapshot/drain that cannot acquire the lock must NOT touch the active file unlocked and preserves the spill in the sync-excluded queue; drain writes to a temp name the `.jsonl` lister ignores then atomically renames, claim-then-commit leaves `<uuid>.jsonl.claimed` recoverable after a crash, and a drain-only fold must never push a drained row into a sync-excluded queue nor join under a huge drain. Snapshots and annotate paths deep-copy (caller mutation cannot corrupt internal state), stale snapshots are rejected via writeNonce identity, edge confidence clamps into [0,1], sorts are stabilized by sessionKey, spill refusal degrades to a logged append failure (symlinks never followed), and session keys pass an own-property/proto-pollution guard since they land in indexed structures. Relay missions append under the mutation lock after idempotency replay detection, with cross-process appends as single bounded O_APPEND records, namespace resolution left to the access service, and `found` meaning valid persisted evidence exists. Replay timestamps are strict UTC-only ISO-8601 (no timezone offsets, no local reimplementation); relevance feedback effect is capped against runaway ranking distortion.

## Consequences
Ambiguous convergence cases surface as unresolved operator decisions instead of silent newest-wins. Mixed-version peers without identity versioning cannot reuse cached identities. Lock-timeout paths leave spills for a later drain, so a crashed writer's data is delayed, not lost.
