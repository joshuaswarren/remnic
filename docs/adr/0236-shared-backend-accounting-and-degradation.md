# Shared backends are counted before decisions, fail with explicit backend_unavailable signals, and short-circuit per batch

Status: accepted

## Context
Semantic dedup, enrichment, and cross-namespace budgeting all share external or rate-limited resources. When the embedding backend degrades (timeouts, non-2xx, connection failures), silently returning [] made every fact in a batch pay a full roundtrip and misclassified failures as empty results. Budget config parsed loosely (0.5 flooring to 0) turned warnings into silent denials.

## Decision
On the embedding LOOKUP path, any backend failure — timeout, non-2xx status, or transport error (ECONNREFUSED, DNS, TLS) — throws EmbeddingTimeoutError so search(throwOnTimeout:true) propagates it and decideSemanticDedup classifies it as backend_unavailable (never no_candidates). Recall-path search() without throwOnTimeout catches it and returns [] (fail-open recall). Once the first lookup signals backend_unavailable, subsequent facts in the batch skip the lookup entirely and proceed directly to write (fail-open), so a degraded batch costs one roundtrip, not N. Embedding budgets differ by path: the lookup budget is short (fail open fast); the index budget is long because indexing is off the write-critical path and a silent drop would blind later dedup lookups. Cross-namespace budget config is floored and then defensively required to be > 0, and inverted soft/hard limits are clamped so soft never warns past deny. Budget accounting counts the current call against the window BEFORE deciding, rolls back the entry on denial, evicts empty buckets, releases reservations by identity (never pop-newest), routes calls with a missing principal into a shared bucket ("we can't attribute this call"), and requires BOTH namespaces non-empty before the same-namespace short-circuit. Enrichment reserves rate-limit quota before the awaited provider call and counts failed attempts, since the provider may have consumed external quota before throwing. Config gates coerce boolean-like values and reject present-but-unrecognized values fast, comparing against schema defaults rather than unreliable runtime authorship signals.

## Consequences
A degraded embedding backend flips dedup from skip to write for the rest of the batch — duplicates can appear during degradation by design. Failed provider calls still consume local rate-limit budget. Strict gate parsing turns typos into startup errors instead of silent defaults.
