# Evidence quotes are located by the densest matched-term window, and the verifier always sees the full source evidence

Status: accepted

## Context
When per-fact verified spans are absent, the gate must locate supporting evidence inside potentially long, noisy source text. Naive prefix or midpoint windows drop the supporting words and route actually-entailed facts to pending_review; repeated anaphoric lines can match the wrong occurrence.

## Decision
The QUOTE is sent whole to the verifier (it is already bounded upstream by provenance.maxQuoteChars / locateFactQuote); only the supplementary CONTEXT is bounded by extractionFaithfulnessContextChars ("window around the quote" semantics). The fallback locator builds a bounded window around the densest cluster of matched fact terms, never a first-N prefix or midpoint window, using an O(n) two-pointer sliding window over sorted match positions (an O(n^2) scan would stall extraction on pasted logs with thousands of token repeats). Stopwords are filtered before overlap scoring so function words do not dilute the signal. Equal-overlap candidates tiebreak on a context score including the immediately preceding candidate, so a repeated anaphoric line resolves to the occurrence whose neighbor names the fact entity; the locator returns the matched offset so the context window centers on the matched hit, not the first indexOf hit. Every valid source span of a composite fact is collected — the verifier prompt includes all supporting spans, not just sources[0]. Context is synthesized only for the fallback-locator path; #1575 verified spans already carry full evidence.

## Consequences
The locator is heuristic: an adversarially sparse candidate can still land a window without evidence; context windows sized too small can keep composite facts ambiguous.
