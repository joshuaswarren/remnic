# Maintenance jobs are deterministic, idempotent, and fail-safe: locks cover snapshot plus rewrite, telemetry persistence is best-effort, and filesystem traversal never escapes its containment root

Status: accepted

## Context
Maintenance jobs rewrite files that concurrent writers append to, run on schedules, and produce operator-facing telemetry. Past incidents: a decay snapshot rewrite silently dropped edges appended mid-window (issue #729); a stale lock broken mid-run let a peer own the file; a success marker written after partial migration failures made failures unrecoverable; health reporting showed ran=0 after a budget-skip; symlinked directories could walk writes outside memoryDir. Several smaller themes that did not warrant their own ADR are merged here and governed by the same rules: logging backend lifecycle (coerce boolean-like env strings, late-bind console methods, restore the pristine no-op backend), cron reconciliation (startup reconcile updates only managed leaves so user edits to schedule.expr/message/timeouts survive, model is mirrored at the job root for older OpenClaw builds, schedule labels reflect the actual expression), file-size ceilings (types live in helpers so files stay under their structural ceiling), the MCP read-only allowlist, the model registry creating its directory only on first save (never during read-only discovery), test conventions (serialized suites for process-global state, mirrored production shutdown budgets), tier text formatters, harmonic graph read batching, and loadTimeStamps taking the loaded memory's own stamps rather than a parse-time 'now'.

## Decision
(1) Any snapshot-modify-atomic-rewrite of an append-only file holds the per-file write lock across BOTH the snapshot and the rewrite; read failures other than ENOENT are surfaced strictly so an I/O outage is never reported as 'no data'. CPU-bound passes yield periodically so the lock's mtime heartbeat fires, and ownership is revalidated before a rename-backed replace: if a peer stale-broke the lock mid-pass, leave the file untouched and report zero decayed edges rather than claiming a rewrite that did not land. (2) Job output is deterministic: total sort orders with stable secondary keys, aggregation across all graph types for top-entity lists, and timestamp comparison parses to instants with a lexicographic fallback for unparseable values. (3) Telemetry and index updates are best-effort: failing to persist telemetry must not fail the maintenance run, and a failed QMD re-index after purge is non-fatal (operators can re-index). (4) Markers follow rule #12: a success marker is written only after ALL mutations succeed; individual failures are counted, the sweep continues, and the next start retries. (5) Health reporting merges the last SUCCESSFUL run forward through later skips/failures so lastRunAt never regresses to null, and surfaces failed namespaces with their reason. (6) When namespaces are disabled, mutating maintenance collapses to the default storage only - never the same corpus once per configured name. (7) Filesystem containment: markdown walkers refuse symlinked directories and entries resolving outside the containment root (realpath resolved once and threaded through), the extensions host lstat-checks its root and verifies any symlink stays under the parent memory directory, and file replacement never deletes before write (temp + rename). Restore bumps the corpus sentinel PER entry so no reader serves a partially-restored corpus, and requests one entity reconcile pass because restored bytes carry legacy references. (8) The projection rebuild runs in a forked child so the daemon keeps a fresh heap, reparents are handled by an orphan guard, injected storages are asserted to be rooted at memoryDir, and IPC carries only typed runner messages. (9) Pattern reinforcement scopes cluster keys by category with a collision-free separator, clusters across active AND superseded members so a canonical with absorbed duplicates still reinforces, counts only valid-ID members, refreshes provenance on any membership rotation while keeping reinforcement_count/last_reinforced_at monotonic (provenance-only refresh writes zero times on a stable corpus), and filters already-superseded members which doubles as crash recovery.

## Consequences
Lock revalidation can skip a decay/rewrite pass (reported honestly, retried next run); best-effort telemetry means a crash can lose counters; strict containment rejects aliased directory layouts; merging smaller themes here means logging, cron, and test conventions share one ADR instead of dedicated ones.
