# Vault writes touch only managed regions outside code blocks; timeline and analysis surfaces validate before side effects

Status: accepted

## Context
Remnic publishes managed regions into user-owned vault notes. Forces: fenced or indented code blocks contain EXAMPLE markers/headings that must never be treated as live; naive marker pairing can delete user bytes; frontmatter values can inject YAML keys; dry runs must predict exactly what the real publisher will do; timeline classification and CLI parsing silently dropped flags or positions; and analysis metadata must guarantee no content leakage by shape, not length.

## Decision
- Region ownership: markers are owned only outside fenced/indented code blocks; the region scanner tracks fence state, matches end markers by name (rejecting mismatched or orphaned ends), and CommonMark heading rules (1-3 columns before hashes; 4+ is an owned indented code block) — pairing the wrong pair must be impossible, and a scan that stops early must never pair a start with a LAST end. A missing note is missing_file, never a create; `..notes` is a literal directory name; symlink and traversal escapes are refused.
- Frontmatter: keys/values reject C0/C1 controls, DEL, YAML indicator first characters, and flow delimiters so a written line can never become a new key or split a flow list; lists render in flow form with quoted delimiters.
- Dry run: validates exact field values before classification (undefined/non-string text fields are malformed, never "unchanged"), and byte-exact comparison — a whitespace-only rewrite is still a write. The prediction must match the real publisher's refusals.
- Timeline: category order is deterministic (order, then id tie-break) with user orders stepping by 10; classification rules are ordered by contract and throw on a rule targeting an unknown category (fail loudly, never fall back silently); corrections live in their own SQLite store and reject unknown categories; publish dispatches through ONE shared implementation on both CLI trees before the qa gate (publish is not a qa surface); per-subcommand flag allow-lists reject foreign flags (`--from` on publish) and stray positionals instead of silently discarding them; the complete request validates before any side-effecting loader; recap failure kinds are typed — every supplied candidate validates FIRST, so a malformed low-priority candidate cannot hide behind a valid high-priority one; recurring patterns enforce a min-days floor of 2 that configuration cannot disable.
- Analysis: the no-content guarantee is enforced by SHAPE (identifier-syntax provider/model/version fields), not length caps; error metadata never interpolates or stringifies the value (type and name only, line breaks reported as breaks); the provider chain has no silent fallback — a bad config is a typed failure; observations are confined to the DST-aware day window before anything is sent, and the payload carries no raw capture channels; an empty observation set is a caller-side guard producing nothing, with no typed failure attached.

## Consequences
Publishing is safe against hostile/user-authored note content but requires the scanner to track fence and heading state precisely. Timeline/analysis surfaces reject previously tolerated sloppy inputs up front.
