# Every HTTP/MCP operation dispatches through the boundary with capability and namespace enforcement

Status: accepted

## Context
Operations were migrating off direct service branches onto a strict-schema boundary, but registration alone did not prove migration: a flipped catalog row with unwired dispatch was a false migration that lowered the unmigrated ratchet while handlers still bypassed the boundary. HTTP had no introspection endpoint, so dispatch coverage had to be verified by static source extraction, and namespace-scoped tokens needed guards for request namespaces, record-intrinsic namespaces, and fleet-wide ops that carry no namespace at all.

## Decision
- A catalog entry counts as migrated only when the live surface dispatches through the boundary: a `getOperation` or `enforceTokenOp` marker must exist in THAT method+path handler block. No pathname-only fallback: if the HTTP method cannot be determined from source, the route is ambiguous and must not be counted. Negated method guards (`req.method !== "GET"`) mean the route IS the method; method changes inside a shared route block update the route key.
- The ratchet gate is equality, not merely <=, so a silent catalog edit is caught even under the ceiling.
- All boundary operations register by side-effect import and are enumerated: under a deny-all capability, no operation's handler body may ever execute (schema rejections at zod or the capability gate are both acceptable).
- Effective namespace resolution is a single chokepoint used by HTTP query/body routes, MCP dispatch, and id-loaded routes: undefined maps to the configured default, fails closed when no default exists, and is a no-op for unrestricted tokens. A scoped token whose allow-list includes the default must pass a legacy undefined-namespace pair.
- Handlers selecting targets by record (not request param) must assert the record's intrinsic namespace against the allow-list and fail closed before executing.
- Mint and load treat the capability version marker identically: absent/undefined coerces to the current default in both, an explicitly wrong version is rejected by both.
- Fleet-wide maintenance ops (no namespace arg) are a distinct guard class: a namespace-scoped token must not trigger cross-namespace maintenance, and mapping undefined to default must not wrongly pass it; the ops axis is enforced separately.
- Infrastructure routes (health, /mcp delegate, UI assets) carry no user envelope and stay excluded; the adapters route is op-gated. Correction flows use one plan/apply pipeline. SSE-only endpoints are catalog-tracked with the streaming lifecycle owned by the HTTP transport.

## Consequences
Adding a route requires wiring a dispatch marker and updating the catalog extractor's known dispatch homes (MCP map, HTTP routes, admin tool table fragments); the static validator cannot see routes it does not read. Fail-closed namespace resolution can reject requests on servers with no configured default.
