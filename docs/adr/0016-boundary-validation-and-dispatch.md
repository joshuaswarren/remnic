# Every operation is validated and dispatched at one boundary through canonical schemas

Status: accepted

## Context
Operations are reachable over MCP-over-HTTP and REST, historically with divergent laxness: parallel hand-written field lists drifted from HTTP validation, missing fields silently defaulted, numeric strings and category alias spellings varied by client, a JSON body could carry `__proto__` members that reach schema parses, and correction flows were implemented per surface. The boundary is the one place every transport shares.

## Decision
- Each operation validates through the ONE canonical zod schema the HTTP transport uses — no parallel field list, no silent defaults: a missing query or bad enum is a 400 at the boundary. All surfaces dispatch through boundary-registered operations (registration completes as a side effect of importing the module), so boundary validation and error mapping reach every path; every memory correction (supersession, invalidation, tombstone, edit, rescope, redaction) flows through the single plan/apply pipeline.
- Invalid input is rejected loudly before stores are touched or irreversible work starts: a supplied-but-blank `expect` is forwarded so the service rejects it (matching the HTTP 400); `"abc"` must not become the configured default and `""` must not become 0 for maxSteps; the coding-decision subcommand must be one of its four values; briefing format must be json, markdown, or undefined; a malformed `asOf` is a structured 400, not a silent NaN floor; work-task/project/board action strings outside their union are input errors before any store access.
- Validation errors — and only validation errors — map to 400s. Backend faults (timeouts, storage errors) bubble to the router's error handler as 500s, and only a real `Error.message` is surfaced, never `String(err)` of an arbitrary throw. The effective namespace is resolved and allow-list checked even when the parameter is omitted.
- Enumerated legacy client shapes stay accepted: numeric strings for numbers; `[m:xxxx]` memoryId handles (resolved against the supplying session's recent recall history); no upper cap on memory-search maxResults (pre-boundary clients request large sets); omitted disclosure defaulting per its own rule; explicit null where the wire contract keeps it (e.g. an explicit session-context clear) while other nulls are stripped; category alias transforms run inside the canonical schema with the raw spelling preserved on the context for the coercion note.
- Parsing is prototype-safe: null-stripped targets are prototype-less objects so a copied own `__proto__` cannot invoke the prototype setter ahead of the schema parse, and a reserved key (`__proto__`/`constructor`/`prototype`) is an ordinary client input fault returning the documented validation failure shape instead of throwing past callers. Tests exercise the same shared entry the REST body reader and MCP wire parse run.
- Identity and scoping are server-resolved: client-supplied principal/namespace on envelope tools is rejected (controls are parsed by the one canonical surface module shared with the external tool, semantics in the envelope composer). Transport-level hooks (e.g. an atomic write-quota gate) fire INSIDE the service's idempotent-write lock — never before it, never on a replay.
- Parity: tools carry canonical and legacy names via the alias layer; a host gets identical ranking-mode semantics whether it talks to an embedded orchestrator or a standalone daemon; recall diagnostics live in their own surface module so the HTTP module stays under its size ratchet, with behavior moved verbatim.

## Consequences
One schema and one error mapping per operation; legacy clients keep working only for the enumerated shapes; strictly more explicit 400s; schema-registry types are trusted per registration site (the registered parser is that type's canonical parser).
