# Peer identity, interaction-log, and profile files use strict, deterministic on-disk formats that reject malformed input instead of silently coercing it.

Status: accepted

## Context
Peer files are read back by parsers and edited by hand by operators; a permissive writer/reader pair silently corrupts identity content or loses data on round-trip.

## Decision
Identity frontmatter is a deliberate strict subset of YAML: a leading `---`, one `key: value` pair per line, string values always double-quoted with backslash, double-quote, newline, carriage-return and tab escapes (bare emission of timestamps would let a newline-carrying value inject extra frontmatter fields). No full YAML parser dependency; round-trip behaviour is deterministic and easy to validate.

The interaction log is append-only, one bullet line per entry; EVERY field (timestamp, kind, session id, summary) is sanitized to collapse newlines/CR/tabs so no value can shatter the one-line invariant. Session attribution uses the canonical bracketed `[session=<id>]` form; the legacy unbracketed `session=` form is intentionally NOT parsed because it is ambiguous with summaries that literally begin with `session=`, and an unterminated bracket is treated as summary text rather than misclaimed metadata.

Peer profiles store a JSON payload in a fenced code block with frontmatter updatedAt; the parser validates the payload shape defensively (string updatedAt, object fields/provenance, non-empty observedAt/signal) and throws loudly on malformed sections - `undefined` sections are tolerated only for older files. Symmetric write-path validation rejects prototype-pollution keys and non-string values at the boundary so what writes also reads back. Malformed files throw; empty strings are treated as missing and fall back (createdAt for updatedAt), never silently coerced.

## Consequences
Hand-edited files that diverge from the canonical forms may lose optional metadata or be rejected loudly. Writers carry escape/sanitize overhead, and old unbracketed session-style summaries round-trip verbatim into `summary`, never as session ids.
