# Optional integrations install à la carte, load lazily with actionable hints, and their installers are safe to rerun

Status: accepted

## Context
The CLI must stay functional for users who never install benchmark, capture, export, or adapter packages; the plugin extension is pre-bundled at install time by a host toolchain with platform quirks; and connectors and the OpenClaw entry are written into live configurations where a bad rewrite silently breaks working setups.

## Decision
- Optional packages are never runtime dependencies of the core CLI. Types may be imported at top level (erased at compile time); runtime access goes through lazy, computed-specifier dynamic imports so bundlers leave the call as a runtime resolution. When a package is absent, the CLI surfaces a clean install hint — never a bare module-not-found. A typo'd or genuinely unsupported format surfaces the normal unknown-format error, not an optional-package hint. `query --explain` falls back to a minimal timing explainer when the bench package is absent. Benchmark running has exactly one runtime; every missing-runtime exit uses the shared hint, and `--all` fails with that hint before an empty expansion can be misread.
- The host pre-bundle of the plugin must stay leaf-scoped: extension modules import leaf submodules rather than the core barrel so the bundle stays small and pure-parser modules stay dependency-free. The generated loader must reuse the bundler's artifacts, self-heal by rebuilding into the bundle output, and resolve the bundler binary across platforms — user-profile variables, PATH probes that skip non-executable files and fail closed on a broken version probe, and case-insensitive Windows drive roots. A failed pre-bundle must never destroy a pre-existing dist bundle, and the wrapper import specifier stays stable across installs. Build/publish-only code is never bundled. Install is retry-with-rollback: pre-existing files are restored on retry, and rollback carries symlink TOCTOU defense-in-depth. Prime Agent is a separate install tree; Pi-family overrides must not leak into it.
- Connector management keeps split-form `--config key=value` pairs out of positional matching, while marketplace's file-path `--config <path>` keeps its own semantics. Publishers receive the connector's actual namespace instead of a default fallback. Removal that cannot verify or complete its work exits non-zero — a possibly-partial removal is not a benign no-op. Health output covers only the requested connector's host, not all registered publishers. Enabled flags come from the parsed config, not hardcoded values. An operator who opted out of the extension directory skips that existence check. External-service failures inside an install surface a user-facing note; they never crash the primary flow. Live-connector symbols resolve by dynamic import from the installed core at runtime rather than a static workspace-crossing path.
- OpenClaw entries are written under the canonical plugin id with the memory slot updated to match that id. Migration merges legacy settings (custom models and the like) with new-entry and explicit-flag precedence; the memory directory is preserved across reinstall so a repair run cannot silently relocate the namespace; a scalar or array legacy entry is never spread, which would merge character-index keys. The legacy entry is kept so rollback is possible; the slot is left pointing at a working legacy entry only when the operator declined migration — every other case is updated so the install yields a working configuration. Doctor inspects the slot-selected entry, falling back to the canonical id when the slot is unset or points elsewhere. A default category with mapped memory categories cannot be removed.
- Short-lived processes manage their own lifecycle: service templates run plain node from built output, not TypeScript source; one-shot commands neither wait for nor orphan deferred maintenance — the long-lived process performs full warmup — while teardown still gives short-lived filesystem requests drain time before forcing; a wearables sync drains its debounced meeting build before its process exits; and the orchestrator is only constructed when a run will actually write, with dry-run, help, and install-hint failures short-circuiting before the memory store is touched.

## Consequences
Optional features cost an extra install step with a clear hint; install and rollback code is platform-sensitive and regression-tested; rerunning installers must be side-effect-safe for existing configurations.
