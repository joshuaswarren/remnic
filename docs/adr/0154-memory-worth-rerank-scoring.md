# Memory Worth rebias preserves upstream ordering and never contaminates the original scores

Status: accepted

## Context
The Memory Worth multiplier reorders candidates after reranking. Sorting by raw score directly would snap neutral candidates back to raw-QMD order and undo the reranker; a wall-clock cache TTL shorter than recall p50 turned every steady-state recall into a full-corpus scan; and bare-path keys collapse same-path results in different namespaces.

## Decision
Feed the filter a synthetic monotone-decreasing rank score so input position is the baseline and the multiplier applies on top; on reconstruction, preserve the upstream effective score and write only the order — never the synthetic score — back into results, so downstream telemetry and confidence gates keep original semantics. Candidates with preloaded frontmatter lacking counters are a NEUTRAL prior, excluded from corpus-scan and direct-read fallbacks (bounded-parallel at the shared batch size, errors swallowed). All candidate identity is the composite (namespace, path) key; fallback caches key on the shared cross-process corpus version, which bumps on every memory mutation, not on a wall-clock TTL, and only candidate rows are copied out of the large map. Quarantined items keep multiplier 1 so the stage never looks adjusted; the trust stage and Memory Worth multiplier are mutually exclusive and preference-drift runs after whichever applied; pair reconciliation happens before the user cap/MMR; topN 0 means skip the reorder, preserving 0 as a true zero; and annotation copies results instead of mutating shared objects.

## Consequences
Cache correctness depends on every mutation path bumping the corpus version; a new write path that skips it serves stale counter maps. The composite key is mandatory — bare-path lookups are inert fallback only. Reordering never changes scores, so consumers must read order, not score deltas.
