# Extraction content policy, redaction safety, and assorted shared hardening decisions (merged small themes)

Status: accepted

## Context
This file merges the chunk's smallest themes into their nearest neighbour, per the ten-ADR limit: prompt/content policy, pre-judge redaction, span-mode rollout, non-Latin handling, cross-process dedup windows, importer and read-registry structure, LCM durability, regex safety, and misc correctness pins.

## Decision
Content policy: every prompt that produces memory content embeds the output-language policy verbatim so a non-English conversation is never silently translated (translated memories fail later lexical recall); the system prompt and its JSON response schema have one shared source for every consolidation path; the proactive answer prompt teaches the canonical "In <connector>," qualifier form via prompt instruction, never auto-rejection (agent-tied-ness is the model's job), and assertions test the prompt on unqualified fixtures. Proactive-recovered facts get the same event-time guidance as primary paths (empty string when the bi-temporal gate is off). One funnel serves every successful extraction path; one derivation over boundedTurns feeds qualifier, grounding source, telemetry filter, and result.sourceConnector so the orchestrator never recomputes over a different turn set; ambient-capture provenance clamps high-impact personal facts at the finalize chokepoint; header/qualifier strip-restore gates on scope-classification capability while persistence records resolvedConnector as trusted metadata; temporal anchoring uses the last turn's timestamp; model output content is never logged by default (user data). Pre-judge redaction: the filter consults the predicted namespace's rules — scope=global facts consult the SHARED namespace (a shared-only never-store pattern is otherwise missed until the write gate), while scope-local facts never consult shared rules (guarding against over-redaction), and prediction shares shouldPromoteGlobalFactToShared with the write-loop scope routing so read/write coupling holds (tool-scoped global facts from known integrations are evaluated against session rules). Redaction patterns: only /…/-wrapped patterns compile as regex, everything else is a literal substring; patterns prone to catastrophic backtracking and overly-broad patterns (.*, zero-width) that would withhold all extraction are rejected; a malformed-but-validated rule falls back to a literal on the regex BODY so it still does something; rule files load sorted alphabetically so the MAX_RULE_FILES truncation is filesystem-independent, and truncation logs a visible warning. Span-mode (issue #2333) is bench-gated: Phase B requires ≥20% extraction wall-clock reduction with no quality loss; config fields live in a sibling module (one spread keeps config.ts at the ratchet); materialization runs immediately after parse and before sanitize; span-materialized content is "frame: verbatim slice" — only on-mode facts of that shape may fall back to the slice; span source stamps hash the exact normalized string so offset drift is detected; wire schemas close objects (io:"input") so providers must emit no extra keys, using zod 4's native toJSONSchema (zod-to-json-schema emits an empty document for v4 schemas). Non-Latin handling: importance keywords use Latin words plus CJK bigrams, informationalLength weights CJK/Hangul 3:1, and the documented non-Latin fallback rests on script-agnostic signals; source-grounding tokenization keeps spaceless scripts (CJK, Hangul, Thai) from collapsing into one token. Concurrency windows: non-fact dedup registration and promotion-target writes share the fact-dedup commit window so the artifact-write gap cannot race; reply diagnostics log identifier-shaped key NAMES only (values never read), capped to bound hostile key shapes, with the exact rendering pinned for log parsers. Structure: the four importer adapters share one three-step adapter shape (parse/transform/writeTo) over a narrowed write target, with test-utils shipped only behind the @remnic/core/importers/test-utils subpath so the runtime barrel never links node:fs; the in-flight readAllMemories registry is dedup-not-cache with reference-counted cancellation and named listeners; LCM background summarization bounds leaf batches per job, serializes pre-compaction flushes with summary retries, keeps retry timers ref'd only while awaited, and treats `undefined` sessionless reads as a distinct leading-space sentinel disjoint from real keys; memory-worth benchmark internals are not exported and live connectors live under connectors/live/ to avoid export collisions. Regex safety (CodeQL js/polynomial-redos): heading parsing uses a non-overlapping greedy form, code-fence stripping drops the leading \s* overlap, and trailing-slash stripping uses a loop; verbatim balanced JSON blocks strip before fence rewriting; coding-mode namespace keys collapse guards preserve the legacy 5-part agent shape and never re-combine already-scoped namespaces; seed graduation uses one shared negation vocabulary, only LATER evidence corroborates, and a polarity-flipped restatement vetoes graduation (recall echo does not suppress a contradiction); graph edge confidence/reinforcement fields stay optional for back-compat; timestamped filenames are filesystem-safe, deterministic, UTC; quote-anchored claims ground against the anchor window, not a single sentence; low-information acknowledgements reserve no_recall narrowly to avoid broad recall regressions.

## Consequences
Because this file merges many small themes, its Decision section states each rule locally; nothing here carries a theme-wide invariant beyond what each sentence states.
