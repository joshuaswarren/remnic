# Graph JSONL writes are atomic and lock-revalidated, and tombstones enforce non-resurrection at a single chokepoint

Status: accepted

## Context
Multiple processes rewrite and append graph and tombstone JSONL files; large corpora block the event loop past lock heartbeats, and a retired fact must never silently return through re-extraction, import, consolidation, dreams, or reinforcement.

## Decision
Graph JSONL files are written atomically via temp+rename (never delete-then-rename). Locked sections chunk their parse/serialize with event-loop yields so the lock's mtime heartbeat can fire; ownership is revalidated immediately BEFORE every destructive publish or restore — a lost lock aborts and leaves the peer's newer file untouched (staged temps are orphaned like rename failures). A partial multi-type pass that fails undoes what already landed before surfacing; appended rows of a failed/superseded build are removed exactly, and a lost lock during cleanup means leaving the peer's file and marking residue rather than writing old-plus-partial-new over it. The incremental edge cache is trusted only when every enabled graph file's on-disk identity (size, mtimeMs, ino) is unchanged — in-place pushes require sole-writership validated against per-file identity captured before and after reads, an inode change (temp+rename) or any size mismatch nulls the cache, and contended reads fall back to serving without a consistency guarantee. Tombstones enforce the non-resurrection invariant at the single StorageManager.writeMemory chokepoint so no per-path code is needed: the append-only JSONL is a rebuildable cache of truth, hashed with the same helper as the dedup index, instance- and namespace-scoped, with a later revocation entry re-allowing; blocked writes land as pending_review + blockedBy (never silent), are not registered as dedup/index entries, and rebuild re-reads the log under the cross-process lock so a peer's revocation written while waiting is never lost. Append failures rethrow after logging so callers' rollback steps run; graph mutation events emit fail-open on a per-memoryDir bus, with the default listener warning removed for SSE clients (warn only on leak-suggesting counts). graph.ts stays under its size ratchet by splitting append-error and JSONL primitives into sibling modules.

## Consequences
Revalidation and rollback add stat/read traffic on the write path; orphaned temps and duplicate rows after lost-lock races are tolerated and reconciled by graph health repair.
