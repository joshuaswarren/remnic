# Search surfaces stay inside read-authorized namespaces: LCM reads follow the recall-authorized namespace set, unscoped LCM scans are suppressed, and fan-out search authorizes before it budgets

Status: accepted

## Context
The LCM archive is keyed by the `session_id` STRING and is NOT partitioned by namespace, so an archive-wide full-text scan cannot be constrained to rows the caller may read — sentinel-framed `<ns>`-scoped overlay and tenant rows share the same scan. Implicit reads (no explicit namespace) previously fell back to `config.defaultNamespace` and pre-authorized it, so under a restrictive default READ policy a principal whose self namespace is readable could recall normally while LCM search threw or crossed tenants. Scope profiles always materialize a userGlobal layer even when readOrder omits it, and multi-tenant principals carry their own policy with a self namespace that is not the configured default — so layer presence or readability alone must not pull a principal into the flat default corpus. On a flat corpus the mode-aware backend has no collection selector, so honoring a ranking mode would silently search the default collection. Finally, a zero search budget is a valid empty search and must never skip authorization.

## Decision
1. When namespaces are enabled, an unscoped `lcmSearch` — no `sessionKey` AND no `sessionPrefix` — returns EMPTY, never an archive-wide scan, regardless of an explicit namespace or default readability. A scoped call carries a namespace-framed `session_id`/prefix filter that already confines the search to the caller's authorized, read-gated namespace. An archive-wide scan is safe only in single-store mode (namespaces disabled, one shared archive owned by the caller).
2. Explicit LCM reads authorize strictly through `resolveReadableNamespace` (they throw on an unreadable namespace). Implicit reads NEVER pre-authorize `default`: the read fallback derives from the already read-authorized recall namespace set. When no readable LCM namespace exists — including an active scope profile with no readable layers, whose empty set is authoritative — the search returns no rows instead of throwing, and never falls back around the profile to legacy/default keys.
3. The LCM read `session_id` AND prefix route through the SAME overlay-aware namespace resolution that observe's write key and compaction use: a project-scoped observe with no explicit namespace archived under the coding-overlay namespace, so a prefix derived only from the raw readable namespace would miss those turns. When the overlay base is unauthorized, reads collapse to the default store (the raw session key) exactly like the orchestrator's `lcmReadNamespaceForSession` — never the caller's resolved namespace, which for an implicit read can be a readable recall namespace and would diverge `lcmSearch`/raw disclosure from in-prompt recall. The write purpose keeps its prior fallback for compatibility.
4. Per concrete `sessionKey`, reads use an ordered, read-authorized key set: the primary overlay key first, then each authorized read fallback (project, then root), combined with the principal base — the same ordered set orchestrator recall searches. Explicit namespaces get no overlay fallbacks; overlay rows are appended only when the self base is readable. One corrupt or failed namespace key must not discard sibling results from other authorized namespaces (settled independently).
5. Fan-out memory search: the legacy flat-root default fallback fires only for genuine legacy flat deployments — the principal's self namespace IS the configured default at the flat root, readOrder explicitly intends userGlobal (the materialized layer's presence is not consent), AND that layer resolved readable (a listed-but-unreadable layer is a deliberate omission). `serverShared` maps to the shared namespace, not the default. A policy-having principal is never pulled into the flat default corpus, and a profile deliberately omitting userGlobal never receives the fallback.
6. An explicit ranking mode is validated on BOTH the flat and the namespaced branch, before any budget short-circuit, so a namespaced request cannot rank differently on a typo; on a flat corpus only the flat branch reaches the mode-aware backend. Authorization runs BEFORE any budget decision, so a zero budget — a valid empty search — can never skip the scope check.

## Consequences
Callers authorized for `default` or a single explicit namespace can no longer pull other namespaces' transcript rows through unscoped scans — the cross-tenant read leak is closed at the cost of empty results for unscoped callers. LCM search degrades to empty under restrictive policies instead of erroring. The fallback's explicit-intent conditions make silent corpus widening impossible but require scope plans to state read intent precisely. Ranking modes on namespaced corpora are rejected rather than approximated.
