# Activity storage, journal extraction, and config parsing fail closed at their boundaries

Status: accepted

## Context
The activity store is SQLite+FTS5; journal text is user-authored and machine-extracted; config drives publishing into the user's vault. Forces: a crash between base and FTS inserts leaves rows silently unsearchable; free text must never become FTS5 syntax; INSERT OR IGNORE would swallow NOT NULL failures as dedup conflicts; a corrupt state file must never block extraction; a `../` in a date or a symlinked path must never escape the activity tree; and a config accepted by the parser but rejected by the publisher turns a valid-looking config into a runtime failure.

## Decision
- Store: the state dir is created synchronously before open (idempotent); FTS5 is a standalone table populated explicitly on insert; base+FTS rows insert in ONE transaction; non-NULL validation happens outside the dedup IGNORE so malformed captures are rejected, not silently dropped; unknown text sources are rejected at the boundary instead of coerced on read; FTS MATCH queries are built only from quoted alphanumeric tokens; with sanitization in place a real backend failure propagates instead of reading as empty; snapshots are idempotent on (machine, captured_at_utc, content_hash).
- Journal: extraction is review-only by design (no auto mode); a sanitization violation extracts NOTHING (the placeholder must never become memory content); journal parsing salvages with warn-logged drops; candidates spanning categories dedup beyond the fact-hash index, committing under the extraction window and rechecking there; the strongest copy per normalized content wins per day; a corrupt state file reads as empty and state writes are unique-temp-file + atomic rename; a stray end marker fails closed; a missing vault root is a no-journal day, not an error; note reads use a no-follow fd verified once; reindex failures are reported, never thrown.
- Privacy: delete plans validate the EXACT candidate path (no trimming) and refuse NaN/corrupt timestamps (every NaN comparison is false, which reads as "not retained"); the feature-gate registry is frozen AND literal-typed; gate enumeration uses own-property semantics (getOwnPropertyNames, no inherited keys, present-but-undefined is invalid — never silently false).
- Config: everything validates at parse time, loudly — labels, IANA zones, prerequisite lists (naming EVERY missing item), and enum/numeric fields where a missing key defaults but an explicit null/malformed value fails rather than silently disabling or unbinding; the accepted config domain equals the publisher's domain (no `-->`/newline names, canonical heading validation reused from the journal work, weekly path required only for enabled-and-publishing entries); source base URLs are protocol-checked and confined to loopback; config reads use literal paths so the config-contract extractor can attribute them.
- Memory generation: dedup keys are day-scoped, trim+lowercase; duplicates resolve by decision durability (active > review > drop) then trust, so a higher-confidence reject cannot crowd out a lower-trust accepted copy; the cap seeds from already-persisted memories so repeated runs cannot each write to the limit; trust fields are inserted first so the salvage cap never trims them and extractor attributes never override the path-owned trust key; decision-derived trust persists as confidence with the rationale in attributes, and NaN/absent confidence fails the gate instead of a 0.7 default; pronoun-prefix names are still third parties (word-anchored exclusions) and attribution only fires at leading positions.

## Consequences
Malformed input fails loudly at load/boundary time instead of corrupting state or leaking later. The cost is strictness: some previously tolerated configs and payloads are now rejected up front.
