# Implicit LCM reads are gated by readable recall namespaces, or suppressed

Status: accepted

## Context
LCM archival under a coding overlay writes to a principal-scoped `*-project-*` namespace, but the implicit read side (lcmSearch, recall overlay substitution) historically bypassed the read-authorization / readable-recall-namespace gating that QMD and file recall honor. A principal who can WRITE but not READ its self namespace — or whose `defaultRecallNamespaces` omits `self` — would receive overlay rows it cannot legitimately read: a cross-tenant read leak. Related forces: lcmSearch pre-authorized `undefined => config.defaultNamespace` before deriving the scoped key, throwing under a restrictive default READ policy even when the self overlay was authorized; and an earlier fix wrongly treated ANY readable recall namespace (e.g. `shared`) as license to read the default LCM store, when the implicit LCM read can only target the coding overlay or the default store, never a third namespace.

## Decision
- The overlay substitution on any implicit LCM read must be gated by the readable recall namespace set: the overlay key is used only when the principal's SELF base is readable-in-recall; otherwise the read key collapses to the default store (or the just-authorized fallback key), mirroring exactly what QMD/file recall would search.
- A sessionless recall always searches the base/default store — no sessionKey means no overlay.
- When the self base is not readable-in-recall AND `default` is denied, there is NO authorized LCM target: lcmSearch must SUPPRESS (return empty), never fall back to the denied default store or an arbitrary readable namespace like `shared`.
- A sessionless, prefixless lcmSearch under a denied default store must also be suppressed (it would scan the whole archive). In a single-store deployment with default always readable, the prior unbounded behavior is preserved.
- Read authorization and write authorization diverge by design: a write-only, read-denied principal still gets the authorized fallback key on reads.

## Consequences
Reads return empty where they previously leaked or threw. Callers must not treat an empty implicit LCM result as an error. The read gate is shared with compaction, but compaction's write gate differs (see the compaction-scoping decision).
