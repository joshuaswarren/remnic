# Flush makes session state durable before draining, and extraction lifecycle effects run exactly once per branch

Status: accepted

## Context
Debounced buffering means a flush may read session state whose pending save is still in flight, and an extraction batch can partially succeed (one write durable, a later write throwing) or be aborted mid-transition. Earlier regressions showed chunked parent fact-hashes lost on crash and queued tasks exiting twice or never.

## Decision
Force any pending debounced buffer save to land durably BEFORE reading or draining session state; keep already-durable facts when a later branch of a batch fails (partial success is committed work, not a rollback target); fire session-transition abort logging exactly once per queued task via exit-once bookkeeping; retain (never drop) windows that hit a policy refusal; and treat flush-plan recovery imports as already-summarized compacted material that skips LCM. Handle syntax is normalized at the boundary: strip echoed [m:xxxx] handles before ingestion and resolve surviving handles through the single shared resolver.

## Consequences
Every flush pays a durability round-trip before draining. Partial batch success leaves a durable fact whose sibling writes are absent; consumers must tolerate that shape rather than assuming all-or-nothing batches.
