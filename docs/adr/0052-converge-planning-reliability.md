# Converge planning is resumable and cache-fail-open, and it acts only on classified failures with abort-safe mutation

Status: accepted

## Context
Converge plans between boot-scale pairs run for hours, peers upgrade their manifest implementations independently of stored files, transcripts must never participate in convergence decisions, and operators interrupt long runs. A crashed or degraded component must degrade to recomputation or a stopped cycle — never to wrong pushes, resurrections of retracted memories, or half-applied changes.

## Decision
- The planning cache is an optimization, never a prerequisite: a cache root that cannot be created or written fails open to full recomputation, as does a cached row whose memory status is not a real value. A namespace whose plan failed is never checkpointed; its peers may be. Checkpoints bind to the census they will be validated against — a mismatch between snapshot watermark and manifest census is skipped, not cached — and are written per completed namespace so a later failure leaves earlier work durable.
- Client-built census rows are a SHA-keyed warm base only. Once a peer advertises manifest streaming, no namespace may full-hit a client-built entry; an unchanged watermark must not serve client-built rows after a peer upgrade; and an unversioned peer never gets streamed-manifest reuse. Snapshot requests pin the manifest's transcript set, so the watermark/fileCount validity check always compares the same set. A cache hit requires the peer census to be byte-identical to the one the manifest was built from; fresh mtime/bytes are overlaid for conflict resolution. Older peers fetch content per file, and prior sha-keyed rows skip already-fetched files.
- Invalidation stamps live with the row shape they guard: negative rows (no memory identity) carry theirs at the top level so the "no identity here" verdict survives normalizer/identity upgrades; positive rows keep theirs inside the memory object; a stampless pre-upgrade negative row is never reused. Streamed rows legitimately omit normalizer/identity versions, so the scope key treats them as optional.
- The local identity cache serializes cache replacements per path, persists negative results, persists standalone classifications for files the snapshot iterator excluded (changing no identity decision, only skipping re-reads), and merges with the current on-disk set under the lock before publishing, since another run may have published after this one loaded its snapshot.
- Census resume reuses a cached sha256 only when mtime and bytes are unchanged within the offline-sync tolerance and ctime is not newer than the cached capture. A failed census is dropped on both sides — never planned as an empty corpus, which would push or pull wrongly. A shared physical root is one census: dropping only the representative leaves the other names unplanned. A namespace excluded by the local census must not come back through a cursor to be planned against an empty corpus. Peer snapshot, manifest stream, and apply all pin transcripts out of the compared sets, so transcript-only files stay invisible to convergence.
- Tombstone evidence is load-bearing: a transport-level failure while reading it is fatal, because there is no safe empty-evidence fallback and stale evidence would let a plan push a peer-retracted memory back. The fetched tombstone store is consistent with the snapshot listing exactly when the listed revision is a byte-prefix of the fetched content, compared in bytes throughout to avoid code-unit slicing on non-ASCII logs; a live peer appending tombstones mid-plan is legitimate. Peer-controlled text that reaches logs is sanitized of C0/C1 controls and DEL, and a failed snapshot body is bounded before it is logged.
- Transport failures are classified before reaction. An operator abort is never retried into a fallback route, which would race the shutdown. A timeout or disconnect while reading a refusal body is a transport error, not an HTTP refusal; swallowing it makes every later namespace wait out the same stall. A live-route timeout survives a fallback 404; a malformed fallback must not hide an earlier timeout, and only a valid snapshot clears it; a body timeout is not invalid JSON. A later alias may still succeed after an earlier route timeout, but if neither alias produced the file, the cycle stops instead of treating the miss as an ordinary unread manifest. An aborted planning signal is not a census failure; a peer request that never produced an HTTP status does not reject the cycle outright. The cycle fails only when no namespace remains to plan; a rejection keeps its original message with the original error as cause; a cycle that excluded a namespace is not fully converged.
- Mutation is batched and abort-checked: bounded batches overlap per-file IO waits and guarantee a stop point between batches even when entries needed no transport call; the first SIGINT/SIGTERM stops mutation, not just planning; the cursor write loop is the last mutation phase and must honour abort.
- Plan-cache locking reclaims a lock this process acquired but could not delete, or one carrying this process's exact identity; two processes stealing in a narrow race is accepted as duplicated work with benign identical entries. The lock lease renews its savedAt while open for hosts without readable start ticks, where the 24-hour lease would otherwise expire. Transport endpoints resolve flag > config > env > default in exactly one place, re-exported for the CLI. Capture-lock generation removal keeps its own lock outside the shared IO adapter.
- The watch loop runs convergence on an interval as a sibling module with a required, injected applier (no import cycle); it classifies cycles by status rather than the `converged` flag, exits non-zero when a cycle made no progress so supervisors can react, and prints per-namespace progress on stderr so slow is distinguishable from stuck. Files used as the fast base within the same millisecond as a rewrite stay inside the ctime safety window.

## Consequences
Cache misses increase after peer upgrades and whenever row shapes are in doubt. A failed tombstone read stops the whole cycle rather than risking resurrection. Lock races may duplicate work but never corrupt entries, and interrupted runs resume from valid partial checkpoints.
