# The embedding index publishes one atomic generation under a cross-process lock, with symlink containment and recovery at the rename gap

Status: accepted

## Context
The embedding fallback index is shared across processes and spans crash points (publish rename, backup cleanup, completion marker). Naive writes produced mixed generations (shards from two embedding identities), served planted symlinks pointing outside the state directory, left unrecoverable states between the atomic publish and its rename, or let warm caches serve stale bytes after a peer publication.

## Decision
Sharded generations are the ONLY authoritative state; a legacy embeddings.json is a one-way migration artifact, never merged back, and removal publishes an empty staged directory through the same swap state machine so a partially-deleted generation can never be exposed (the empty published directory stays the one-way layout marker). All mutations take the cross-process generation lock; a cold load enumerates and reads complete shards under the lock so a concurrent swap can never cache a subset; warm cached searches stay lock-free, but mutations drop any cached index first and re-verify the on-disk identity under the lock. Provider swaps run the network embed OUTSIDE the lock, then re-verify identity inside it. An identity change publishes a COMPLETE replacement (the dirty-shard fast path would leave a mixed generation every load rejects). Publication uses a fixed transaction backup; only the rename gap (published directory absent, backup present) is recoverable — the rollback rename is destructive and reasserts lock ownership immediately before each destructive write, and recovery runs in the mutation wrapper before identity probes so deletions and insertions see the restored generation. An unreadable backup or unrecognized on-disk index fails closed (mutation refuses; the file stays for recovery); unsupported identities fail closed like any malformed document; a published generation that cannot be enumerated propagates the error (strict mutation fails closed, recall fails open at its boundary); an empty dirty shard is removed from disk, not skipped. Recall fails OPEN on index read failures by returning [] WITHOUT caching, so a later mutation still revalidates and fails closed. Every generation member and the backup path is checked for symlink containment with lstat at read and mutation boundaries — a regular file inside a symlinked directory is still outside the root and rejected, and containment throws BEFORE any shard membership check. The warm-cache generation stamp moves through a two-half barrier (strict bytes before, best-effort marker after) plus directory stat so it cannot alias consecutive publications on coarse-tick filesystems; an in-flight marker never yields a repeatable stamp, so probes revalidate until a publication completes; cross-process warm caches revalidate deterministically against the published bytes. Shard assignment is stable FNV-1a so updates never need cross-shard moves; reads are gated by the hard single-string ceiling only (not the soft write budget) so legacy indexes still load and migrate; a no-op removal performs no persist and must not clear a recorded persistence failure; lock-acquisition failures are routed through the durable diagnostic exactly once, and recovery failures are recorded durably BEFORE the mutation is rejected. The status file is always plaintext non-secret diagnostics so console_state reads it on locked stores and failure counts never reset. Derived per-directory sidecars follow the same durability discipline: render post-order (deepest first), prune orphaned sidecars from directories that stopped carrying memories, never clobber a user-authored file at the sidecar path (serve nothing instead), fingerprint subtrees content-free (name|size|mtime descriptors), and exclude symlinks from the corpus per the fs-boundary rule.

## Consequences
Mutations are serialized across processes — a peer swap forces a cache drop and reload. Read-path I/O errors degrade recall to empty rather than serving mixed data. Coarse-tick filesystems pay an extra stat per identity probe. Symlink containment rejects legitimately linked stores.
