# Migration-era names and cross-platform realities stay working: legacy CLIs, cursors, config shapes, and payload spellings are honored

Status: accepted

## Context
The project renamed its CLI and env/state names (engram → remnic) while deployments in the wild still carry the old names, and the hook runner must run identically on Linux, macOS, and Windows — where CLIs are `.cmd` npm shims that Node can only launch through a shell, `HOME` is typically unset, and async spawn errors and 32 KB env caps change what detection patterns work. Host payload schemas also evolved (Antigravity documents camelCase fields), and projectId derivation lives in two places that must agree.

## Decision
Shared core: one parameterized cross-platform runner serves all hosts; hosts differ only by configuration, including which project-directory env var is theirs.

CLI fallthrough: try `remnic` first, fall through to legacy `engram` when it is missing from PATH. Detect availability with an `onPath()` PATH pre-check that is `.cmd`/`.exe`-aware, never by catching spawn ENOENT — `spawn` emits ENOENT asynchronously via its `error` event, and under `shell:true` a missing command yields a non-zero shell exit instead, so an exit-code check cannot distinguish "missing" from "migration failed". On Windows, launch through a shell so `.cmd` shims actually run, with fixed literal arguments so that remains safe.

State adoption: adopt legacy `engram-*` cursor/lock files mid-migration, and cursors left in a higher `os.tmpdir()` (or `/tmp`) by older cross-process runs, then clean them up — a rename must never cause a whole-transcript re-observe. Honor legacy config layouts (a top-level-object config) only when the file is not the current OpenClaw-shaped config.

Payload compatibility: documented camelCase Antigravity payload fields (`conversationId`, `transcriptPath`, `lastUserInput`) are applied only when the snake_case key is absent — snake_case wins, so existing hosts are unchanged.

Derived identity: the hook's `normalizeOriginUrl` mirrors the daemon's `remnic-core` git-context implementation exactly; keep them in sync so the hook-computed projectId matches the daemon's.

Child environment: force `HOME` in spawned children to the home the runner resolved (HOME → USERPROFILE → os.homedir()) so the materializer resolves the same config paths on Windows where HOME is unset.

Host isolation: the active host's own project-dir env var always wins, and that variable is deliberately absent from shared fallbacks — a stray cross-host variable can never reroute another host's recall.

## Consequences
Old installs keep working across the rename, at the cost of two code paths for CLI lookup, cursor files, config shapes, and field spellings until the legacy names are retired. Mirrored implementations (normalizeOriginUrl, per-host env resolution) must be updated in lockstep, and each new payload field needs an explicit snake_case/camelCase precedence rule.
