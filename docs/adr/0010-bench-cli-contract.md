# The bench CLI validates at entry, mirrors dry-run to the real run, and publishes exactly the artifacts it produced

Status: accepted

## Context
Benchmarks run against provider endpoints whose misconfiguration only surfaces mid-run; datasets live in a layout that changed once and must stay consistent across subcommands; and artifacts feed a leaderboard where publishing the wrong file, or letting one runtime profile overwrite another, corrupts results silently.

## Decision
- Provider flags validate against one shared allow-list kept in lockstep across `--provider`, `--system-provider`, and `--judge-provider`; the internal-provider list is deliberately narrower. `--model` is free-form but rejects empty strings so it cannot silently fall through to a later default. When the effective provider is `local-llm`, a base URL is required at the boundary for both roles; silently defaulting to another provider's endpoint would make the provider contract untrustworthy. An explicit adapter flag on a run that would ignore it is rejected, not silently dropped. `--dataset` is an alias for `--dataset-dir`; when both are supplied, `--dataset-dir` wins. Published-action flags parse unconditionally so their errors are consistent even outside the action.
- The canonical dataset root is the user-level bench datasets directory in every context, repo checkout or published install. The legacy repo-local tree is read-only fallback discovery: a dataset found there is used with a once-per-process migration hint and is never moved, linked, or mutated; identical roots have nothing to fall back to. Legacy discovery is containment-guarded: the resolved candidate must be a strict subdirectory of the resolved root, rejecting traversal, absolute-path smuggling, symlinked parents, and realpath escapes. The downloaded-marker list is kept in lockstep between `datasets status` and the runner so they never disagree about what counts as downloaded. Run-path auto-selection uses the same discovery and per-benchmark content markers as `datasets status` and `datasets download`, so a just-downloaded dataset is consumable without overrides and an interrupted download cannot feed an empty directory to the loader. The dataset root is threaded to the download script through the environment so writes land where status reads; the script ships with the package with the in-repo path as fallback; Unix relies on the shebang and executable bit, Windows falls back to bash with a clear error since the script is bash-only.
- The bench package is the only benchmark runtime; every missing-runtime exit carries the same actionable install hint, including `--all` expansion, which fails before an empty expansion can be misread as "no runnable benchmarks". Benchmark ids validate before resume/retry-failed filtering so unknown names are caught early instead of silently dropped. Calibration resolves benchmarks through the same package-aware resolver the run command uses, so package-registered benchmarks calibrate instead of being rejected by the static catalog. The default baseline directory is resolved from the bench package itself rather than inlined, since the loader runs on the next line regardless.
- Dry-run mirrors the real run's effective limit so preflight item counts match what will execute, and fails loudly when the dataset source is missing — a dry-run that exits 0 on a missing dataset is not a preflight gate.
- The published harness executes recall, answer, and judge per trial, which requires both models co-resident; when the answer and judge endpoints differ, preflight fails fast with an actionable message instead of failing mid-benchmark after the first trial. `--seed` is forwarded to the runner so the advertised determinism contract is honoured, not just parsed. Matrix runs create per-profile status entries so a failed profile is not overwritten by a later success.
- Artifact promotion copies the exact files this run wrote, collected as they were produced — never a newest-mtime scan of the results directory, which could publish unrelated or older artifacts. The primary result stays in the canonical results location and `--out` receives a flattened copy under a canonical filename that includes the runtime profile so multi-profile runs cannot overwrite one another. A promoted artifact's JSON is shape-validated before dereference — a null parse must crash neither promotion nor the run. The ad-hoc ablation harness stays ad-hoc, not a catalogue entry.

## Consequences
Strict entry validation rejects some invocations earlier; dataset migration stays manual; promotion depends on per-run path collection rather than directory scans.
