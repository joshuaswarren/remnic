# Architecture cards are built deterministically with strict surface guarantees

Status: accepted

## Context
Architecture-card content reaches LLMs and stored memory, so silent nondeterminism, sparse scans overwriting good cards, symlink escapes, or LLM summaries crowding out facts are all real failure modes observed in review. Truncation and card identity were also ambiguous (stale truncated tags, user facts mis-tagged as cards, raw build errors leaking to clients).

## Decision
- The card is a pure, deterministic, byte-stable builder: same repo input, same bytes. The deterministic card's byte budget is reserved FIRST; the LLM summary is prepended only into remaining space, clamped to its own cap, and can never crowd out or truncate deterministic sections when the card fits. An LLM/summariser failure is intentionally swallowed — the deterministic card ships unchanged.
- Scan defensively: expand `~` before resolving rootPath (path.resolve does not expand it); use lstat and skip symlinks (they may point outside the repo root); probe root readability BEFORE scanning so an unreadable root surfaces as `scan_failed` instead of silently overwriting a valid card with a sparse scan (lstat can succeed while readdir is denied); cap walk depth; keep the skip-list of directories conservative; extract presence-only data from non-primary manifests; record bin targets via narrowing guards without casts; surface only the most useful entry-point scripts.
- Truncation is derived from the exported visible content marker, never a frontmatter tag (the refresh update path changes content without rewriting tags, so tag checks go stale). A user-created fact merely tagged "architecture-card" is NOT the managed card — the `cardKind` structured attribute is required; cards archived via `archivedAt` are also filtered.
- Surface handler contract: authorize the write and resolve storage BEFORE scanning or invoking the summariser (an unauthorized refresh fails fast instead of doing work it cannot persist); persist nothing on build failure — no stale card left behind; client-facing errors carry only the code (detail with absolute paths and raw I/O messages goes to operator logs); system-built card content uses strict sealed-envelope compose — an invalid card is a code bug that must surface; a tombstone-blocked write reports `refreshed:false` with a blocked reason, never refreshed:true. Prior card content is snapshotted through page-versioning BEFORE overwrite, skipped when versioning is disabled. Storage reads strip the single-line `[Attributes: ...]` suffix via the shared guarded stripper (single-line-only, so card markdown legitimately ending in an attributes-like line is returned verbatim); `sourceConnector` backfill on refresh is preserved by frontmatter spread; tests mirror the caller's backfill intent. The codegraph `get_architecture` response composes the deterministic card (no live graph) with live graph stats, degrading graph stats to a clean unavailable code rather than failing the composition. Console-script extraction anchors section regexes on `$`/next-header — never `\Z`, which JavaScript treats as a literal Z (a `[project.scripts]` table at EOF was silently dropped); the stub LLM client satisfies the interface structurally with no cast.

## Consequences
- The deterministic builder is deliberately conservative: presence-only manifests and capped depth may under-describe unusual repos rather than mis-describe them; strict compose makes invalid machine-built cards hard failures.
