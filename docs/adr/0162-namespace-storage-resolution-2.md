# Namespace storage is resolved through one routing authority with containment, token decoding, and a safe legacy-raw fallback

Status: accepted

## Context
Per-namespace data lives under either a tokenized dir (`namespaces/<ns-<hex>>/`, post-identity-tokenization) or a legacy raw name (`namespaces/<name>/`, pre-tokenization). The secure store keys ONE master key per memory ROOT, so any maintenance that reads or rewrites a namespace ledger must reach it through the same root-keyed secure StorageManager the router would hand out; a keyless plaintext manager would defer encrypted over-cap ledgers forever or fold ciphertext into plaintext. Separately, directory scans must never be redirected outside memoryDir by symlinks, and ad-hoc dir→namespace derivation duplicated the scope module's logic. Custom namespace routing can also place targetStorage.dir outside memoryDir, storing absolute paths in indexes.

## Decision
- Resolve namespace storage only through the production routing resolver (`resolveNamespaceStorageRoot` / the scope-module resolver); never re-derive inline, and never pass an already-tokenized dir name back through the resolver (it re-tokenizes and can exceed the safe-route limit, making the resolver throw and the encrypted ledger defer forever).
- Decode an on-disk `ns-<hex>` token back to its canonical namespace first. Treat a non-token dir as a raw namespace ONLY when it is a safe route namespace; garbage or traversal names are never handed to the resolver.
- Accept the resolved keyed storage only when it roots at the directory being serviced; any unexpected re-route is refused, preserving namespace isolation and never compacting the wrong ledger. Without a resolver (focused tests / plaintext deployments), keep the keyless target: the rebuild chokepoint still refuses to downgrade an encrypted ledger.
- When namespaces are enabled but the catalog is disabled or a namespace is not yet cataloged, scan `<memoryDir>/namespaces/<token>/state/` directly so per-namespace ledgers are still discovered and bounded; dedupe by resolved dir so catalog-backed namespaces are not processed twice.
- Contain every scan through realpath: reject a symlinked or escaping scan base and skip symlinked/escaping children, so backup and ledger rewrites cannot land outside memoryDir.
- Namespace scope filtering must return the absolute storageDir as the path prefix when targetStorage.dir lies outside memoryDir, so semantic-dedup lookups stay scoped to the correct tenant's files and cross-tenant similarity hits cannot suppress writes.

## Consequences
Encrypted per-namespace ledgers always compact through the correct root key; legacy raw-name deployments keep working without migration. The cost is one resolver round-trip and realpath checks per directory, and a refusal path that leaves an encrypted ledger pending when routing is surprising.
