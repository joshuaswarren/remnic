# The trace recorder never poisons its write chain, drains before close, and every replay/shutdown wait is abortable and time-bounded

Status: accepted

## Context
The console trace recorder serializes writes on a promise chain; the replay loop sleeps between frames and can be Ctrl-C'd; the CLI shuts down by closing the recorder, which may be stuck on a wedged disk. Naive implementations hang shutdown for up to the full replay delay, drop already-enqueued frames, or permanently poison the write chain after one I/O error. Console ledger readers additionally face multi-GB JSONL files that are not sorted by recency.

## Decision
- The serialized write chain must recover after any I/O error: errors are surfaced to the awaiting caller AND the chain is restored to a resolved state, so one failed append never poisons subsequent appends. A non-serializable snapshot is a bug: record-and-skip, not crash.
- `close()` must NOT set `closed = true` before draining: queued writes begin with `if (closed) return`, so the drain of the existing chain happens first, then `closed` flips to reject further appends, then the file handle closes.
- `flushWithTimeout` bounds `recorder.close()` against a deadline: it reports `flushed`/`timedOut` truthfully, returns a flush rejection in `result.error` instead of propagating, clears AND unrefs its fallback timer so normal shutdown is never delayed by the safety net, and fires the caller-supplied AbortSignal when the deadline wins so underlying I/O releases resources instead of staying open until the orphaned chain resolves. The signal must NOT fire when the flush completes in time.
- Replay sleeps are abortable: the default sleep rejects with `AbortError` on signal abort, SIGINT exits cleanly and the replay `finally` still runs; only AbortError-shaped rejections are treated as clean exits — any other error propagates so genuine bugs surface. Replay frame delays are bounded (min/max) so a pathological trace cannot stall replay for an hour; renderer failures emit a minimal error frame and keep replaying.
- Recent-ledger reads use streaming bounded top-N: visit every row, keep only the N most-recent in memory — memory stays O(N) and recency ordering is globally correct, unlike a byte-tail read on a file sorted by session/hour. Missing files are probed via `fs.access` so ENOENT quietly returns `[]` without hitting the readline error path. Orchestrator methods are invoked directly on the object (never extracted to a local) to preserve `this`.
- Flush timeouts are config-overridable with defined precedence (config values over env, defaults last) and parsed invariants (e.g. inverted schedules rejected at parse time); junk env overrides are rejected.

## Consequences
Shutdown is deterministic and prompt even on wedged filesystems, but a timed-out close means trace data may be lost — reported via `timedOut: true` rather than hidden. The abortable-sleep contract is part of the public `sleep` option: custom implementations must reject with an AbortError-shaped error or Ctrl-C will wait out the current sleep.

## Merged themes
`ledger-streaming-top-n`, `jsonl-enoent-probe`, and `orchestrator-method-this-binding` (console state reading) and `converge-peer-timeout`/`converge-config-override-precedence`/`converge-capture-lock-parse-invariants` (bounded, override-aware time budgets) are merged here: they are the same "bound every wait, read streams, never hang shutdown" decision applied to adjacent console surfaces.
