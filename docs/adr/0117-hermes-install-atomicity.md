# Hermes installs are atomic: connector.json is written only after YAML and token commit succeed

Status: accepted

## Context
A Hermes install touches three stores (config.yaml, tokens.json, connector.json) plus the discovery shim. Partial failure - a YAML write that throws, a token commit that truncates tokens.json mid-write (ENOSPC), a connector.json write denied - previously left the daemon with a revoked token and no valid replacement, or a registry pointing at a shim that no longer exists. Two spellings of the same directory (symlinks, case-insensitive volumes) also caused the freshly written shim to be deleted as 'stale'.

## Decision
The install sequence is all-or-nothing: (a) build a token candidate without persisting it; (b) validate the profile fail-fast; (c) write config.yaml - on failure or skip, abort leaving the old token valid and connector.json untouched; (d) commit the token - on failure, roll back the YAML write and abort; (e) write connector.json only after both succeed - on failure, restore the FULL pre-install token-store snapshot (captured before any write, since a single-entry snapshot cannot unwind a partial write), roll back the shim reconciliation and prior-config mutations (in reverse mutation order, from recorded pre-mutation content), and delete only what this install created; (f) run the health check only when the token was actually committed. Paths are compared by resolved file identity, never string equality. Provenance invariants: a Remnic-generated shim on disk is either removed or referenced by the connector JSON; prior marker shims/configs whose cleanup failed stay tracked (priorPluginShimPaths / priorHermesConfigPaths persisted in the SAME registry write as everything else, with pre-mutation content recorded for rollback); provenance paths are read before the connector JSON is deleted so removal targets the HERMES_HOME active at install time. Force-reinstall without re-supplied --config preserves the previously saved profile/host/port (saved JSON, then explicit options, then defaults - each sanitized; saved values coerced so string ports work; invalid user input returns a clean failed result, never a throw). Explicitly-set-but-absent HERMES_HOME directories are created; a missing default profile dir remains the signal that Hermes is not installed. Provider activation stays manual: the exclusive memory.provider slot in the user's config.yaml is never edited. A shim backfill for pre-shim installs reconciles idempotently, is gated on the active home carrying a remnic: block, and mirrors the same rollback (deterministic shim content makes regeneration exact); the real failure (symlinked home, bad profile) is surfaced rather than masked as a missing remnic: block.

## Consequences
Rollback paths are extensive and must be maintained alongside any change to the write order. Failures during rollback itself are swallowed best-effort and reported honestly (rollback success is tracked, never assumed). The daemon keeps working with the old token on any abort, at the cost of not half-completing installs that users might have preferred to force through.
