# Operator doctor checks share gates, resolve config once, and stay informational

Status: accepted

## Context

Operator diagnostics (`doctor`, toolkit) must agree with runtime surfaces: `/health` downgrades would-be-converged peers when the local census is partial, but the doctor once rendered those same peers as converged. Config-driven tools have no live namespace catalog; feature gates were scattered as raw config flags; `unknown`-typed detail fields were re-narrowed at every read; and cold installs would otherwise read as errors.

## Decision

Doctor checks are deliberately light consumers of already-computed state: the replica check normalizes config through the same read-boundary resolver `/health` uses (a missing block degrades to disabled, never aborts the run) and applies the SAME census gate, so both surfaces derive peer state from one function and machine-read JSON cannot report agreement `/health` denies. Corpus watermark and replica-divergence checks are built together as a paired scan, enumerate namespaces config-driven (deduped by root), and live in their own module beside the structurally capped toolkit with a shared extracted result type; `details.corpus` is narrowed exactly once. Each diagnostic resolves feature gates ONCE via the shared helper (config loaders delegate slot/canonical/legacy resolution to it, #403) instead of reading scattered flags. Provenance counts read all tiers via `allSettled`, surfacing partial reads as warnings rather than swallowing failures. A `SecretRef` counts as configured (resolution happens at service start; the resolved value is never logged). Observational checks (Memory Worth legacy counters, buffer-surprise telemetry, judge acceptance, maintenance fanout, tombstone-invariant status, watermark) are informational and never error on their own; the extraction-resilience check infers 'breaker likely open' only from durable parked-fingerprint counts at the configured consecutive-failure threshold (the breaker itself is daemon-only, and a single parked fingerprint is ordinary backoff, never overclaimed). Dreams governance parsing reads the real on-disk manifest format instead of treating every failure as 'no runs yet'. Versioning scans honor the configured `versioningSidecarDir`. Doctor inventory reads disable the hot-memories cache (one-shot reads; caching would retain the full corpus under an unregistered root's gate/TTL), and disabled features lazy-import to keep the doctor fast.

## Consequences

Doctor output is trustworthy, consistent with `/health`, and clean on cold installs; misconfigurations fail at parse time or degrade visibly. Cost: diagnostic parity requires sharing gates rather than re-deriving them per surface.
