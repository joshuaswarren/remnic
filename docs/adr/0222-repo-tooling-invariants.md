# Cross-cutting tooling and platform invariants: token snapshot coherence, envelope belt, opt-in gates, transcript windows, script gates, and test-support contracts

Status: accepted

## Context
These invariants exist because each failure mode was observed: stale-token identity windows, unmigrated writers escaping the envelope, undetected daemon hangs, Windows ENOENT, ReDoS, and docs drift. The cost is maintenance of discovery heuristics and structural constraints (narrow interfaces, dependency-free types, explicit capability records); the merged small topics here are each single-site rules that would not justify standalone ADRs.

## Decision
A family of platform-level rules that recur across modules; each module follows the shared invariant rather than a local variation.

Rules:
- Token cache: validation (token strings) and identity resolution (connector ids) read ONE cached snapshot (re-reads tokens.json at most once per TTL, default 5s; saveTokenStore invalidates on every mutation), so a token can never validate against a fresher snapshot than the one that resolves its connector, and mint-then-use happens in the SAME snapshot call that validates it — no window where a token is valid but its identity is unknown. Every newly-built token entry carries an EXPLICIT capabilities record; when none is requested, a deliberate unrestricted `{ version: 1 }` is recorded — "full access via omission" is reachable only by pre-feature legacy entries. Legacy flat-map store migration is best-effort: a migration write failure must not hide the successfully parsed tokens.
- Tool-scoped memory guard: detection leans permissive (a false positive is cheap — the fact stays in the documented safe narrower namespace; a false negative is the cross-integration tool-collision bug) but must not fire on ordinary prose — word-anchored keywords so "tooling"/"commander" and the "search" in "research" do not match, case-sensitive camelCase structural detection for host-tool naming, and a structural article/invocation-verb rule for capitalised names replacing a growing STOP_WORDS blocklist; quoted and unquoted invocation arms share one matcher so they cannot diverge.
- Feature gates: new surfaces (coding-knowledge Track A, conversational chat inspection, branch-scope overlay) are opt-in master-gated; off means byte-for-byte/byte-identical pre-feature behavior on every path. types.ts stays dependency-free and under a size ceiling (sibling modules re-exported so `./types.js` imports resolve). The graph edge cache is incrementally updated in place by the single writer (revalidated by file size for cross-process coherence) instead of nulling the 6 MB / 30k-edge cache and re-reading (2–4 s) on every write.
- Transcript windows: day views use a half-open UTC window; `readRecent(hours)` bounds work by the append invariant — mtime-anchored 256 KiB tail chunks with exact newline accounting, blank-line and epoch-sentinel edge cases pinned by tests; ownership digests trust a file's exact bytes via a per-verify parse cache.
- Script gates: the sealed memory-write envelope belt requires every production memory write to go through the sealed writeMemory envelope — package src roots are DISCOVERED, not hand-listed (the narrow scan missed unmigrated writers in plugin-openclaw, remnic-cli, and belief-ledger), and only method INVOCATIONS of writeMemory count (not declarations, comments, or strings). StorageManager.writeMemory persists content verbatim; callers that trim own trimming. Hook-grep source tests must include the core contract file. last_recall.json load rejects arrays and skips unsafe proto keys. The OpenClaw SDK surface check sources from the authoritative PLUGIN_HOOK_NAMES / OpenClawPluginApi declarations (excluding harness-internal events and non-plugin registrars), matching real declarations rather than re-exports, with the token heuristic kept only as a fallback for the missing dimension. Vocabulary agreement scans strip comments first (a commented-out member must not count) and keep comments as separators; scans fail closed on non-literal members. Package test scripts must not name deleted .ts files; typecheck scripts must exist where required.
- Pre-push gate: fast subset of CI's checks job (no build, type-check, or test run); base ref resolution tries the closest merge-base across the repo's several base refs, mirroring CI's ratchet/lifecycle inputs — a stale origin/main silently widens the changed-line set to unrelated main commits; spawn via process.execPath + resolved tsx entry, never bare npx (npm exposes npx.cmd on Windows, which shell:false spawnSync cannot execute — the whole gate died with ENOENT); --conditions=remnic-source matches CI source resolution.
- OKF export: shared bundle mechanics (frontmatter, publish, symlink guard, file write) live in one shared render module — one source of truth for every OKF exporter, with the namespace resolved once through the shared containment guard; staging happens inside the destination's parent, not the OS temp dir (publishBundle finishes with a rename, and rename across filesystems fails EXDEV when --out lives on a different mount than /tmp); regexes are shaped (`\S` capture boundaries disjoint from `\s+`) to avoid polynomial ReDoS on whitespace-heavy lines. who-knows always resolves and ACL-checks the effective namespace even when nominally unambiguous; input validation (including namespace ACL) is 400, backend faults are 5xx; attribution is per entity; multi-word names match as phrases, single words as tokens.
- Server/misc: port 0 is reserved for programmatic ephemeral-port use and a blank string is rejected explicitly (Number("") === 0); an event-loop lag monitor exists because daemon logs gave no starvation signal (COS-666 MCP timeouts); healthcheck auth/readiness answers are final — the legacy path is never probed. Work-layer block replacement uses indexOf, not backtracking-prone regex, with defensive handling of unterminated wrappers; slug trimming avoids ReDoS-prone anchored quantifiers; whitespace truncation is lazy (walk stops at budget) with a pragmatic East-Asian-Width Wide/Fullwidth subset; test randomness is deterministic so failures replay exactly.

## Consequences
See Decision: each rule pairs the constraint that forced it with its cost (extra reads and realpath work, explicit caller options, maintenance of shared helpers and gate regexes). Where topics were merged into this theme as nearest neighbours rather than standalone ADRs, that is noted here: the small single-site topics are absorbed into the theme whose files and failure modes they share.
