# HTTP routes stay thin and cacheable with body-over-query precedence, the server releases every timer and connection on shutdown, and operator-facing outputs redact user content

Status: accepted

## Context
Several surfaces (recall diagnostics, who_knows, location sync) would otherwise bloat the HTTP server with parsing logic that needs a booted server to test. The same parameter can arrive in the JSON body and a query parameter, and a stale URL must not silently override an explicit payload. Admin console routes would be dragged through the boundary migration wholesale even though the access-surface catalog treats the admin prefix as infrastructure. `server.close()` waits for every open request; extraction can run for minutes, and a restart once sat in listener closure until systemd's stop timeout killed the process. SSE connections hold heartbeat intervals, batch timers, and bus subscriptions, and idle chat sessions grow the JSONL store unbounded. Quarantine list output and shared benchmark reports can carry full user memory content.

## Decision
1. Routes are thin glue: parameter parsing and 400 mapping live in sibling modules (access-recall-diagnostics, who-knows, location/http-glue) so they are unit-testable without booting an HTTP server. xray explains the results a recall DID return; why explains the ones it did not; the query comes from `q` so GET stays cacheable. Bearer auth is enforced by the surrounding handler and namespace scope inside the service before the recall fires.
2. Body beats query: an explicit body field wins over a stale query parameter (disclosure depth, the asOf historical pin, tags including explicit `[]` to clear a filter, include_low_confidence). Invalid query values throw, never fall back silently (rule 51); empty query is rejected only when the body supplied no valid pin. Graph snapshot filters stay query params so the surface stays cacheable, invalid values yield a descriptive 400 (never a silent default), and validation runs up-front so the `invalid_since` error code survives instead of leaking a generic 500.
3. Admin console surfaces live under the admin prefix, which the access-surface catalog treats as infrastructure (no boundary migration; the static-completeness fitness test excludes the prefix); the routes still require bearer auth and delegate to the pure admin-surfaces module — the dashboard never re-resolves scope or re-lists namespaces. Admin promotion reports the actor from the authenticated principal, resolves the promotion source via the scope plan (not the default namespace), threads coding context into scope-profile plans, reports owner-private support-passports as not found, salvages legacy rows through sealed-envelope writes, and reports tombstone-blocked promotions as failed.
4. Live diagnostic routes are uncacheable: the no-store header is set BEFORE dispatch so the 403 path carries it too. A host-supplied pre-auth request handler runs after public UI assets and before the operator bearer gate, deciding whether it fully owns the response or falls through; `ctx.authorized` is computed there so operator-only endpoints can be implemented without owning token validation.
5. Peer contracts: the destructive full purge requires `?forget=true` AND `confirm=yes` in the body (absent confirmation yields 400); plain DELETE keeps the soft-delete behavior. Malformed percent-encoding in a peer id path segment maps to a 400 input error instead of silent garbage. Relay mission receipts share access-boundary schemas and the namespace-resolved storage contract; the browser receives an already-reduced snapshot and never scans general memories, recall logs, or production state.
6. Lifecycle: the chat-session TTL sweep runs once on startup plus a periodic unref'd hourly re-sweep (never blocks process exit), no-ops when chat is disabled, and clears any prior handle so a second start without an intervening stop cannot leak a dangling interval. Every SSE client registers cleanup callbacks — heartbeat intervals, batch timers, graph-bus subscriptions, chat-SSE disconnect cleanup — invoked before the HTTP server closes, with a belt-and-suspenders clear of state the callbacks miss; long-running SSE connections must not leak interval handles or EventEmitter listeners.
7. Shutdown: requests finish for a grace period, then connections are cut, which also aborts their request signals — in-flight recall/observe would otherwise hold server closure open until the service manager's timeout killed the process. A queued recall rejects on abort WITHOUT waiting for the holder to release (the old width-1 lock only re-checked the signal after acquiring); an in-flight holder is still held.
8. Quarantine: the operator list command projects records to metadata only — the raw payload is the original request and can carry full user memory text, which must not leak through an operator-facing list. Replay defaults to the principal the write was originally attributed to unless overridden, so authz resolves against that identity. The idempotency key derives stably from the parked file name, so a re-run after a failed delete dedupes to the same write server-side instead of duplicating the side effect (observe has no content dedupe); a key already present in the payload is preserved. Config resolution and reading happen inside the error boundary so a bad path or invalid JSON exits cleanly (exit 2) instead of hitting the global handler, and the store opens on the SAME resolved memoryDir the orchestrator dead-letters into — never a divergent resolve result. Dry runs never dead-letter, and a replay re-submit suppresses re-parking so a still-unwritable target propagates; parked records keep the FULL request (alias spelling included) so replay can re-report the coercion.
9. Public reports anonymize by allow-list: only allow-listed scorecard fields (a raw benchmark card can carry questions, answers, and recalled memory content), built-in benchmark ids (a user-defined id can be a client, project, or other sensitive name), allow-listed metric names, identifier-shaped metric keys, and finite numbers under those keys. A benchmark scorecard is NEVER copied verbatim.

## Consequences
Route parsing changes happen in sibling modules, keeping the server file thin. Body/query duplication must be resolved deliberately on every new parameter. Admin routes rely on bearer auth rather than registry validation. A grace period delays shutdown in exchange for not killing in-flight work. Quarantine replay depends on stable file-name-derived keys. Report output is limited to allow-listed shapes — anything new is dropped by default.
