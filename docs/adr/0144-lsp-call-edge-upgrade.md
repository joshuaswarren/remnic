# LSP call-edge upgrades are budgeted, provenance-aware, and reconcile conservatively

Status: accepted

## Context
Phase A (heuristic) indexing resolves many call sites; Phase B upgrades the remainder via language servers under a finite budget. Review found budget starvation, reconciliation retiring valid lsp edges that were never re-queried, mis-attributed callers for nested symbols, and server misconfiguration hiding as ordinary unresolved calls.

## Decision
- Budget: sites already resolved by Phase A — provenance matters: only HEURISTIC edges count — are memoized per caller FILE (duplicate qualified names across files must not leak resolutions) and excluded from LSP spend; member accesses are Phase A's deliberate skips and always remain candidates; a store predating resolvedCalleeNames conservatively spends budget rather than mis-retiring. Planned requests that never reached a server hand their budget back so one missing language cannot starve the remaining groups. Cross-file definition targets need their bytes loaded for position→offset conversion — without it cross-file upgrades stay unresolved. Queries run in UTF-8 byte space (span offsets are UTF-8 bytes; string indexOf returns UTF-16 units, so non-ASCII source skews string-index searches), positioned on the callee NAME not the call-expression start, bounded to the call-site span; the innermost (smallest) containing symbol owns the edge — first-match picks the outermost container for nested symbols. The workspace root must resolve absolute before building file:// URIs. Both reindex and LSP paths enforce the same symlink containment for tracked paths.
- Reconciliation: only files whose gathered sites ALL made it into the plan may reconcile — a budget-truncated file would otherwise retire valid lsp edges its omitted sites still assert. Files with skipped writes are excluded entirely (their asserted set is incomplete). Phase-A-filtered sites were NOT re-queried: when the store supports it, their current lsp edges are appended to the asserted set so stale cleanup retires genuinely stale edges without dropping preserved ones; otherwise skip reconcile for such files (conservative). Preservation keeps ONLY lsp edges that duplicate a current heuristic resolution (same src, same dst) — a dstName-only match would re-assert a removed member call's edge; a more-precise lsp edge may be retired in favor of its heuristic twin. lsp-provenance rows orphaned by a deleted call site are retired by this pass alone (the heuristic reindex deliberately excludes lsp rows from its stale-delete scope).
- Degradations are loud: candidates without a launch spec, missing/misconfigured servers, mid-run crashes (counts PLUS a degradation tag), and failed edge writes are recorded as diagnosable degradations so `codegraph_index` can distinguish "server absent" from "LSP found no definitions". Write contract: throw only when nothing persisted (ok:false — the executor's transactional contract holds because no state changed); a batch with skipped>0 already committed its resolvable edges in one transaction, so report truthfully (handed-off upgrades minus store-skipped) and surface the skip as a degradation, never a silent drop. Skips are tracked per FILE via upgrades' caller symbols (a SET — duplicate caller names span files) so a skip suppresses reconcile for exactly the affected file batch; a boolean flag went stale in exactly those cases. Client-facing lsp error detail is sanitized to class + errno; full errors live in server logs only.

## Consequences
- Conservative reconciliation leaves some stale edges in mixed files until a clean run; a rare lsp edge more precise than its heuristic twin is retired — the heuristic edge still represents the call.
