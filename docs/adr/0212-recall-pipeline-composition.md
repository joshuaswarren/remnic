# Recall composition runs four pipelines through one staged spine with byte-parity, MMR diversifies after rerank, and navigation/deep-recall are pure, seam-validated extensions

Status: accepted

## Context
Four recall pipelines (targeted-fact, response-guidance, event-order, and the recognition tier) each implemented their own dedup/score/threshold/sort pass, drifting in sort direction and tie-breaking. After the reranker orders candidates, a diverse final list still needs MMR re-selection. Feature modules (navigation, deep recall, composition) had to be extracted without growing grandfathered files past their ratchet ceilings, and every surface (CLI/HTTP/MCP) must render and validate the same way.

Scope note: This file merges several smaller themes — the unified pipeline spine and its byte-parity migration, MMR re-selection, reasoning-trace validation, recall navigation (#1956), deep recall (#2332), composition budgeting, and the module-extraction ratchet — into one composition family, as the chunk's ten-file limit requires.

## Decision
All four pipelines route dedup + score + threshold-filter + sort through the unified spine; each pipeline declares its divergences as config (notably the turn-index sort direction), and the spine's comparators match the pre-extraction implementations byte-for-byte. Per-tier intent classification stays with the caller. MMR re-selection runs after rerank: similarity is clamped to [0,1] (negative cosines count as 0), relevance is intentionally not min-max normalized (pass [0,1] scores through; all-zero scores give everyone 1 so diversity drives), ties break toward the earlier original position, candidates get unique identity keys so colliding ids do not merge, a budget larger than topN appends tail candidates, CJK text falls back to per-codepoint grouping after unicode-aware normalization, and diversity metrics summarize a small head of the list. Reasoning traces are a distinct category: a payload needs >=2 ordered steps plus a final answer everywhere (prompts, normalizer, schema) so one-step payloads cannot round-trip in from loose extraction, and step counting counts LINES carrying markers, never summed regex matches, keeping the false-positive-averse bias. Navigation (memory_expand/memory_traverse) accepts one allow-list covering both traversal vocabularies (including supersedes), sorts before deduplicating, treats a malformed stored entry as a real snapshot with empty servedIds while a bad REQUEST is a caller error (asymmetry is intentional), resolves neighbors through the SAME namespace storage, validates at the seam so every surface reports the same fault, and renders through one shared markdown module for CLI, MCP `rendered`, and HTTP. Deep recall is a pure REFINE/EXPAND/STOP stepper with injected policy: the budget check runs before the rewrite is inspected, a foreign id refuses the whole selection, the frontier is capped after every working-set change, and rewrite progress is compared on a case-folded, whitespace-collapsed key so pure case/spacing drift is not progress. Composition: when the full context exceeds budget, per-entry shallow first-line forms fit breadth-complete-but-shallow instead of a few deep entries; footer truncation is fixed overhead outside the degradation contract; a failed recall path composes an explicit missing-memory marker instead of an empty or silently truncated context, and recalled body text is fenced before entering model-visible context; cleaned request arguments accumulate in null-prototype objects. New feature modules are extracted into their own files so recall-internal/access-http stay under their structural ratchet ceilings; request-argument accumulation uses null-prototype objects; empty input to `runUnderDeadline`-style helpers is validated where the per-namespace path would otherwise never run.

## Consequences
Pipeline behaviour changes must go through the spine config, and byte-parity constrains refactors to observable-equality. MMR after rerank can reorder a reranker-preferred candidate out of the head. Extracted modules mean more files but bounded file sizes. A single-line heuristic detector remains a heuristic; true chain-of-thought detection is prompt-driven.
