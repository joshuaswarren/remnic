# Every recall section runs under a real deadline that degrades to a neutral value and never hangs or fails the recall

Status: accepted

## Context
Recall composes several optional sections (harmonic retrieval, QMD, native knowledge, rerank stages, trust stages). Enrichment sections originally only followed the parent abort signal, so their deadlineMs was a metric label: a slow section ran past the client's budget with nothing to cut it, and a never-resolving stage could hang the whole recall. Operators also need a per-attempt timing record whose shape is stable across surfaces, and the assembly order of QMD vs harmonic results affects when results become visible.

Scope note: This file merges the per-section QoS deadline theme with the recall-attempt timing contract and the QMD-before-harmonic ordering fix — all bounded-time, fail-open enrichment behaviour.

## Decision
Run every recall section under a genuine timer-based deadline (unref'd only when the caller is not awaiting it; deliberately NOT unref'd when the deadline is the awaited bound). A section's deadline is a fraction of the request's REMAINING budget, not the original ceiling, and a section that starts late must finish inside what is left. Timeout is a distinct recorded outcome from other errors: it means the section started, exceeded its deadline, and was degraded to its neutral value. A deadline fires by racing a tagged result wrapper (the caller's T must never be mistaken for the timeout marker), the losing work is aborted through a per-step AbortSignal — never the request-level signal, which alone may reject the whole recall — and its late settlement is swallowed so it is not an unhandled rejection. The assembly deadline fails open: when a stage never resolves, the deadline substitutes the pass-through fallback and the recall still settles. Ordering: the settled QMD candidate is formatted and published while harmonic is still parked; the move must not touch any deadline or default budget, and a numeric harmonicRetrieval timing proves the shared enrichment budget was neither shortened nor spent ahead of QMD. The per-attempt record (requestId, outcome, httpTotalMs, phases) is pushed once from recordRecallAttempt's finally, scoped per attempt via AsyncLocalStorage; the record's requestId IS the server-generated x-request-id. Serialization is an allowlist boundary: only known numeric phases and copied dimension strings reach the public shape — never a spread of the internal record. Phases that did not run are omitted; 0 means ran-and-measured-zero; durations parse as ms strings, statuses must be enum literals, absent/negative values floor to 0, and non-string ids drop — legacy emitters carry no phase-2 noise. The ring buffer is process-local; processStartedAt (from the process time origin, not module init) lets consumers detect restart/failover discontinuity. Timing-contract fields live only in the operator-gated timing record.

## Consequences
Sections that exceed their deadline return degraded neutral values, so a recall under load may silently omit enrichment. Timing consumers must tolerate missing phases and must not treat degraded sections as completed. Deadline timers keep the event loop alive while awaited.
