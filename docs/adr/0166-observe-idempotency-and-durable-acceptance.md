# Observe deduplicates by fingerprinted idempotency keys and accepts only after durable capture

Status: accepted

## Context
Observe is retried by transports and fans out to side effects of different durability: durable LCM archival, background extraction with a time budget, and per-session transcript persistence. Naive key dedup replayed responses whose payload, identity, or resolved scope had changed, or masked refusals as if a success had happened; cancellation could discard an already-durable capture; and failure diagnostics wanted stage timing without leaking message content.

## Decision
- A retried observe with the same idempotencyKey is deduplicated server-side: the batch is ingested once and identical retries replay the stored response (same contract as memory_store/suggestion_submit).
- The replay fingerprint folds the request body, the authenticated principal, and the RESOLVED write namespace (not the raw ambient context). Same key with a different body, a different principal (cross-identity replay), or a changed resolved scope — e.g. the session was rebound to another coding project between calls — is a CONFLICT, never a replay. A capacity refusal does not bind the key: a retry after capacity exists is a real miss; only a success bounds the key.
- Acceptance waits only for DURABLE capture. The LCM archival append is durable before observe returns (the queue holds only a session reference; summary DAGs build in the background, so the caller never blocks on inference). Extraction runs in the background: its promise is handed to the queued-extraction callback and tracked for force-flush, which parks on the pending extraction and reports its failure identity-preserved. The extraction budget is a DURATION from now, converted to an absolute deadline at the orchestrator — never read as an absolute epoch. Transcript persistence is best-effort and must never fail the observe.
- Cancellation stops extraction only: a capture whose preparation was cancelled is preserved (ingest still sees it, with nothing queued), and job tracking registers every job immediately while dropping cancelled preparation barriers.
- A replayed submission whose target is still unwritable propagates the rejection instead of re-parking it in quarantine; observe has no dry-run path.
- Observability logs carry noncontent stage timing only — durations in the failed and slow lines; failed requests always get phase attribution regardless of duration. Never message content, session keys, namespaces, or principals.

## Consequences
Retries are safe across identity and scope drift; observe latency is bounded by durable capture, not inference; extraction failures surface at flush time rather than accept time.
