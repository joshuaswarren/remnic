# Benchmarks run offline and deterministically: model components get labeled stand-ins, production logic is exercised as-is

Status: accepted

## Context
Benchmarks must run in CI and no-network environments and must be reproducible, but several components are inherently non-deterministic or remote: LLM judges, embedding models, extraction providers, and the assistant's agent. Naive substitutions corrupt measurements in their own way - a character-frequency embedder cannot distinguish English topic shifts; greedy nearest-first matching undercounts topic-shift true positives; a reimplemented ranker diverges silently from production; shared buffer state leaks between cases; telemetry ledgers double-count flush decisions.

Theme consolidation: this record merges 14 sweep themes into one decision family (121 origin records): assistant-agent-injection, assistant-latency-accounting, assistant-seed-generation, buffer-surprise-additive-flushes, buffer-surprise-benchmark-design, buffer-surprise-fixture-design, buffer-surprise-test-adapter, coding-graph-synthetic-generator, coding-recall-ranker-delegation, coding-recall-review-ranking-ordering, contradiction-heuristic-judge, span-mode-fake-provider-determinism, topic-shift-max-bipartite-matching, topic-shift-scalar-output.

## Decision
- Every benchmark completes without network. Where a model component exists, a deterministic stand-in replaces it and says so: the contradiction bench's heuristic judge is explicitly NOT a replacement for the real LLM judge and exists to measure structural correctness without an LLM; the assistant tier ships a structured, bounded fallback agent for smoke and no-network runs, with provider-backed agents injected via the config hook; extraction uses a fake provider that mirrors the production schema (on-mode emits the short frame, the token saving vs restatement) and keeps both variants on the same model and seed, with per-conversation salts so offset-error draws decorrelate instead of corrupting the same fact slot N times.
- The buffer-surprise embedder is a deterministic word-bag hash embedder (non-alphanumeric tokenization, stopword drop, djb2 bucketing, mild position awareness) so the surprise signal tracks vocabulary; the benchmark threshold sits above the package default because sparse vocabulary overlap in short English turns otherwise over-fires on ordinary follow-ups. Each case runs on a fresh on-disk buffer with a high count-flush bound and deliberately empty signal patterns, so only the surprise gate (or the count/timeout guards) can flush and the A/B delta stays clean; surprise-on never flushes less than surprise-off (additive-only invariant). Flush cadence averages intervals between CONSECUTIVE flushes only (0 or 1 flushes report 0; check flush_count before interpreting), flush decisions are read from the addTurn return value rather than the telemetry ledger, and storage is a minimal in-memory double for hermeticity. Topic-shift scoring pairs predictions with expected pivots via maximum bipartite matching (greedy nearest-first undercounts TP), and every score is a defined scalar - never NaN or undefined.
- Benchmarks never reimplement production logic: coding-recall delegates review-context ranking to the core's rankReviewCandidates so the verdict exercises the shipped code path - a parallel copy would hide production regressions. The smoke fixture pins exact score ties and the stable id tie-break, and orders developer-workflow cases first so capped quick runs still exercise workflow coverage.
- The coding-graph generator is a seeded mulberry32 synthetic-repo generator: all symbols are generated before cross-file edges are wired (no bias toward early files), and LOC is approximated from symbol spans for the LOC/s metric.
- Latency accounting sums per-seed wall-clock into task.latencyMs (mean per seed = one agent call + one judge call, the actual per-query unit of work) so multi-seed runs do not look artificially cheap, and run seeds come from one shared, validated helper.

## Consequences
Stand-in results support structural claims only, never published quality claims about the real components. Benchmark thresholds are benchmark-specific and must not be confused with package defaults. Any change to production ranking surfaces in the benchmark instead of hiding behind a local copy.
