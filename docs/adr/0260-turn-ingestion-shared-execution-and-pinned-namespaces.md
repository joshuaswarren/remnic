# Accepted captures run under a shared execution boundary with pinned namespaces resolved once and revalidated at execution

Status: accepted

## Context
Capture sessions can be pinned to an explicit namespace, and between trigger time and execution time config, bindings or abort state can change. Running mixed accepted scopes under one trigger or letting a stale claim execute writes to the wrong namespace or resurrects aborted work.

## Decision
Resolve the effective write namespace once per capture with explicit override pinned for the session, and revalidate at execution time against the ORIGINAL stored binding and current policy — if namespaces are now disabled or the binding changed, reject rather than silently retarget. Accepted captures share one execution boundary: triggers never drain mixed scopes together, pre-aborted signals are ignored by the buffered capture, a claim-backed task sees only the gate's buffer view, and task closures carry a discriminated source so they never capture the caller's mutable snapshot; re-check the claim at execution time. Namespace precedence is uniform everywhere: explicit override → session experience → default store. Passive correction writes go through the session-scoped ACL, and replay/import forces queue-only mode. Bulk imports use per-batch unique crypto-random session keys. Startup discovery is bounded so no readiness gate can hang forever.

## Consequences
A capture accepted under one namespace can still be refused at execution time; callers must handle the rejection rather than assume acceptance implies a write. Fail-open startup timeouts mean discovery may be incomplete rather than slow.
