# Capsule import, merge, fork, and export validate every path fail-closed before any filesystem mutation

Status: accepted

## Context
Capsules are untrusted archives; a single unchecked path can write outside the memory sandbox or clobber existing state. The cost is up-front full validation (one pass, one realpath per candidate) and rejection of ambiguous inputs instead of best-effort repair.

## Decision
All capsule import/merge/fork and training-export file collection run phase-1 validation over the whole archive before any write, and every path is both lexically and realpath-contained inside the memory root.

Rules:
- Phase 1 verifies checksums and validates ALL target paths before any mutation, so a corrupted or malicious archive cannot leave partial writes; per-record errors in phase 2 propagate and each write is atomic (mkdir + writeFile).
- Reject source paths containing `..` segments, absolute prefixes, or backslash separators (Windows path separators bypass a purely posix-split check), and re-check after posix-normalization (catches `subdir/../..`). Fork-mode rebase prefixes cannot be bypassed by traversal paths that `path.join` would silently collapse inside the root but outside the fork prefix.
- Containment is symlink-aware: the root is resolved once via realpath, the nearest existing ancestor of each target is resolved and verified inside the canonical root, and a target that already exists as a symlink is rejected via lstat (a symlinked parent passes the ancestor check but the write would escape). This applies to all modes, including fork mode. On macOS /tmp is a symlink, so lexical pre-checks against unresolved paths are skipped in favor of atomic realpath walk + containment.
- Duplicate normalized target paths (same after `.`-normalization or differing only in case on case-insensitive filesystems) are rejected up-front with both offending entries named; the lowercase-folded dedup key is unconditional rather than probing filesystem case-sensitivity at runtime. In merge, without this guard prefer-source silently overwrites and skip-conflicts/prefer-local misclassify the second entry as a local conflict.
- The manifest is the source of truth: records without manifest entries and entries without records are corruption. Unknown/missing schemaVersion tries V1 then V2 so hand-authored payloads get a clear zod error; import is V2-only and rejects V1 up-front. Unknown import modes are rejected at runtime before any write (no silent destructive fallback). Records are re-sorted by source path so imports are deterministic even for hand-edited archives.
- These helpers are security-critical (path-traversal and symlink-bypass guards); fixes must apply uniformly across import/merge/fork via the shared fs-utils helpers, not per-module copies. Export-side collection additionally refuses to descend into symlinked directories regardless of target, and rejects entries with nlink > 1 (a hard link is the file, so realpath alone returns an in-tree path — the extra link is a potential exfiltration vector).
- Before overwriting, the pre-write bytes are snapshotted; snapshot failure aborts that record's import rather than silently destroying history.

## Consequences
See Decision: each rule pairs the constraint that forced it with its cost (extra reads and realpath work, explicit caller options, maintenance of shared helpers and gate regexes). Where topics were merged into this theme as nearest neighbours rather than standalone ADRs, that is noted here: the small single-site topics are absorbed into the theme whose files and failure modes they share.
