# MemCorrect scores the correction protocol with pure, turn-isolated metrics and integrates third-party adapters faithfully

Status: accepted

## Context
The runner drives a MemCorrectSystemAdapter through the correction protocol (issue #1584 PR 2); every metric is a pure function over the probe log plus resolved scenarios, and the adapter interface is deliberately minimal and agnostic with half-open [start, end) windows. Measurements break in specific ways: probes that share a turn with an ingest underreport uptake_latency by one; a token-absence check misreads provenance-rich strings ("not old, now new") as stale; a resolved >= cap check double-counts boundary wins as censored; silently routing contract runs through the turn path mislabels the measurement. Third-party adapters (Letta, Mem0, Zep; issue #1727) must behave like a production integrator, and their remote state must reset cleanly between scenarios without swallowing real failures.

## Decision
- Exercise the real Correction Contract surface - plan plus confirmed apply through the same public access layer the MCP/HTTP correction tools use. When the planner yields nothing applicable or the adapter has no surface, fall back to delivering the correction as a user turn while preserving the seeded corpus timestamp, so temporal reasoning is evaluated against the scenario timeline.
- Split recalled context into ranked strings (token containment is scored per string, not over a monolithic blob). Force the background write paths to drain (the #1579 tombstone-chokepoint hooks: drain then contradiction scan); a no-op drain is allowed and simply surfaces as higher non_resurrection for that adapter.
- The append-everything baseline accepts a correction as just another user turn - no retire, no tombstone - so its non_resurrection must collapse toward 0 under re-ingest (the issue's sanity requirement); measured systems must not collapse.
- Stale recall: a retired token is a stale signal only if the corrected value is absent from the SAME string; a string citing both values is affirmative correction evidence and passes.
- Uptake probes get their own interaction turn: bump the turn counter before the recall probe and measure uptake_latency from the probe's own turn, so an anti-event ingest that is the first recall to reflect the correction cannot underreport by one. A success landing exactly at the cap (delta === cap) is resolved, not censored.
- Per-task directional scores include only metrics that are directional and applicable (collateral_delta is target-zero, not directional; scope_precision and reassertion are n/a for non-scoped / non-re-assertion scenarios); all metrics remain in the full bundle under details.metrics.memcorrect. The headline bundle is computed across the union of all scenario probe logs; the per-task mean view is kept separately in results.aggregates.
- Honor options.limit: 0 is a valid zero-item cap (never "all"), a non-number means no cap, negatives and fractions are rejected. Persisted config omits the live adapter instance so the result stays JSON-serializable (the label is captured as adapterMode).
- Third-party adapters mirror production integration: Mem0 receives the correction as a user turn (no contract API exists) and recalled block content is split per line so each fact is its own recalled string. Reset removes each session-to-agent mapping as its delete succeeds or is not-found (Letta), and deletes per exact user_id for every ingested session (Mem0's prefix does not match session-scoped ids); only HTTP 404/422 is swallowed - real failures (auth, server error, timeout) retain the mapping and rethrow so a broken clean-slate surfaces. Mem0 namespaces get a unique per-instance prefix so independent runs never share remote state. Fake fetches default to 404 so unmatched requests are loud; Zep's route table registers /memory before /sessions because the memory-add URL contains both substrings; the HTTP timeout path swallows the eventual AbortError and throws a clean Error.

## Consequences
A degraded or partial correction can never silently count as full uptake. Adapters without background drains score worse on non_resurrection by construction. Third-party reset requires tracking ingested session ids in-process. Swallowing only not-found means per-scenario isolation failures surface instead of scoring against stale remote data.
