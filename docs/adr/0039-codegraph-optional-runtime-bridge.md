# The optional codegraph engine is loaded dynamically, gated per tool, and degrades with clean tagged codes — never stub success

Status: accepted

## Context
`@remnic/coding-graph` is an optional peer dependency: memory-only installs must compile and run without it, yet every codegraph surface must behave identically whether the engine is present, missing, or broken. Earlier bugs reported stub success, double-resolved the specifier through a parallel loader, mis-keyed the store cache so configs read each other's SQLite handles, or leaked raw errors to clients.

## Decision
- Core owns the contract: engine and IR types live in `coding-graph-types.ts`; the optional package imports and implements them (no compile-time dependency; CI's fresh base install compiles). Loading uses a computed-specifier dynamic import through ONE shared loader (`optional-coding-graph.ts`) — one import, one cache, one contract check; a miss throws the canonical install hint, never a raw ERR_MODULE_NOT_FOUND. Failure policy: missing package → install hint; present-but-incompatible → a real `module_load_failed` diagnostic (not a misleading reinstall hint); present-but-broken (transitive dep, loader fault) → the underlying error on the load path, `null` on probes. Cache slots are strictly disjoint: a success cache never populated from failures, a shared in-flight probe promise, and no absent-result cache — loadFactory always attempts fresh after a failure so users see the real diagnostic. Casts at the loading boundary are justified only by runtime structural validation; specifier matching is boundary-guarded so `@remnic/coding-graph` does not match `@remnic/coding-graph-foo`. The runtime bridges to the engine via hand-written structural shapes mirroring its public API, narrowed without casts; the surfaces module is the single import boundary and re-exports the runtime helpers.
- Tool surfaces: runtime delegates are OPTIONAL — when absent, index/ingest/status/detect degrade with a clean tagged code instead of placeholder success; trace ingest persists HTTP_CALLS edges through the delegate (never `accepted: traces.length` without persisting); `list_projects` works without a store (config gate only, then a per-tool availability check) and returns an empty list rather than throwing. Gates: a config-only predicate plus a runtime-availability probe, fail-closed when config is unpopulated, ONE shared gate pair deduped across surfaces (every Track A surface resolves its gates here; booleans are strict-coerced so `=== true` is safe). The `codingKnowledge` config block is parsed in one core module; `lsp` server overrides are validated STRICTLY (rule 51): a malformed entry or misspelled language key must not silently fall through to the built-in default server, keys validate against the core-owned tier-1 list, numeric knobs are strictly parsed; the `lsp` key is spread conditionally so an absent key stays absent (an own `lsp: undefined` would change the pinned defaults shape and leak into serialized configs). The runtime narrows the loader-served module to its structural view, and the store cache returns the SAME handle for a `(principal, projectId)` pair, rebinding only per the rootless-reopen rule below. The tool switch is exhaustive over the tool-name union and the default branch fails closed; enum-ish params use allow-lists that reject loudly listing valid options; destructive operations are never defaulted to proceed; Cypher passthrough is rejected in favor of the structured query API; `search_code`'s kind filter is real (per-kind queries merged and deduped by nodeId — the store silently ignored a `kinds` array). Store failures arrive as `{ok:false, code}` and the surface MUST mirror `ok:false` so MCP/HTTP clients do not treat failures as successes. Tool names mirror the external codebase-memory-mcp surface; `codegraph_manage_adr` is a presentation of Track A's decision records — both routes call the same handler and write byte-identical records. Index composition pairs the deterministic architecture card with live graph stats. The surface layer carries no query logic — handlers are thin adapters.
- Store resolution and cache: project derivation lives in the shared `resolveStore` so every store-backed tool reopens the SAME DB. Cache keys are built from SANITIZED identifiers plus the resolved DB path: aliases sanitize to one handle (never two open handles on one SQLite file), differing `codegraphDbDir`/`memoryDir` get distinct entries, and deletion finds the live entry regardless of which raw projectId form opened it. A rootless cached store is closed and reopened when a later call supplies a repoRoot (root-bound operations need it); closeAll drains FIFO by monotonic order; deletion treats ENOENT as already-deleted (idempotent) and surfaces other errors as `deleted:false`. DB roots must be absolute; project/principal path segments are sanitized to flat filesystem-safe tokens (`_` fallback, leading dots stripped, surviving separators refused — defense-in-depth). The default coding git invoker is a FACTORY FUNCTION checked with typeof (an object check always failed, degrading index tools to runtime_unavailable). Reindex with omitted candidatePaths discovers tracked files via the git invoker instead of returning a noop; the LSP workspace root resolves absolute (relative roots make malformed file:// URIs); reindex/LSP paths enforce symlink containment; list degrades to empty on a relative root while open reports the tagged error; index status bodies stay opaque at the surface layer; client-facing errors are sanitized to class + errno (full detail recoverable from server logs, not the tool response).

## Consequences
- A missing optional engine means graph features are unavailable by design; fail-closed gating hides tools under partial config rather than half-running them. Store-cache keying by sanitized values means raw aliases intentionally share one handle.
