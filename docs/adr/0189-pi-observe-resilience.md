# Observe delivery is durable, idempotent, and budgeted so an unreachable daemon never breaks or delays a turn

Status: accepted

## Context
The pi plugin observes every turn over a daemon that can be down, slow, refusing, or version-skewed — the 2026-11-16 fleet incident saw a hook wait behind an unreachable extraction LLM while the host allowed only a fixed hook window. Captures must survive crashes and multi-pane processes; the daemon dedupes on idempotency keys hashed over the exact body; shutdown is teardown with no host handler window; and several pieces of state (breaker, cooldowns, pending hashes, namespace verdicts) are consulted from concurrent background chains.

The test-determinism, background-chain-settling, and budget-tuning notes were merged into this record as the nearest neighbour (they pin the behaviors above) to respect the ten-file limit.

## Decision
- Ambiguous failures and capacity refusals queue durably instead of dropping the turn. Entries keep their replay-nonce idempotency key bound to the EXACT body (bounding content only at enqueue would make the replay body differ from the live body and double-ingest), are destination-aware (a hash bound to another daemon never suppresses a live send here), and keep their original principal on replay rather than adopting the draining process's identity.
- One durable outbox per extension instance: the file is process-global, one instance serializes writes, entries carry their own session key, and a drain started by any session's successful contact replays every session's queued captures in queue order — before the background startup chain, so replay lands before the first turn's own observe.
- The outbox drain never blocks the live hook and never turns its own failures into failed live observes; live observes already answered 200 stay delivered even when a later replay is refused.
- A circuit breaker fast-skips observe/recall when the daemon is known-unreachable, with exponentially growing cooldowns; the breaker also trips on budget-exhausted retries and abort/timeouts classified as unreachable; ANY daemon answer marks the client reachable through the same production path; a generation guard keeps a late startup failure from wiping a fresh manual success.
- Shutdown replay bypasses the breaker (it is the last chance to observe before teardown) and uses the GENERAL request budget, not the per-turn budget.
- Live observe runs on per-turn hooks: retries, backoff sleeps, and multi-chunk sends all share ONE per-turn deadline — a sleep that would overshoot the remaining budget is skipped, and a retry is only worth starting with enough budget left. Recall retries transient connection failures under the general budget.
- Chunked observes account for every envelope byte (idempotency key, array commas) against the body cap, and truncation keeps only role plus a content marker, binary-searching the largest slice that fits — the marker itself is kept even when nothing else fits.
- Namespace preflight trusts only a fully-formed contract: `ok:true` requires a concrete namespace; `ok:false` requires a known reason AND concrete namespace; anything else is indeterminate and recorded as nothing. An authoritative verdict is recorded so it survives a restart, replacing the loud error and success-notify spam.
- A malformed tool catalog fails the listing rather than passing as a successful empty one; a listing retry needs at least a floor of remaining startup budget to be worth starting; the version check runs once in the background via MCP initialize's `serverInfo`.
- Test infrastructure notes: extension instances isolate their state maps so identical session keys still produce calls; landing order is controlled by holding recalls; stale chains are allowed to settle so negative assertions are not vacuous; budgets are tuned to the behavior under test (below the first backoff to exhaust retries, far above the turn budget to prove capping).

## Consequences
- No turn capture is lost to a down daemon, and no replay double-ingests; hook windows are respected by construction rather than by luck.
- Costs a durable queue file, breaker/cooldown state, and destination-aware bookkeeping; worst case an observe is deferred to shutdown or the next successful contact.
- The breaker can delay background work until cooldowns expire; shutdown remains the guaranteed final replay.
- Indeterminate preflight answers stay silent by design — diagnosability relies on the recorded verdicts once a well-formed answer arrives.
