# Corpus store integrity: scans fail closed on layout corruption, tolerate poisoned entries, run heavy work off-thread, and undo is all-or-nothing with hardened paths

Status: accepted

## Context
The daemon periodically censuses and scans a filesystem memory corpus that users (and attackers) can reshape: category dirs replaced by files, planted symlinks, hostile frontmatter, partial cancellations, and 100k+-file corpora that can starve the main thread. A census that silently publishes partial state would let a peer be certified converged against a broken deployment, and consolidation undo could archive or overwrite unrelated files via crafted `derived_from` paths.

## Decision
Scanning and census:
- Strict (census) scans fail closed: a category root that exists but is not a directory is a layout/backend failure — the namespace is omitted rather than published as healthy; non-strict (recall) stays best-effort and skips it. Enumeration failure reports `complete: false`, never an empty set that reads as an empty deployment; a never-created base dir (ENOENT) is a genuine empty corpus. Backend read failures propagate with errno; a vanished file reports null freshness.
- Symlinked or non-directory category dirs are skipped; poisoned entries are isolated so recursion still reaches valid nested memories. Cancellation is checked at directory boundaries and never swallowed by per-entry error handling — a signal that fired mid-read must not return a truncated list as the whole corpus.
- Heavy work leaves the main thread: scans run in a worker when available (with the inline fallback reported exactly once), stat calls are batched into fixed-size chunks so a bulk import cannot monopolize the shared threadpool, watermark parsing yields to the event loop every N paths, and background namespace scans are single-flight with a concurrency cap. The watermark digest buckets hot and cold tiers separately (same-day partitions must diverge the digest, fold together), validates dates as real calendar days, stamps `computedAt` AFTER the stat loop so no consumer sees a pre-scan timestamp, and shares one namespace-root resolver between /health and doctor so the surfaces cannot drift.
Consolidation undo and provenance:
- Undo is a two-pass plan + execute, all-or-nothing: plan validation (including dedupe by source path) precedes any write; once one write fails, all remaining writes are skipped so a target is never archived with partial source coverage; restores use exclusive create so concurrent recreation fails EEXIST instead of overwriting. Failures surface as fatal, with per-source skip reasons emitted before the error.
- Every path from on-disk frontmatter is treated as hostile: raw `..` segments rejected before canonicalization, dangling/self-referential symlinks rejected at every ancestor, absolute paths rejected (path.join would bypass the memoryDir guard), targets confined to active directories (archiving a sidecar snapshot would delete version history), and only regular files count as recovered/restorable. Restores bump the corpus sentinel (cache rescan) and request an entity reconcile pass for pre-migration legacy bytes.
- Provenance doctoring reads RAW frontmatter (not the lenient parser, which coerces unknown values to undefined and keeps the last duplicate key) so dropped tokens, truncated values, duplicate keys, and mixed lists surface as corruption; enumeration failures surface as a synthetic issue rather than throwing. `derived_from` accepts both `<path>:<version>` snapshots and bare ID-shaped entries, with the bare-ID bypass restricted to the pattern-reinforcement operator.
- The consolidation operator vocabulary stays dependency-free and narrowly gated for the LLM-driven pass; LLM output-length tolerance matches LCM parity.

## Consequences
Strict surfaces can report failure where a lenient scan would report a healthy-looking partial corpus — intentional. Undo's two-pass plan costs an extra validation pass and refuses partial recovery. Raw-frontmatter parsing duplicates some parser logic deliberately, because the lenient parser is exactly what hides corruption.

## Merged themes
`corpus-scan-worker-offloading`, `corpus-scan-dual-execution`, `corpus-read-explicit-cancellation`, `stat-batching-threadpool`, all `corpus-watermark-*` topics, and all `consolidation-*` / `derived-from-disambiguation` / `semantic-consolidation-llm-operator-gate` / `llm-output-token-tolerance-lcm-parity` records are merged here: they jointly express one rule — the on-disk store is untrusted, and every reader, census, and mutator must fail closed or stay all-or-nothing rather than publish partial state.
