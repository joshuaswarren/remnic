# Consolidation snapshots provenance per cluster, writes sealed envelopes, and fans out over the catalog-union namespace set

Status: accepted

## Context
Semantic consolidation rewrites memories across namespaces, and a crash or partial write could leave canonical content without its provenance, or the content-hash index pointing at stale entries. Maintenance jobs (pattern reinforcement, peer profiles) also run per-namespace with their own cadence gates.

## Decision
Snapshot each cluster's provenance before consolidation and write canonical content as a sealed envelope whose provenance travels atomically with it; archive safely rather than overwriting. Consolidation fans out over the catalog-union namespace set and records a per-namespace catalog write for every namespace it touches. The content-hash index is owned by the orchestrator's storage-scoped index — modules delegate removal, never edit it directly. Extensions are discovered once for all clusters; the Codex materialize post-hook fires on consolidation when configured; smart memoryMode routes candidates through the same durable extraction judge; pattern reinforcement respects its per-namespace cadence gate unless forced, and skips namespaces whose fanout is empty. Hygiene rotates first so bootstrap files stay small.

## Consequences
Consolidation cannot be a single global pass — the catalog union defines the work, so a namespace missing from the catalog is silently skipped. Sealed-envelope writes cost extra bytes per canonical memory.
