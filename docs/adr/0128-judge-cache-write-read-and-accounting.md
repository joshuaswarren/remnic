# Judge-cache writes never fail a task, reads never consume the judge's phase budget, and every accounting field reflects what actually happened

Status: accepted

## Context
Judge verdicts are cached to disk (issue #1573 PR1) so unchanged answers are free on re-runs. Making that safe surfaced a cluster of failure modes reviewed across PR #1591: a slow filesystem write consumed the judge-call phase timeout; concurrent benchmark iterations read a key while iteration N's fire-and-forget write was still pending; naive wrapping threw on class-style adapters with getter-only or frozen `judge` properties; flat or delimited cache keys collided; and cached re-runs looked as expensive as real judge passes while judgeModelCalls read zero.

Merged sweep themes: judge-cache-key-composition, judge-cache-concurrency, judge-cache-async-writes, judge-cache-write-policy, judge-cache-read-budget, judge-cache-hit-accounting, judge-call-accounting, judge-adapter-receiver-preservation, judge-wrapper-modelcalls-ordering, judge-wrapper-optional-methods.

## Decision
**Writes.** Cache writes are fire-and-forget at the miss site, chained onto a drainable `pendingWrites` promise so callers can drain between runs or at exit; failures increment `cacheWriteFailures` and never fail the task — the judge already produced a verdict. A verdict returned after the phase-timeout signal has aborted is NOT persisted: a later rerun must not find a "successful" verdict for a task that actually timed out.

**Read-your-writes.** The in-memory inflight entry is populated synchronously inside put(), before the first await, and get() checks it first — so an immediate get() finds the verdict even before the disk rename lands. The entry is cleared in a finally block only when it is still ours (one settled-safe promise object per key; a fresh `.catch()` per comparison would never match the identity check and would leak).

**Concurrency.** Writes to the same key are serialized per key so concurrent writers cannot race a temp-file rename into place; reads stay lock-free from disk (plus the inflight layer).

**Keys.** Each key field is hashed independently to a fixed 32-byte digest and the digests are concatenated and hashed — no delimiter is needed because each field contributes exactly 32 bytes, so fields containing the old `|` delimiter cannot reproduce the same byte stream. Binary verdicts key on a sha256 prefix of the prompt body: binary prompts are content-sensitive and two distinct same-length prompts collided on the old `binary:N` key.

**Accounting.** Cache hits return the stored score and model identity but ZERO the latency/token work-tracking fields — downstream harnesses sum them into totals, and a cached re-run must be observably free. `modelCalls` is incremented BEFORE the await so a thrown or timed-out call still registers as attempted traffic (a fully-cached run reads 0, a fully-failed run must not). A synthesized result from the `score()` fallback carries the real measured latency, not zero.

**Adapter wrapping.** The wrapper overrides ONLY `judge` and binds every other method to the original instance, so private state (`this.#data`) resolves; judge methods are invoked through member-access syntax so `this` is preserved for class methods and state-reading adapters. The wrapper never ADDS an optional method the underlying judge lacks (e.g. `scoreBinaryPrompt`): the harness detects support by property presence, and a synthesized method would score every binary item 0 instead of taking the generic-judge path. Distinct optional judge methods with sealed rubric contracts are preserved through the wrapper but not folded into the scalar-judge cache keyspace.

**Reads.** A cache read is raced against a small INDEPENDENT budget, never the merged phase-timeout signal: the prior version registered an abort listener that leaked one listener per call on hits, and a slow read inherited an already-aborted signal into the judge call, recording the deterministic fallback instead of letting the judge run. If the merged signal has already aborted, the read is treated as a miss; a slow or failed read is also a miss (counter incremented) and the listener is always removed once the read resolves or times out.

## Consequences
A crash between put() and rename leaves a cache miss — no partial state. Cache correctness now depends on identity-checked cleanup and synchronous population, which are easy to break in refactors. The wrapper allocates per judge call. Aborted phases leave no cached verdict, so reruns after a timeout pay full judge cost.
