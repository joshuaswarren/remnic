# Coding namespaces are sanitized deterministically with disambiguating hashes, combined with the principal base, and read/write paths must agree

Status: accepted

## Context
Project ids, branch names, and principals are untrusted strings that must become safe route namespaces. Naive sanitization is lossy (case, `/`, long-prefix truncation) and silently mixed recall and write state between distinct inputs. Rule 42 requires read and write paths to resolve identical namespaces; global fallback and LCM session keys had their own collision and forging hazards.

## Decision
- Sanitization is single-pass and linear (explicit loops over regexes CodeQL flags for polynomial backtracking); output must pass `isSafeRouteNamespace`. When sanitization actually changes the raw trimmed string — including case-only changes — append a deterministic hash of the raw input; when truncation occurs, append a hash suffix: distinct inputs must always map to distinct namespaces (`feat/x` vs `feat-x`, `Feature` vs `feature`, long-prefix collisions). Already-safe-lowercase and empty inputs get no hash so the common case stays readable. The shared FNV-1a 32-bit hash (Math.imul for correct wrap-around) is the one canonical implementation — reuse it, never re-hardcode.
- Scoping: branch scope exists only when project scope is on and a branch actually exists (null in detached HEAD) — there is no branch-only mode. Deliberate asymmetry: branch writes never leak up to project, but project-level memories remain visible as read fallbacks from any branch; with `globalFallback` on, the root namespace is also appended so globally useful memories surface everywhere (set false for strict project isolation). `projectScope=false` wins over `branchScope=true`. With namespacesEnabled off, the router maps every namespace to one directory — overlays would fake isolation — so coding mode degrades to unscoped behavior.
- Rule 42: read and write paths must agree bit-for-bit. The write-path namespace is `<principal>-project-<id>` (plus branch overlay and hash); the read path combines the same raw overlay with the same principal base through the shared resolver — never a replacement or a separately hardcoded join. The global fallback value is the empty-string sentinel: `combineNamespaces(principal, "")` returns the principal base unchanged; using a literal namespace name ("default") would produce "default-default" and miss the target. The orchestrator overlay is COMBINED with the principal base, so two principals in one repo get distinct namespaces.
- LCM keys: namespaced overlay keys are framed with the reserved U+001F (UNIT SEPARATOR) sentinel so the boundary is unambiguous and unforgeable — a namespaced key can never equal a raw default key (the namespace is guaranteed `\x1f`-free by `isSafeRouteNamespace`); default-store keys are escaped only if they would intrude on the overlay key-space. Tests derive expected keys through the SAME shared encoder production uses — never re-hardcode the join. Sessionless reads are a single archive-wide read (no `session_id` filter), never the literal "default" session id, which would silently drop every targeted/focused/explicit LCM section.

## Consequences
- Hash suffixes cost readability; the common already-safe inputs stay plain. Sessionless archive-wide reads can return cross-session sections by design.
