# Write-time dedup and skip gates are scoped to connector and namespace, run before chunking, and never suppress corrections

Status: accepted

## Context
Several gates decide at write time whether an incoming fact is a near-duplicate to skip: semantic dedup, the exact content-hash index, and the tombstone/dedup windows in explicit capture. Unscoped, these gates let one connector's or one namespace's content suppress another's legitimate write, let a skipped fact's hash permanently block future writes, or let long-content chunking bypass the skip decision entirely.

## Decision
A provenance-bearing candidate may be suppressed only by a near-duplicate from the SAME connector; a different or absent connector never suppresses, and unattributed candidates keep the original skip-on-any-match behavior. Semantic dedup lookups are scoped to the target namespace's path prefix (using the absolute storage dir when it is outside memoryDir), so cross-namespace or cross-tenant suppression cannot occur. A semantic skip must NOT register the skipped fact's content hash — an orphaned hash would permanently block legitimate writes after the neighbor is archived. The orchestrator runs contradiction detection and the semantic-skip check BEFORE the chunking branch, so chunked writes honour pendingSemanticSkip; when a contradiction triggers the supersede path, the chunked parent must carry `supersedes` and links in its frontmatter. Corrections in the "correction" category are always exempt from the semantic-skip fallback, and a detected contradiction blocks the skip even when contradictionAutoResolve=false (detection and resolution are separate flags). decideSemanticDedup fails open on lookup errors (writes proceed), treats zero configured candidates as disabled (no backend call), and distinguishes `no_candidates` (empty index) from genuine backend failure; the lookup is injected so callers get identical decisions. Explicit-capture dedup uses hash indexes only as an optimization: one lookup returns the MISS together with the authority behind it (never a stale MISS paired with authority from another moment), falls back to a full corpus scan when the index cannot answer, treats the same content from different connectors as distinct (empty strings normalized to undefined), and commits fact captures inside the per-dir dedup window with the tombstone lock taken INSIDE the window to preserve lock ordering. Validated capture input must compose: the composer's tag contract is enforced at validation time, and the review queue's machine-assembled tag list clamps to the 50-tag limit with the fixed review tags first, so a queued capture can never fail strict compose. Curation writes are a write boundary that records the caller's ORIGINAL ref and repairs entity resolution after write; per-statement corpus bumps happen at the write chokepoints. The merge suggested-neighbor is excluded from links so a memory never becomes its own neighbor.

## Consequences
More near-duplicate writes survive when connectors or namespaces differ — recall-side dedup must tolerate the extra copies. Contradiction detection must run even when auto-resolution is off, or contradictory facts are silently dropped. The scoped lookup costs a path-prefix-filtered query per write.
