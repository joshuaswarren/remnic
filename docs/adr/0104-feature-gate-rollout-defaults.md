# New capability gates default off until evidence justifies flipping them on

Status: accepted

## Context
Remnic ships many independent capabilities (recall stages, retrieval tiers, extraction gates, connectors, lifecycle machinery, local-LLM behaviors). Shipping each enabled would change recall output, add latency or LLM cost, or activate external integrations for existing deployments before the feature is benchmarked; shipping each disabled forever would strand finished infrastructure. Reviews repeatedly rejected fail-open defaults and silent opt-ins.
*(Merged ADR: the smallest gate/rollout themes that did not warrant separate files are recorded here - see the merged topics in the origin list.)*

## Decision
A new capability gate defaults to OFF (least-privileged) unless a specific decision records a justified flip. Off means byte-identical behavior to the pre-feature pipeline. Operators enable explicitly, and CLI-string forms must coerce correctly. Notable recorded exceptions to default-off, each evidence-backed: tombstones (non-resurrection invariant) default ON with `false` reserved for rollback; the Memory-Worth recall filter flipped ON after a bench (precision@5 0.00 to 0.60, zero regressions) with opt-out preserved; hot-memory caches, scope-aware invalidation, the GraphIndex edge cache, and the corpus-level recall-stage fallback default ON because they are performance-preserving in steady state; the lifecycle policy engine flipped ON once tier infrastructure had shipped for several releases; CJK/Thai segmentation defaults ON; the namespace catalog defaults ON but is inert unless namespaces are enabled. Bounds and thresholds are clamped or rejected at parse time (documented disable values like 0 stay 0), judge timeouts fail open rather than self-disabling, connectors ship disabled with malformed top-level shapes rejected loudly, and connector credentials are re-validated per sync pass so secret-store values can round-trip empty through the config layer.

## Consequences
Every new flag inherits the default-off burden of proof; flipping a default requires bench or ablation evidence recorded with the flip. Default-on caches need staleness bounds (the version sentinel does not cover external editor/git writes, so a TTL self-heals them). Small topics that did not warrant their own ADR (scope fallback, capture bounds, retry hardening, judge timeout, thinking suppression, correction config namespace, pattern-reinforcement clamps, trust weights, provenance characterization defaults) are merged into this ADR.
