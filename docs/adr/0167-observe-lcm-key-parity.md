# All LCM session keys flow through one shared namespaced encoding so writes, reads, and compaction agree

Status: accepted

## Context
Observe archives LCM transcripts under the effective overlay namespace, but recall readers and compaction flush/record derived keys from the raw session key or the base default namespace — an auto-scoped session archived under the overlay key while its reads and flushes used the base key, so turns just written were invisible to the same session. Separately, the LCM archive is keyed by session_id and NOT partitioned by namespace: a caller able to control the raw session key could forge a victim's overlay key string or a LIKE prefix and read another namespace's rows, and a sessionless, prefixless search was an archive-wide scan over every session_id that no namespace constraint could bound.

## Decision
- Every LCM session key — observe archival, recall reads, compaction flush/record, lcmSearch — is built by the SAME shared helper. Namespaced keys are sentinel-framed `<US><namespace><US><sessionKey>`; a single-store deployment keeps the raw sessionKey unchanged, and a missing sessionKey passes through for the downstream default fallback.
- The sentinel (U+001F) cannot occur in a route namespace or a legitimate session key, and a raw key that begins with it is escaped, so overlay and default key-spaces are provably disjoint: a caller-supplied raw default-store sessionKey can never reproduce, collide with, or LIKE-prefix-match an overlay key.
- Objective-state snapshots route to the scope plan's objective-state namespace: the effective write namespace for explicit-namespace and coding-overlay writes, the principal SELF base for an implicit write — not the general default-store write namespace.
- LCM reads honor READ authorization, not just parity: the read namespace/key set must be readable by the principal (the gate consults the configured recall namespaces), and a namespaceless principal without policy still lands on the default store when namespaces are disabled.
- When namespaces are enabled, an LCM search with no sessionKey and no sessionPrefix is SUPPRESSED regardless of explicit namespace or default readability — only single-store deployments keep the legitimate archive-wide scan. A same-session search resolves the SAME overlay key (and framed prefix) the write used.

## Consequences
One key-derivation implementation to keep in sync (the sentinel encoding is shared); callers cannot address overlay rows by string forgery; namespace deployments lose archive-wide LCM search and must scope by session or prefix.
