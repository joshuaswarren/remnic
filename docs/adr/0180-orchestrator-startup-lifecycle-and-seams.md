# Orchestrator startup is hang-guarded and epoch-fenced with deferred, union-covered QMD sync; coordinators hang off stable instance seams that Object.create test doubles can stub; operator config gates (per-dir TTLs, secure store, feature flags) are scoped per instance or per directory and fail closed where unsafe.

Status: accepted

## Context
Startup work raced lifecycle restarts and client aborts, boot-time sync missed cataloged dynamic namespaces, and helpers scattered across the instance made both refactors and prototype-based tests fragile.

## Decision
Startup and lifecycle: a watchdog guards startup awaits as a HANG guard, not a speed budget. The corpus-wide QMD update does not sit in the awaited ready path - deferredReady settles first, and startupSearchSync (the post-ready retry entry point) drives the update over the UNION of configured + cataloged namespaces, because a dynamic namespace written before a daemon restart exists only in the persisted catalog; a catalog read failure degrades to the configured set rather than breaking the sync (same tolerance as maintenance namespaces). Both startup call sites open read readiness without migration replay. Readiness never opens off an unverified ensure: an undeterminable collection check leaves retrieval fail-open but the gate closed, and a zero-result healthy warm-up on top does not count as warmed; remote/daemon-only modes report "skipped" as an explicit supported answer. Lifecycle epochs fence startup work: the first sync begins an epoch that resets the selfDeps gate fields (prototype fakes must declare them); a same-instance restart retires epoch A while A's shared ensure is in flight, the epoch-owned shared run survives one caller's abort for callers that joined it, and the aborted caller settles immediately instead of staying parked. Fresh lifecycle retirement aborts the controller forwarded to the namespace-check seam. Destroy order: abort signal first (every client and extraction task holds it), buffer flush, drain, then the destroyed flag, then post-drain removal persistence.

Seams and test doubles: issue #1526 moved helpers to coordinators (graph recall, section budgeting, recall assembly, search pipeline, turn ingestion, introspection, init, persistence index, workspace ops, namespace fanout) with thin delegation keeping call sites stable and seams overridable per instance; helpers are re-exported for existing importers. Coordinator services construct against the selfDeps proxy so instance overrides apply; lazy accessors tolerate Object.create(Orchestrator.prototype) doubles that skip the constructor (report "no budget" rather than throwing), and session-binding maps get defensive init. Delegation wrappers route through `this` so root-test stubs hold. Ad-hoc namespace resolution delegates to the scope-module resolver so the ratchet no longer counts that site.

Config and gating: hot-memories escape hatch and scope-invalidation gates are registered per directory (parent and namespace children; cold roots registered before construction, since their TTL resolves via the per-dir map and an unregistered root would inherit another orchestrator's process-wide TTL; OKF conformance inherits via ancestor walk). Secure store, when enabled, marks the store required so writes throw SecureStoreLockedError instead of silently falling back to plaintext when locked. LCM routes to the fast tier explicitly (configured fast persona, else taskModelChain) to avoid an expensive gateway default. Plugin mode gates on localLlmEnabled alone. Pattern-reinforcement `force` relaxes only the cadence floor - a disabled feature stays disabled (cadence gate is keyed per namespace so one tenant's run doesn't suppress another's; default tenant uses the empty-string key). Faithfulness counters, workspace selections, coding-agent context, and peer registries are per-instance/per-session state with a single per-instance ordering domain for X-ray snapshots; the legacy string-returning recall surface keeps its soft-abort behaviour (resolve empty string, never reject) inside that domain. Contradiction auto-resolve completes only after the new write and its tombstone settle. Episode sets exclude pending_review fact ids. The provenance principal is pinned and forwarded to runExtraction. Tests use frozen/injected clocks where timing assertions must be exact.

## Consequences
Epoch fencing requires every prototype fake to declare the gate fields; deferred sync means recall readiness is not corpus-fresh at ready time; per-dir registration is load-bearing for TTL isolation and easy to omit for new roots; seam stability constrains how coordinators can be reshaped without breaking stubs.
