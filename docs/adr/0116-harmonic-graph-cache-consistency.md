# The harmonic graph cache is singleflight, validity-deadline-bounded, and defensive at every boundary

Status: accepted

## Context
Recall builds a projected graph over the memory corpus; builds are expensive, the corpus changes underneath them (writes, out-of-band edits, invalid_at passing), and source paths and shared cache state are attack or corruption surfaces.

## Decision
One build runs per cache key at a time; every recall on a miss waits for the same build. A caller exceeding the wait budget leaves WITHOUT the graph, but the build it abandoned keeps running and populates the cache so the next recall does not pay the wait again — without this bound a write storm keeps every recall waiting for a rebuild. The build owns its own abort controller, not any caller's signal; a caller's abort ends only its own wait, and a cache hit must not mask an aborted signal. A build that finished before storing must not store into a cleared/replaced cache key. Cache entries freeze records and nested values so callers cannot corrupt the shared cache (freeze terminates on cycles). The corpus stamp is read BEFORE the build so a write landing mid-build leaves the entry stale; beyond the TTL a stamp-unchanged graph is still served while a refresh runs behind it, and a failed background refresh retries at most once per TTL. Each entry carries a validity deadline: the first instant any source memory's invalid_at passes the projection is wrong without any write, so the entry ends there regardless of freshness; ineligible sources drop out whatever their invalid_at, and with temporalExpiredInInjection the filter is off so no invalid_at ages the graph. All graph readers project nodes and anchors against the namespace's current active memories (one projection contract). Source resolution is path-safe: ids reach SQL as bound parameters, join into paths only as single safe segments, retain the realpath containment check in direct and cached probes, legacy opaque ids use the full scan, non-matching parses drop within each batch so a walk does not hold every MemoryFile, the cache publishes atomically last-writer-wins (contention repeats a walk, never loses sources), and validation fails closed when the authorized memory directory is unreadable while source-less nodes stay eligible. Node and anchor token indexes key by position (ids are unique only per record day / anchorType), remembered across recalls on cache hits; artifact reads fail open so invalid artifacts stay visible via status tooling; newest-first source order keeps projected titles on the most recent facts with ascending-id fallback. The index has a max age beyond which incremental dating stops being cheap; unprojected candidates probe only recall-corpus categories by exact path (questions/ and artifacts/ are never sources).

## Consequences
Validity deadlines can expire a freshly built cache and force a rebuild; the wait budget trades one caller's recall quality for system-wide latency under write storms.
