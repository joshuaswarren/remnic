# The SQLite projection accelerates browse but every cache layer is invalidated through one chokepoint, keyed by secure-store key identity, and a broken projection falls back to the full corpus loudly

Status: accepted

## Context
Multiple caches (hot memories, derived episode/rule views, QMD search/recall, archive) sit in front of the corpus. Out-of-band writers (capsule import, governance restore, review, page revert, binary redirect) bypass the mutation paths that invalidate caches, leaving warm processes serving pre-write results for a full TTL (issue #1902). Shared per-baseDir cache slots risked leaking plaintext across secure-store key boundaries; a present-but-unopenable SQLite projection collapsed into the same silent null as a missing file, hiding wrong-ABI builds behind 17-27s full-corpus scans on every memory list (issues #1829, #1848).

## Decision
(1) Every cache layer invalidates through the single scope-aware chokepoint; layers declare mutation scopes via evictOn; out-of-band writers bump the corpus-version sentinel, which (a) drops in-flight readAllMemories scans started before the write and (b) evicts the TTL-keyed derived and QMD caches the sentinel cannot self-heal. (2) A single-file write keeps the hot-memories layer warm (patched and re-keyed in place) and evicts only derived and global views; the entities layer is keyed on memory-status, which plain create/content writes deliberately do not bump; the archive layer is version-keyed with no age TTL. (3) Cache entries carry the secure-store keyId that decrypted them; a manager only reads/mutates entries matching its own key identity, so a locked or differently-keyed instance never sees another's plaintext. (4) Hot entries are evicted when their own TTL elapses; QMD search results carry a short 60s TTL; the entity-cache schema key has one normalization point. (5) Browse visibility follows one recall-corpus rule shared by every code path: derived/non-recall stores are invisible-by-design (resolve as not_found, indistinguishable from missing; find cannot surface them even by wildcard); namespace ACLs fail closed (no principal or a non-authorized principal throws); find matches name/path, orders by code point, and tree depth is rooted at the queried store; the browse index is rebuilt per call from readAllMemories (O(corpus) at agent cadence is accepted). (6) A MISSING projection is a normal cold-install fallback (null triggers the full-corpus scan and the scan must still hold every memory); a PRESENT-but-unopenable file is a real failure: browse still returns null (fallback preserved) but emits a distinct, rate-limited (5-min dedup), path-free warning so wrong-ABI builds no longer collapse into silence. (7) Projection health requires more than a file that opens: verify memory_current exists, answers SELECT 1, AND carries the columns the browse reader SELECTs - a stale/half-built table is present-but-invalid so doctor hints a rebuild instead of a false-clean bill of health; verify/rebuild read disk fresh, bypassing stale in-process caches. (8) Projection row precedence is authoritative by tier (hot over cold over archive) with path tiebreaks so readdir order never decides; scoped rebuilds source native-knowledge and governance rows from the persisted snapshots, never the prior projection. (9) Projection rebuilds manage heap deliberately: raw file text is dropped unless retainRaw is set, preview copies detach from the source string, and document bodies are dropped before the ledger scan so peak heap is the larger of corpus and timeline, not both.

## Consequences
Scope-aware invalidation depends on layers declaring correct scopes; per-call index rebuilds trade CPU for simplicity; path-free error details hide absolute paths from operators by design (rule 11 / stack-trace exposure); strict schema validation flags legacy projections for rebuild.
