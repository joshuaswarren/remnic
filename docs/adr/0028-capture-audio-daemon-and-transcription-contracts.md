# The audio capture daemon is identity-verified and loopback-only, honors caller cancellation, and derives stable idempotency keys from content so replays never double-commit

Status: accepted

## Context
The audio capture daemon transcribes through a native helper, spools transcripts, and must survive restarts, replays, symlinks, and concurrent cleanup without corrupting state or leaking paths — and speaker identity must survive restarts.

## Decision
**Daemon control and pid ownership.** The pid file is an atomic, identity-bearing record. A daemon is signalable only when the record's instanceId/pid verifies against the process answering the health endpoint: never signal an unverified pid, never reclaim before a safe stop, and a verified mismatch refuses `--force`'s override; an unverifiable identity (health unreachable, no recorded instance id — guards against PID reuse) refuses to signal unless forced. A late shutdown removes the pid file only when it still records that pid, so a newer daemon's record survives. Startup writes pid + effective binding first; the child adds instanceId only after the HTTP server is listening — `start` does not report success before the child actually binds, and a readiness timeout terminates the child and fails loudly so automation never observes a false success. If the detached child was scheduled first and already published its own full ready record, a provisional write must not clobber it; a stale record for a different pid is reclaimed. If pid persistence fails, the child is killed so it is never orphaned unrecorded. The health URL prefers the effective binding persisted in the pid record. Live capture starts BEFORE binding so the reported `capturing` reflects whether the helper actually started — a missing helper degrades honestly and the daemon still serves the spool.

**Replay and shutdown ordering.** Replay ingestion runs as a supervised task AFTER readiness, and start yields so the caller returns to serving before the synchronous ingest; replay volume or failure never delays or fails readiness and never kills the daemon. Shutdown cancels and drains replay (bounded: ingestion stops at the next commit-batch boundary) BEFORE closing the spool, so no ingestion write can hit a closed database. A failed shutdown flush is surfaced — chunks still in memory with raw audio still on disk is a recoverable state, and swallowing the error made it look like a clean exit.

**Capture pipeline contracts.** The daemon captures into an owner-only directory (transcript spool + bearer token live there). Helper-supplied paths are resolved against symlinks and rejected if they escape the raw capture dir BEFORE transcription reads them; deletes never target anything outside the raw dir, falling back to the lexical path when the symlink target does not exist yet. Config-layer coercion throws on unrecognized values — never silently defaults. Request-input validation raises a typed input error the HTTP surface maps consistently. The chunk callback seam never throws — failures route to the error callback. The CLI parses flags anywhere (global flags may precede the subcommand; first non-flag token is the command), normalizes bracketed IPv6 authorities to the bare form so the loopback check and bind agree, and surfaces operator-safe error descriptions (never foreign message text or paths); status output strips filesystem paths before they reach spool meta or health.

**Idempotency.** Chunk identity derives purely from the WAV path (never a freshly generated conversation id, so replays reuse keys); per-segment keys derive from segment CONTENT — bounds and text — not position; a whole-transcript marker key guards the chunk's manifest because a segment count is too weak (a replay returning the same count with different text must not pass). The latest segment end never precedes the chunk's own end.

**Cross-channel ordering.** A transcribed chunk is HELD in a bounded reorder window until the other channel's watermark passes it, so a delayed system chunk still assembles into its conversation; only the both-channels mode interleaves — a single channel is already ordered and buffering would add latency and widen the crash window for nothing.

**Speaker identity.** Diarization activates only with an embedder wired; the clusterer seeds from persisted clusters so speaker ids survive restarts. Snapshots persist as the daemon/library shape directly (field names must line up or the count silently stores 0); seeding a fresh clusterer from persisted rows keeps sample counts so established speakers are not treated as fresh. Restoring a snapshot replaces every cluster and rolls back on assignment failure (assignment mutates in place). Example replacement swaps the example most similar to the incoming one, keeping the cluster diverse across the speaker's range. Self-enrollment builds the canonical cluster through the diarizer so the stored shape matches what live diarization seeds from, and reports what is actually stored after an upsert so a relabel never falsely claims no embedding exists. The wearables speaker registry owns naming; the connector supplies only the stable per-source key.

**Files, errors, resilience.** Deletion-time ENOENT is disambiguated with lstat: a dangling symlink occupies the path and is cleared, not silently treated as absent (a later rename/link would fail on it). The janitor skips a chunk that vanishes between readdir and rm instead of aborting the run — a concurrent capture/cleanup already pruned it. Model downloads land via atomic same-directory rename, which works without hard-link support (FAT32/exFAT, network mounts). The native-helper backoff resets on a valid chunk — a valid chunk proves the helper healthy. Connector probes are bounded so a wedged daemon reports unreachable instead of hanging; caller cancellation is honored and never mislabeled as a daemon fault; timeout, offline daemon, or malformed baseUrl all classify consistently as unreachable (never a raw TypeError). The bearer token is auto-generated (256-bit), stored 0600, and read only for a loopback base URL; binding checks treat non-loopback hosts as unreachable from other machines. Server errors after bind are handled by a persistent sanitized handler so a socket error cannot crash the daemon as an unhandled event. The optional VAD peer is imported with a computed specifier (kept out of static analysis), with ERR_MODULE_NOT_FOUND reported as absent and installed-but-unusable reported distinctly. The bundled output must keep the `node:` sqlite prefix — dropping it fails at daemon start, so a distribution test asserts it. Tests use named element access and assertion-signature-safe comparisons under noUncheckedIndexedAccess, and exercise cross-channel dedup with distinct non-overlapping spans on ONE processor instance so resume state is real.

## Consequences
Strict pid identity means stop can refuse when identity cannot be proven — automation must use explicit force knowingly. Held chunks add bounded latency in both-channel mode. Content-derived keys mean identical segment text at identical bounds dedupes across replays by design; genuinely repeated content requires the transcript marker to disambiguate.
