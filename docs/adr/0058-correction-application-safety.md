# Corrections are applied only through storage chokepoints, blocked by tombstones, atomically rescoped, and never leak the secrets they redact

Status: accepted

## Context
The correction subsystem rewrites memories from LLM-drafted plans. Corrections can therefore corrupt memory state in many ways: superseding to a tombstoned (pending_review) replacement, duplicating attributes on rescope, writing stale content, racing the index, or — worst — persisting verbatim the very secret a never-store/redaction correction was asked to withhold. Config plumbing and versioning must reuse existing machinery rather than fork it.

## Decision
- All memory mutation routes through `writeMemory`, the single storage chokepoint where catalog/dedup/reindex and tombstone blocking fire. Corrections are themselves memories, and a correction-category memory capturing plan + outcome is the audit trail.
- Sealed-envelope writes (issue #1989): LLM- or plan-derived content composes in SALVAGE mode — one malformed optional field cannot make a correction inapplicable; drops are warn-logged. But identity fields are fatal: an explicit unrecognized category is a contract error (defaulting only when ABSENT). System-built audit records compose strictly — an invalid audit record is a code bug.
- Tombstones block resurrection: content matching a tombstone lands `pending_review`; a merge or rescope whose replacement is tombstone-blocked must FAIL cleanly rather than retire the only active copies behind review. The executor writes the tombstone set BEFORE retiring the source (a null `appendTombstone` while tombstones are enabled means persistence failed and the retire must not proceed); once one tombstone is durable the whole set finishes even on caller abort; a partially written multi-key set is rolled back best-effort (a dangling tombstone is the safer failure mode).
- One tombstone per derived supersession key (mirroring temporal-supersession/forget/pattern-reinforcement), each carrying the canonical contentHash, so paraphrased re-observations placing an attribute at a different key position are still blocked; contentHash is recomputed from the patched body and hashed over the ORIGINAL unsuffixed body.
- Rescoping is atomic write-then-archive within the AUTHORIZED namespace scope (never just the default namespace), never copies stale source content, strips the `[Attributes: …]` suffix before rewriting (so it is not doubled), and compensates by archiving the destination if the source archive fails — no duplicate ACTIVE facts. Post-write QMD reindex propagation is best-effort (a warning, never a failed action) and keyed by the touched namespace's storage.
- Candidate eligibility is lifecycle-aware (`stable`-ish states only); correction keyword search deliberately tokenizes and scores by overlap (no embedding dependency) — locating candidates is the planner's job, ranking is recall's.
- Correction config fields are owned by `parseConfig` (parsed booleans win so operator config takes effect; loose reads remain only as test fallbacks). The classify step accepts only one schema-valid, verbatim response — never an arbitrary example or fence-rewritten patch.
- Versioned previews reuse page-versioning (no fork); never-store/redaction requests and their error text are withheld verbatim from durable audit memories.

## Consequences
Corrections can fail loudly late (at chokepoint checks) rather than silently corrupt; the executor must treat tombstone-blocked outcomes as failures. Salvage mode trades strictness for applicability on plan-derived fields only — identity and audit fields stay strict. Secret-withholding means some error messages are intentionally truncated.

## Merged themes
All `correction-*` topics (tombstone-blocking, sealed-envelope, supersession-keys, rescope namespace/atomicity, config-parsing, keyword-search, attributes-suffix, page-versioning-reuse, storage-chokepoints, secret-withholding, redaction-rule-idempotency — where re-registering a pattern overwrites via slug+hash instead of colliding — index-propagation, content-hash, classify-parse-policy, audit-trail, access-wiring-design, candidate-eligibility) form one decision family and are recorded together.
