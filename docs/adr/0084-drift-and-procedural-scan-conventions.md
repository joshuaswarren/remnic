# Preference-drift and procedure/skill maintenance scans are deterministic, status-inclusion-set driven, zero-respecting, and non-destructive: stamps and salvaged writes never destroy live state, and any write bypassing the extraction pipeline bumps the corpus version.

Status: accepted

## Context
These subsystems rank, stamp, merge, retire, and project memories outside the normal extraction write path, so undamped conventions would make results depend on iteration order, let a misconfigured cap flood hosts, or leave hot caches serving pre-write frontmatter.

## Decision
Shared conventions across drift scan, procedure library maintenance, and skill projection:

- Candidate sets are stated as INCLUSION sets of statuses (only active procedures are merge/retire candidates; imported skills stay pending_review unconditionally and only the active set is ever projected), never exclusion lists. Archived files are scanned where operators expect counts (procedure stats scan live + archive, deduping by id against the mid-archive race).
- Zero is the documented disable value and must survive as zero everywhere (scan intervals, projection caps) - never clamped up; stalePenalty 1 is the no-op and 0 is rejected as a silent delete-from-recall.
- Ordering is deterministic: oldest-first with stable id tiebreak so caps are fair, evidence order preserved over Map iteration, report flags in evaluation order, readdir order never relied upon, sort comparators guard NaN timestamps (invalid = oldest) so the comparator contract holds.
- Time windows are half-open [start, now): a memory observed exactly at the window start counts, one at the run instant does not; the same rule bounds writesLast7Days. Repair flags mean nothing on an empty lookback window.
- Bypass writes bump the corpus: frontmatter stamps skip the extraction pipeline, so the shared corpus version is bumped out of band (metadata-only bumps must not move the mention epoch) or hot recall caches keep serving pre-stamp state.
- Salvage writes: machine-generated or externally authored content composes with salvage and warn-logs dropped optional fields instead of failing; replacement text goes through the sealed-envelope pattern, and a tombstone-blocked replacement never supersedes the old preference (never destroy old state before the new state is viable). Drift replacements use `update` semantics - restate one claim, never merge two. A drift finding is honestly recorded as a `contradicts` review verdict; drift stamps live beside their codec, an unrecognized verdict round-trips to undefined, and writing one is a caller bug that surfaces. Corroborated is deliberately not a persisted verdict - it is derived provenance stamped after the fact. Neutral passes keep input order, and the drift stage is pure ranking/annotation, free of I/O. Trajectory id lists are capped to envelope attribute-value limits AT an id boundary so salvage drops the tail, never all provenance. Projection strips the machine "[Attributes: ...]" footer so it cannot be absorbed into a step on re-parse, and fence parsing scans lines rather than using a lazy fence regex.

## Consequences
Salvage silently drops cosmetic fields (warn-logged); pending-only projection means imported skills need an explicit promotion; the corpus-bump requirement applies to every future bypass write, which is easy to forget.
