# Identical concurrent recalls coalesce onto one shared pipeline with atomic cross-namespace budget admission

Status: accepted

## Context
Recall is the most expensive read path, and identical requests for one principal arrive concurrently (transport retries, multi-agent hosts, keyed and unkeyed callers). Without coordination each arrival spawned its own pipeline, reserved its own cross-namespace budget event, and concurrent callers could each pass a stale budget peek and collectively overrun the hard limit. Abort timing made it worse: a caller disconnecting mid-pipeline either ran work nobody wanted or leaked its reservation.

## Decision
- Identical concurrent recalls for one principal coalesce onto ONE shared pipeline (single flight) under a per-principal concurrency slot. The flight key represents the recall WORK (query + options that shape the result), never the idempotency key, so retries that arrive with distinct per-request idempotency keys still coalesce; every keyed caller persists the shared result under its own key.
- The leader registers the flight synchronously before any await, so later identical arrivals coalesce; unkeyed followers join WITHOUT consuming a concurrency slot. Keyed callers never take the unkeyed fast path: they enter the idempotency guard FIRST (stored response replays; reused key with a different payload is a conflict), then join a live flight on a store miss.
- A caller that has already disconnected is rejected at admission; it never starts, joins, reserves, or persists work. A flight whose callers all aborted while still queued is cancelled; once a slot is granted and the abort re-check passes, a keyed flight commits and persists even if callers disconnect.
- A keyed flight carries a persistence gate: followers (and the leader) report success only after the leader's idempotency put settles, and a failed put rejects them with the leader's exact error — no phantom success. The flight stays registered until the gate settles; unkeyed flights unregister as soon as their last consumer finishes. Keyed followers waiting on that gate race it with their own abort signal and are never stored on by a disconnected caller.
- Cross-namespace budget: peek all effective namespaces for cross-namespace-ness WITHOUT recording, normalize the recall mode BEFORE any budget accounting (no_recall/invalid modes never consume budget), then reserve ATOMICALLY at admission in the same synchronous turn as the peek, so the budget's project-and-push denies the Nth concurrent cross-namespace recall before its pipeline runs.
- A reservation is released exactly once, by token, on ANY post-reservation failure or abort — pipeline failure, response-clone failure, idempotency-put failure, late abort after the result resolved. A persisted keyed recall's budget event legitimately stands; a discarded unkeyed result releases its reservation. The leader's own event is reserved inside the pipeline and never recorded twice; a coalesced follower records its OWN per-caller event, and the server-only reservation token (and principal id) never reaches responses or caches. Uncontended acquires report no queue wait rather than counting scheduling jitter.

## Consequences
Contention no longer multiplies work or quota spend, but the coordinator owns refcount, persistence-gate, and reservation-release subtleties; a keyed caller can block on another caller's persistence (bounded by its own abort signal); single-flight-disabled deployments keep per-request execution under plain slots.
