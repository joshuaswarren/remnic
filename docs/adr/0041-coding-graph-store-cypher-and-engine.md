# The coding-graph store fails loud at its boundaries with tagged failures, and the Cypher layer is a strictly validated read-only subset that never silently drops results

Status: accepted

## Context
The coding-graph package pairs a SQLite graph store (two-pass delete + reinsert write pipeline, issues #1552/#1891/#1914) with an openCypher read subset. Review found the failure modes that matter for a code-intelligence database: error-vs-empty conflation (SQLITE_BUSY indistinguishable from "key absent"), close() racing in-flight writes, FK cascades silently no-opping, relative repoRoots slicing the wrong file, duplicate paths corrupting the edge pass, path caps silently truncating results, and BFS compilation dropping endpoints reachable only at longer paths (issue #1650).

## Decision
**Store.**
- Writes use a two-pass, single-batch, single-transaction delete + reinsert per file. Duplicate paths within one batch fail loud — pass 2 would delete the first entry's edges when the second entry's edge pass runs. The canonical-path check runs BEFORE the duplicate check: `./src/a.ts`, `src/a.ts`, backslash and absolute spellings of the same file must collapse to one file row or later canonical ingests cannot match or prune the stale duplicates.
- repoRoot, when provided, must be absolute and is validated at open() with a thrown, name-specific error — a relative root resolves against the process CWD and snippet slicing would silently hit the wrong file. It stays optional so snippet-less callers can open with just a DB path.
- Read primitives return tagged failures, never empty-on-error: SQLITE_BUSY must stay distinguishable from "key absent" / "empty index" / "no co-change edges", because the reindex executor's prune and head-advance decisions depend on the difference. A locked or corrupt DB surfacing out of a queued callback is converted to the tagged db_error, matching the advertised result types.
- close() is a serialized flush barrier: NEW writes are blocked before draining, an in-flight drain is shared (a second close() awaits the same completion instead of resolving early), so a caller that deletes/reopens the DB after await close() can never race a still-scheduled write.
- SQLite pragmas are copied verbatim from the shared in-repo LCM schema — never tuned per-store — and `foreign_keys=ON` is load-bearing: the edges table (and node_attributes) rely on ON DELETE CASCADE; with the pragma off the cascade silently no-ops and orphans accumulate.
- Node-id resolution uses the conservative ambiguity policy: only names appearing exactly once in the file resolve.

**Cypher read subset.**
- Read-only by construction: any token signaling write/mutation intent or an unsupported clause, anywhere in the query, is rejected up front; queries MUST start with MATCH. The grammar documents one shape (bracketed relationships required; after `..` a NUMBER is required — no unbounded max) so there is exactly one form to test. Rejection contract: "rejected with a clear message", not a specific code. Cypher has its own failure-code table, distinct from store codes.
- The label universe is the documented schema set (including labels the current ingest pipeline does not emit, which simply match zero rows); everything outside it is rejected with a clear error. The store persists symbol kinds lowercase; PascalCase query labels map to those stored values.
- WHERE is flat OR-of-AND-of-terms (AND + OR, no precedence gymnastics). Literal semantics are deliberately simple and documented: string escapes are preserved verbatim (the subset stores and matches the raw characters, including backslash sequences); a leading `-` is tokenized as DASH so the parser can negate numbers in literal position; exponents are accepted. Comparison coercion: number/number numeric, string/string lexical, bool/bool for =/<> only, null involvement follows SQL three-valued logic for =/<> (ordering with null is false), mixed-type ordering is false (no coercion).
- Filter pushdown is conservative: one `name`/`filePath`/first-node-label equality filter is pushed into the structured index filters only when WHERE is a single conjunction (no top-level OR) — with OR, a term true on one branch is not necessary overall and pushing it would drop the other branch's rows. LIKE metacharacters are skipped so a pushed pattern stays literal-exact (`_` falls back to the capped label scan + exact post-filter). Pushdown exists so a rare node is found BEFORE the 1000-row cap instead of being truncated out.
- Variable-length paths compile to the path-enumerating primitive so exact `*N` honors concrete length-N paths (a node reachable at both a shorter and a length-N path qualifies via the length-N path; `*1..N` stays endpoint-deduped, one row per reachable node). minHops is pushed into the store so its maxPaths cap counts only in-range paths, not the shorter prefixes an exact *N must walk. Any traversePaths cap hit marks the result `truncated: true`; an oversized variable-length depth surfaces as a query-level failure instead of the store silently dropping hops. Fixed single hops keep the BFS compile target, which is exact for direct neighbors.
- Bindings track named variables AND the positional most-recently-resolved node, so anonymous nodes anywhere in a path still pass the cursor forward. The parsed label of a relationship TARGET node is enforced at binding time — the first node's label rides the pushdown, but without target enforcement `(a:Function)-[:CALLS]->(b:Type)` returned Function nodes for `b`. Edge types pass through: the store has no CHECK on edge type; the Cypher layer documents the known set, accepts any string, and returns no rows for unknown types.

**Engine and parsing.**
- Parse calls are serialized (the backend's single Parser instance is shared across languages); a caller that already passed the disposed guard is re-checked after waiting, and dispose() waits for any in-flight parse so freed parser/grammar state is never touched.
- Extraction/query errors surface as tagged parse_failed results, never thrown exceptions that abort a batch reindex. A missing grammars/ directory surfaces the same way, per file, which is why grammar-directory resolution is deferred to first use.
- Grammar directory resolution probes candidate locations relative to the running module (source tree, bundled dist, published package) and picks the first that exists — no hard-coded depth that breaks under different bundler layouts.
- In-flight init/load promises are cleared on BOTH success and failure: a cached rejected promise would make every subsequent call re-await the same transient failure, permanently bricking the backend or a language until dispose.
- All mutable backend state is per-instance so engine lifecycles stay isolated; extractor conventions include CommonJS export patterns (module.exports / exports.X) so Node public APIs are not marked unexported; the IR emitter sorts byte-stably; all benchmark/fixture source is synthetic (public-repo policy).
- FTS5 rowids derive deterministically from node ids (signed 64-bit slice); tests assert through the fts_index reverse map because SQLite returns rowids as JS numbers that lose precision at int64 magnitude. Stale-edge deletion is provenance-scoped so reindexing does not delete edges derived by a different pipeline.

## Consequences
Every boundary rejects instead of guessing, so callers must handle tagged results and absolute paths. The conservative pushdown leaves OR queries on the post-filter path (correct, slower). Path enumeration costs memory proportional to paths walked; truncation is honest but partial. The documented literal semantics (raw escapes) differ from full Cypher and are tested as such.
