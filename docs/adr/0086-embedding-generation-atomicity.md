# Embedding-index generations travel and apply as one atomic unit

Status: accepted

## Context

Embedding index state (`state/embeddings/` shard set, or the legacy `state/embeddings.json` marker) travels through offline sync, where inline changesets are diffs rather than complete generations, multiple daemons and retries race under a generation lock, crash windows exist around renames, and secure-store deployments must never stage plaintext. A partially applied generation would silently serve missing memories.

## Decision

Every `state/embeddings/` shard set, or legacy marker, is treated as ONE generation in both directions. Push side: filter-to-omit, never filter-to-delete; if an exclusion filter removes any member (including already-absent tombstoned members), the WHOLE generation (files and deletion metadata) is omitted, and a filtered generation is never announced as deleted. Changesets carry an `embeddingGenerations` manifest with the complete post-change membership; the receiver assembles the full incoming set (changed members inline, unchanged members hash-verified from local bytes, removed members swept by the swap), applies it through the shared locked atomic backup-swap state machine, and surfaces anything it cannot prove as conflicts so the push side never checkpoints unapplied generations. Under the lock the receiver re-enumerates and hashes the ACTUAL local generation through secure IO and defers the whole generation on divergence: a concurrent daemon mutation is never silently discarded, and a base-less fresh-creation claim must match an existing local generation exactly or defer. Response-loss retries are idempotent via pre-authorized removals. Secure staging is fail-closed (no staging hooks, no publication), staged ciphertext binds its final canonical path, and staged bytes are verified before the published generation is touched. Whole-generation removal (tombstones or shared-base absence covering every known member) happens as ONE atomic swap, never per-shard deletes; swept members' deletion revisions are recorded after publication so a later peer cannot reintroduce removed shards. Census digest uncertainty fails closed: only ENOENT on a digest means absent, and ambiguity never emits a confirmed delete; plain files hash via a streamed pass cached by (path, bytes, mtimeMs). Node-local generation markers are excluded from sync on both sides and advanced around out-of-band shard writes so stale pre-lock digests and partial chunks cannot disturb a valid stamp.

## Consequences

Crashes, races, and hostile peers can never leave a mixed generation on disk or erase local work silently; unprovable pushes surface as visible conflicts instead of silent skips. Cost: whole-generation granularity means a one-shard change re-syncs the unit, and every apply pays an under-lock census.
