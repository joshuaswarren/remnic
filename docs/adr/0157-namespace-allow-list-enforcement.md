# Every namespace-scoped operation is gated by one fail-closed per-token allow-list chokepoint, and coding contexts bind sessions to project namespaces only at defined points

Status: accepted

## Context
Bearer tokens can carry a namespace allow-list (any namespaces axis, including an empty one). Many routes learn their target namespace from somewhere other than a request parameter: id-loaded records fetched by pair id, session id, or chat session id carry their namespace in the record; MCP tools/call accepts an adapter `namespaceOverride`; absent values fall back to the server default; resumed chat sessions bypass param-based resolution entirely. Any path that skips the allow-list lets a namespace-scoped token read or mutate another tenant. Other forces compound this: operation schemas normalize `namespace` with `.trim()`, so gating the raw value would reject `" team "` while the MCP path accepts `team`; legacy records carry no namespace, which storage maps to the server default; and some operations run across ALL namespaces or against global stores, so no namespace argument can isolate them. Separately, the CLI is a one-shot process whose fresh Orchestrator has an empty session coding-context map, so project-scoped gates and refresh scans need a coding context attached before dispatch; refresh walks `codingContext.rootPath`, which must be a real checkout. The admin graph snapshot reads edge files from disk under the namespace root, so symlink or realpath divergence could escape the namespace directory. Citation usage recording and SSE bus subscriptions must apply the same namespace ACL as every other endpoint.

Merged into this theme as nearest neighbours: the REST no-adapter-fallback and post-parse namespace recheck rules, citation principal parity, SSE tenant scoping, graph snapshot namespace containment, and the session coding-context binding family (CLI attachment, post-write seeding, explicit-clear semantics).

## Decision
1. Every namespace-scoped route on every surface (REST routes, MCP tools/call, HTTP chat new-session, resume, and SSE, peer REST routes, memory_search) resolves the EFFECTIVE namespace — the explicit argument, else the adapter override, else the stored namespace of the id-loaded record, else the server default — and passes it through the single shared chokepoint `enforceNamespaceAllowList` BEFORE dispatch or any side effect. Namespace-scoped tokens fail closed with 403; unrestricted and legacy tokens are unaffected (the check is a no-op without an allow-list). One rule, every surface.
2. The namespace is trimmed BEFORE the gate, and the trimmed value is what gets stamped downstream, so the gate and the operation see one namespace. On REST the body `namespace` is user-controlled: there is no adapter-inferred fallback, the parsed namespace is re-checked after schema parsing, and falsy namespace spellings mean absent.
3. Operations that run across all namespaces or dispatch to global stores carry the `fleetWide` flag: the operation runner rejects a namespace-scoped token BEFORE the handler, with no side effect on denial. Peer and work ops against global stores follow the same rule. Both canonical (`remnic.*`) and legacy (`engram.*`) aliases route through the same gates.
4. memory_search is a fan-out: an absent namespace must never search everything the principal can read. For a namespace-scoped token the (already gate-proved) server default is bound explicitly, so results stay inside what the token was authorized for.
5. SSE graph subscriptions resolve the per-namespace storage directory and pass the request principal so namespace ACL is enforced; citation usage recording passes the authenticated principal so ACL checks resolve the same identity as every other write endpoint.
6. Graph snapshot file access canonicalizes the storage root once through realpath, then applies a three-stage guard (absolute, lexical containment, realpath containment). When the namespace root is missing on disk it falls back to lexical resolve, and edge-file reads use the realpath-resolved namespace root.
7. Coding contexts attach at defined points only. A one-shot CLI attaches a context BEFORE dispatch when `--project-tag` + `--session-key` are given, so the gate passes and project-scoped writes resolve to the right namespace; the coding root must be a real checkout path (default to the CWD or an explicit `--repo-root`), the context id comes from `--project-tag`, and when it is absent a default is derived from the repo-root basename. The write surface seeds a session's coding binding ONLY after a real, project-scoped write commits — never on a dry run, a replay/conflict, a quota rejection, or an explicit-namespace write. `codingContext: null` means explicit clear; absence means untouched.

## Consequences
Id-loaded routes must load the record to learn its namespace before dispatching — an extra read on every gated path. Legacy undefined-namespace records are readable and resolvable only by tokens whose allow-list includes the server default; a scoped token whose server default is unlisted cannot start chats, open legacy pairs, or resolve them. Explicit-namespace writes never bind the session's coding context, so later bare calls on the same session stay unscoped, and one-shot CLIs must re-attach context on every invocation. Idempotent-write surfaces stay responsible for forwarding quota hooks (no hooks on one-shot CLI paths).
