# Local LLM client degrades gracefully: probing never caches timeouts, rate limits get a bounded retry budget, and config refusals stay terminal

Status: accepted

## Context
The local LLM client talks to heterogeneous proxies (llama.cpp, vLLM, LiteLLM, Ollama) behind operator-controlled networks. Several forces collided: a probe that times out on a busy event loop is not evidence the backend is down, yet caching it blacked out loaded daemons (issue #2210); a LiteLLM /health probe runs a live completion against every pool deployment, turning a 2-second check into thousands of unwanted completions; a saturated LiteLLM proxy answered 429 and the client gave up at once (COS-447); host-installed global dispatchers silently applied a 300s header cap to LAN endpoints; and pool-config refusals ('pool missing or disabled') were misclassified as saturation and retried forever.

## Decision
Availability handling follows these rules: (1) A TIMED-OUT probe is never cached as a verdict - timeouts are tracked separately so a busy daemon cannot cache itself into a blackout; only definite failures are cached, and a lapsed circuit stays visible as a tombstone so each client can invalidate its cached verdict exactly once; an empty string is a real pool key. (2) Concurrent probe sequences collapse onto one in-flight run; the pending entry is detached BEFORE aborting so a late caller cannot join a doomed sequence and read its failure as a verdict. (3) Availability loss is logged at warn, not debug, because extraction otherwise stops silently. (4) LiteLLM is recognized before llama.cpp/vLLM health probes and probed via GET / ('LiteLLM: RUNNING') to avoid generating pool-wide completions; port-matched probes keep their lead. (5) Rate-limit responses (429/503/408, LiteLLM cooldown) get their own retry budget with exponential full-jitter backoff and a process-wide semaphore capping concurrent HTTP attempts; the shared deadline is rechecked after every async wait because another attempt may have extended the cooldown; waits are bounded by the request timeout. (6) A proxy 503 carrying a pool-config refusal is terminal - it enters no rate-limit retries. (7) Error bodies are PARSED, not substring-matched: proxy bodies carry an error object without a code field, and any spacing/shape variation must hit the same classification as isRateLimitedResponse. (8) REMNIC_LOCAL_LLM_DIRECT=1 makes the transport use its own dispatcher pool (covering availability probes as well as chat) for operators whose host installs a global dispatcher that cannot reach the LAN server; without the flag behavior is unchanged, and tests assert the dispatcher mechanism itself rather than trusting it. (9) Health checks dial 127.0.0.1 (not localhost) to avoid DNS issues, HOME resolution prefers the resolved helper for launchd environments, request bodies are never logged by default, verbose model listings stay debug-only, an ineligible critical head must not strand a background permit, and process-wide state is shared via globalThis so bundled duplicate module copies agree.

## Consequences
Fail-open probe semantics and bounded backoff mean a genuinely flaky backend sees repeated attempts instead of a long blackout; direct mode is an explicit operator declaration and shifts dispatcher ownership to the transport; parsing error bodies couples classification to current proxy payload shapes.
