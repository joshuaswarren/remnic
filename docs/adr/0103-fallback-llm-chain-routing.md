# Model chains route by explicit precedence, degrade to prompt-only once, and propagate terminal failures

Status: accepted

## Context
Extraction and background tasks run over multi-provider fallback chains with gateway routing, subscription auth, structured-output requests, and cancellation; ambiguity in any of these turns a transient provider fault into a user-visible failure or a misattributed error.

## Decision
Routing precedence is fixed: taskModelChain wins over gatewayAgentId. A persona chain that deliberately excludes the gateway default is never augmented by an implicit last resort; the implicit last resort keys on the SAME activation condition as chain resolution (modelChainOverride.primary) and, when active, appends the FULL gateway default chain (primary plus fallbacks), so an exhausted task chain never leaves the chain empty and a listed default fallback is still tried after the default primary. An unresolved secret ref skips that provider entirely so the chain falls through. Provider config resolves active gateway config first; materialized models.json only for providers absent from config; OpenAI-compatible and unknown formats use chat completions; Ollama gets its native /api/chat transport. A provider rejecting structured output degrades the REST of the chain to prompt-only (an N-model chain costs N+1 requests, not 2N). Terminal typed provider failures and caller aborts propagate unwrapped and unretried — timeout/re-login guidance and cancellation depend on it; the caller's abort is never swallowed as a provider failure. Request construction (e.g. token acquisition) runs once, outside the retry boundary; only fetch/network/HTTP-retryable failures retry, and network error text is sanitized before logging (it can carry loader paths). Codex-subscription calls share one bounded headroom between provider timeout and outer deadline (SIGTERM lead / settle grace); the runner is chosen so the owning runtime terminates requests it started; schema-rejection classification is narrow — an echoed format name or an outage message is not a capability rejection, only direct evidence the provider cannot parse the schema content degrades. Deadlines in tests use real timers when the wall-clock behavior itself is the subject.

## Consequences
Narrow classification means some real schema rejections surface as generic provider errors; prompt-only degradation loses structured-output guarantees for the remainder of the chain.
